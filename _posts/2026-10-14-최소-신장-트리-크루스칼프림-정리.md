# 가장 저렴한 연결을 찾아서: 최소 신장 트리(MST) 파헤치기 (크루스칼 & 프림)

안녕하세요, 개발 블로그 독자 여러분!

오늘은 컴퓨터 과학, 특히 그래프 이론에서 매우 중요하고 실용적인 개념인 **최소 신장 트리(Minimum Spanning Tree, MST)**에 대해 이야기해보려 합니다. 이름만 들어서는 조금 어렵게 느껴질 수도 있지만, 걱정하지 마세요! 가장 친절하고 쉽게 설명해 드릴 것을 약속드립니다.

## 🌳 최소 신장 트리가 뭔가요?

우리가 살고 있는 세상은 수많은 "연결"로 이루어져 있습니다. 도시간의 도로, 컴퓨터 네트워크, 전력망, 심지어 SNS의 친구 관계까지, 이 모든 것을 그래프(Graph)라는 형태로 모델링할 수 있습니다. 그래프는 **정점(Vertex)**이라는 지점들과 이 지점들을 잇는 **간선(Edge)**으로 구성되어 있죠.

여기서 최소 신장 트리는 다음과 같은 특징을 가진 특별한 형태의 부분 그래프입니다.

1.  **신장 트리(Spanning Tree):** 그래프의 모든 정점을 포함하면서, 사이클(Cycle)이 없는 트리(Tree) 형태의 부분 그래프를 말합니다. 쉽게 말해, 모든 점을 다 잇되, 빙글빙글 돌아가는 길은 만들지 않는다는 거죠.
2.  **최소(Minimum):** 각 간선에는 '비용' 또는 '가중치(Weight)'가 할당되어 있습니다. 이 가중치의 합이 최소가 되는 신장 트리를 최소 신장 트리라고 부릅니다.

**예시:** 여러 도시를 연결하는 고속도로를 건설해야 하는데, 각 도로 건설 비용이 다릅니다. 모든 도시를 연결하면서 총 건설 비용을 최소화하고 싶다면? 이때 바로 최소 신장 트리를 찾아야 합니다!

이러한 최소 신장 트리를 찾는 대표적인 두 가지 알고리즘이 바로 **크루스칼(Kruskal) 알고리즘**과 **프림(Prim) 알고리즘**입니다. 이제 하나씩 자세히 살펴볼까요?

---

## 🛠️ 크루스칼(Kruskal) 알고리즘: 가장 싼 간선부터 차례대로!

크루스칼 알고리즘은 "가장 저렴한 간선부터 차례대로 선택하되, 사이클을 만들지 않는 간선만 MST에 추가한다"는 아주 직관적인 아이디어를 가지고 있습니다.

### 작동 방식

1.  **간선 정렬:** 그래프의 모든 간선을 가중치를 기준으로 오름차순으로 정렬합니다. 가장 싼 간선이 맨 앞에 오도록요.
2.  **간선 선택:** 정렬된 간선들을 앞에서부터 하나씩 확인합니다.
3.  **사이클 검사:** 선택된 간선이 MST에 추가되었을 때, 기존에 연결된 정점들 사이에 사이클이 생기는지 확인합니다.
    *   **사이클이 생기지 않으면:** 해당 간선을 MST에 추가하고, 두 정점을 연결합니다.
    *   **사이클이 생기면:** 해당 간선은 건너뛰고 다음 간선을 확인합니다.
4.  **반복:** 모든 정점을 연결하는 MST가 완성될 때까지 (즉, `정점의 개수 - 1`개의 간선을 선택할 때까지) 2~3단계를 반복합니다.

여기서 "사이클이 생기는지"를 효율적으로 검사하는 데 아주 유용한 자료구조가 바로 **유니온-파인드(Union-Find)**, 또는 서로소 집합(Disjoint Set) 자료구조입니다.

### 유니온-파인드 (Union-Find) 잠깐 설명!

유니온-파인드는 여러 개의 집합으로 나누어진 원소들을 관리하는 데 사용됩니다.
*   **`find(x)`:** 원소 `x`가 속한 집합의 대표 원소(루트 노드)를 찾아줍니다.
*   **`union(x, y)`:** 원소 `x`가 속한 집합과 원소 `y`가 속한 집합을 합쳐줍니다.

크루스칼 알고리즘에서는 `find(u) == find(v)` 이면 `u`와 `v`가 이미 같은 집합에 속해있다는 뜻이고, 이는 두 정점을 잇는 간선을 추가하면 사이클이 생긴다는 의미가 됩니다.

### 파이썬 코드 예제 (크루스칼)

```python
import heapq

# 1. Union-Find (서로소 집합) 자료구조 구현
def find_parent(parent, x):
    if parent[x] == x:
        return x
    parent[x] = find_parent(parent, parent[x])
    return parent[x]

def union_parent(parent, a, b):
    a = find_parent(parent, a)
    b = find_parent(parent, b)
    if a < b:
        parent[b] = a
    else:
        parent[a] = b

def kruskal(vertices, edges):
    # vertices: 정점의 개수 (예: 6)
    # edges: (cost, u, v) 형태의 간선 리스트
    
    parent = [i for i in range(vertices)] # 부모 테이블 초기화 (각 정점이 자기 자신을 부모로 가짐)
    edges.sort() # 간선을 비용 기준으로 오름차순 정렬

    mst_cost = 0
    mst_edges = []
    
    # 2. 정렬된 간선들을 하나씩 확인
    for cost, u, v in edges:
        # 3. 사이클 검사 (두 정점의 부모가 다르면 사이클이 생기지 않음)
        if find_parent(parent, u) != find_parent(parent, v):
            union_parent(parent, u, v) # 두 정점을 연결 (집합을 합침)
            mst_cost += cost
            mst_edges.append((u, v, cost)) # MST에 간선 추가
            
            # 모든 정점 연결 완료 (정점의 개수 - 1 만큼의 간선을 선택)
            if len(mst_edges) == vertices - 1:
                break
                
    return mst_cost, mst_edges

# 그래프 예시
# 정점 0부터 5까지 총 6개의 정점
# 간선 정보: (비용, 시작 정점, 끝 정점)
# (0,1) (0,2) ...
graph_edges = [
    (10, 0, 1),
    (15, 0, 2),
    (20, 1, 3),
    (30, 1, 4),
    (25, 2, 3),
    (40, 2, 5),
    (35, 3, 4),
    (50, 4, 5)
]

num_vertices = 6 # 0, 1, 2, 3, 4, 5
min_cost, mst = kruskal(num_vertices, graph_edges)

print(f"크루스칼 알고리즘으로 찾은 최소 신장 트리의 총 비용: {min_cost}")
print(f"포함된 간선: {mst}")
# 예상 출력:
# 크루스칼 알고리즘으로 찾은 최소 신장 트리의 총 비용: 120
# 포함된 간선: [(0, 1, 10), (0, 2, 15), (1, 3, 20), (2, 5, 40), (3, 4, 35)]
```

### 시간 복잡도

주로 간선을 정렬하는 데 걸리는 시간에 의해 결정됩니다. 간선이 E개라면 `O(E log E)` 또는 `O(E log V)` (V는 정점의 개수) 정도의 시간 복잡도를 가집니다. 간선이 적은 희소 그래프(Sparse Graph)에서 특히 효율적입니다.

## 🏗️ 프림(Prim) 알고리즘: 한 점부터 확장!

프림 알고리즘은 "하나의 정점에서 시작해서, 현재 만들어진 트리에 인접한 간선 중 가장 저렴한 것을 하나씩 추가하며 트리를 확장해나가는 방식"입니다. 마치 눈덩이를 굴리듯이 말이죠.

### 작동 방식

1.  **시작 정점 선택:** 그래프 내의 임의의 한 정점을 선택하여 MST에 포함시킵니다.
2.  **간선 후보 추가:** MST에 포함된 정점과 MST에 포함되지 않은 정점들을 잇는 모든 간선들을 '후보'로 등록합니다.
3.  **최소 간선 선택:** 후보 간선들 중에서 가중치가 가장 작은 간선을 선택합니다.
4.  **MST 확장:** 선택된 간선을 MST에 추가하고, 이 간선이 연결하는 새로운 정점(아직 MST에 포함되지 않은)도 MST에 포함시킵니다.
5.  **반복:** 모든 정점이 MST에 포함될 때까지 (즉, `정점의 개수 - 1`개의 간선을 선택할 때까지) 2~4단계를 반복합니다.

여기서 "후보 간선들 중 가장 가중치가 작은 간선"을 효율적으로 찾아내기 위해 **우선순위 큐(Priority Queue)**, 특히 최소 힙(Min-Heap) 자료구조를 사용합니다.

### 파이썬 코드 예제 (프림)

```python
import heapq

def prim(vertices, graph):
    # vertices: 정점의 개수 (예: 6)
    # graph: 인접 리스트 (graph[u] = [(cost, v), ...])
    
    mst_cost = 0
    mst_edges = []
    
    # 방문 여부 체크 리스트
    visited = [False] * vertices
    
    # 우선순위 큐: (cost, start_node, end_node) 형태로 저장하지만,
    # 프림에서는 현재 MST에 연결할 가장 싼 '다음' 간선을 저장하므로 (cost, next_node) 형태로 저장
    # 초기에는 (0, 0) 즉, 0번 정점에서 시작하고 비용은 0
    # 엄밀히 말하면 (cost, next_node) 형태이고, 시작 간선이 없으므로 임시로 첫 노드를 넣음
    # (cost, 도착_노드)
    min_heap = [(0, 0)] # (비용, 시작 정점)

    edge_count = 0
    
    while min_heap and edge_count < vertices:
        cost, u = heapq.heappop(min_heap)
        
        # 이미 방문한 정점이면 건너뜀 (이미 MST에 포함된 정점)
        if visited[u]:
            continue
        
        visited[u] = True
        mst_cost += cost
        edge_count += 1
        
        # 실제 간선을 추적하려면, 시작 노드를 저장해야 함
        # 이 코드에서는 MST의 총 비용만 계산하고, 어떤 간선이 선택되었는지는 직접 추적하지 않음.
        # 만약 간선을 추적하고 싶다면, min_heap에 (cost, u_from, u_to) 형태로 저장해야 함.
        # 예제 편의를 위해 비용과 방문 정점만 추적.
        # (원래는 MST에 포함되는 간선 정보도 저장해야 함)
        
        # 현재 정점 u에 연결된 모든 간선들을 우선순위 큐에 추가
        for next_cost, v in graph[u]:
            if not visited[v]:
                heapq.heappush(min_heap, (next_cost, v))
                
    # 프림 알고리즘의 MST 간선 정보를 얻는 것은 약간 더 복잡함.
    # 일반적으로는 (cost, from_node, to_node) 형태로 힙에 넣고,
    # pop될 때 from_node와 to_node를 활용하여 mst_edges를 채움.
    # 현재 코드에서는 mst_cost만 정확히 계산됨.
    return mst_cost

# 그래프 예시 (인접 리스트 형태)
# 정점 0부터 5까지 총 6개의 정점
# graph[u] = [(cost, v), ...]
graph_adj = [
    [(10, 1), (15, 2)],  # 0번 정점과 연결된 간선: (비용, 도착정점)
    [(10, 0), (20, 3), (30, 4)], # 1번 정점
    [(15, 0), (25, 3), (40, 5)], # 2번 정점
    [(20, 1), (25, 2), (35, 4)], # 3번 정점
    [(30, 1), (35, 3), (50, 5)], # 4번 정점
    [(40, 2), (50, 4)]   # 5번 정점
]

num_vertices = 6
min_cost = prim(num_vertices, graph_adj)

print(f"프림 알고리즘으로 찾은 최소 신장 트리의 총 비용: {min_cost}")
# 예상 출력:
# 프림 알고리즘으로 찾은 최소 신장 트리의 총 비용: 120
```

*참고: 위 프림 알고리즘 예제는 MST의 총 비용만 계산합니다. 실제 MST를 구성하는 간선 목록을 얻으려면 우선순위 큐에 `(cost, from_node, to_node)` 형태로 간선 정보를 넣고, `pop` 할 때 `from_node`와 `to_node`를 `mst_edges`에 추가해야 합니다.*

### 시간 복잡도

우선순위 큐를 사용하는 방식에 따라 달라집니다.
*   일반적인 이진 힙(Binary Heap)을 사용하면 `O(E log V)` 또는 `O(E log E)` (E가 V^2에 가까우면 E log V, V에 가까우면 E log E)의 시간 복잡도를 가집니다.
*   피보나치 힙(Fibonacci Heap)과 같은 고급 자료구조를 사용하면 `O(E + V log V)`까지 줄일 수 있지만, 구현이 복잡하여 잘 사용되지 않습니다.
간선이 많은 밀집 그래프(Dense Graph)에서 특히 효율적입니다.

## 🧐 크루스칼 vs. 프림: 언제 무엇을 쓸까?

두 알고리즘 모두 MST를 찾는 데 사용되지만, 각각의 장단점이 있어 그래프의 특성에 따라 더 적합한 알고리즘이 있습니다.

| 특징          | 크루스칼 알고리즘                     | 프림 알고리즘                            |
| :------------ | :------------------------------------ | :--------------------------------------- |
| **핵심 아이디어** | 가장 싼 간선부터 연결 (사이클 방지)   | 한 정점에서 시작해 트리 확장 (가장 싼 인접 간선) |
| **주요 자료구조** | 유니온-파인드                         | 우선순위 큐 (최소 힙)                    |
| **효율적인 그래프** | 간선 수가 적은 **희소 그래프(Sparse Graph)** | 간선 수가 많은 **밀집 그래프(Dense Graph)** |
| **시간 복잡도** | O(E log E) 또는 O(E log V)           | O(E log V) 또는 O(V^2)                   |

*   **희소 그래프(Sparse Graph):** 간선의 개수(E)가 정점의 개수(V)에 비해 훨씬 적을 때 (E ≈ V)
*   **밀집 그래프(Dense Graph):** 간선의 개수(E)가 정점의 개수(V)의 제곱에 가까울 때 (E ≈ V^2)

간단히 말해, **간선이 적으면 크루스칼**, **간선이 많으면 프림**을 고려해볼 수 있습니다.
