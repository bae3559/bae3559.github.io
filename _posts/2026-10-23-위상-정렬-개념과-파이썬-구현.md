# 복잡한 의존성을 우아하게 정렬하는 마법: 위상 정렬 (Topological Sort) 개념과 파이썬 구현

안녕하세요, 개발 블로그 독자 여러분! 🚀

복잡한 시스템을 개발하다 보면, "이 작업을 먼저 해야 저 작업을 할 수 있어!" 와 같은 의존성 문제에 자주 부딪히게 됩니다. 예를 들어, 웹 개발 프로젝트에서 데이터베이스를 먼저 구축해야 백엔드 API를 만들 수 있고, 백엔드가 준비되어야 프론트엔드를 개발할 수 있죠. 혹은 대학교 수강 과목에서 '자료구조'를 수강해야 '알고리즘'을 수강할 수 있는 것처럼요.

이런 순서가 정해진 작업들을 효율적으로 처리하기 위해 우리는 어떤 도구를 사용할 수 있을까요? 바로 오늘 다룰 **'위상 정렬(Topological Sort)'** 입니다. 위상 정렬은 수많은 의존성을 가진 작업들을 올바른 순서대로 나열해주는 강력한 알고리즘입니다. 오늘은 이 위상 정렬이 무엇인지, 그리고 파이썬으로 어떻게 구현하는지 초보자 눈높이에서 쉽고 친절하게 설명해 드릴게요!

---

## 1. 위상 정렬, 너는 누구냐? 🤔 (개념 설명)

위상 정렬은 한마디로 **방향성이 있는 그래프에서 노드들을 일렬로 세우는 방법**이라고 할 수 있습니다. 여기서 중요한 두 가지 키워드가 있습니다.

### 1.1. 방향성 (Directed)

그래프의 간선(edge)이 한쪽 방향으로만 흐르는 것을 의미합니다. 예를 들어 `A -> B`는 "A를 먼저 해야 B를 할 수 있다"는 의미를 가집니다. B에서 A로는 갈 수 없습니다.

### 1.2. 비순환 (Acyclic)

그래프 안에 순환(cycle)이 없다는 뜻입니다. 만약 `A -> B -> C -> A`와 같은 순환이 있다면, 우리는 A, B, C를 어떤 순서로도 일렬로 세울 수 없습니다. (A를 하려면 C를 해야 하고, C를 하려면 B를, B를 하려면 A를... 무한 루프에 빠지죠!) 따라서 위상 정렬은 **'방향 비순환 그래프(DAG: Directed Acyclic Graph)'** 에서만 사용할 수 있습니다.

### 1.3. 핵심 정의

위상 정렬은 방향 비순환 그래프(DAG)의 모든 노드를, **'모든 간선 (u, v)에 대해 u가 v보다 먼저 오도록'** 선형으로 정렬하는 것입니다.

**예시:**
만약 다음과 같은 작업 의존성이 있다고 상상해 보세요.
*   자료구조 (A) -> 알고리즘 (B)
*   자료구조 (A) -> 운영체제 (C)
*   알고리즘 (B) -> 개발 프로젝트 (D)
*   운영체제 (C) -> 개발 프로젝트 (D)

이것을 위상 정렬하면 `A -> B -> C -> D` 또는 `A -> C -> B -> D` 와 같은 순서가 나올 수 있습니다. (B와 C는 서로 의존성이 없으므로 순서가 바뀔 수 있습니다.) 중요한 것은 A가 B와 C보다 먼저 오고, B와 C가 D보다 먼저 온다는 것입니다.

## 2. 위상 정렬, 어떻게 구현할까? 🛠️ (Kahn's Algorithm)

위상 정렬을 구현하는 방법은 크게 두 가지가 있습니다: **BFS(너비 우선 탐색) 기반의 Kahn's Algorithm**과 **DFS(깊이 우선 탐색) 기반 알고리즘**입니다. 초보자분들이 이해하기 쉽도록 Kahn's Algorithm을 중심으로 설명하고 파이썬으로 구현해볼게요.

Kahn's Algorithm의 핵심 아이디어는 다음과 같습니다.

1.  **시작점 찾기:** 진입 차수(In-degree)가 0인 노드를 찾습니다. 진입 차수란 해당 노드로 들어오는 간선의 개수를 의미합니다. 진입 차수가 0이라는 것은 어떤 작업도 이 작업을 시작하기 위해 선행될 필요가 없다는 뜻이죠.
2.  **큐에 추가:** 진입 차수가 0인 노드들을 큐(Queue)에 넣습니다. 이 노드들이 위상 정렬의 첫 번째 후보들이 됩니다.
3.  **순서대로 처리:**
    *   큐에서 노드를 하나 꺼냅니다. 이 노드는 위상 정렬 결과에 추가됩니다.
    *   꺼낸 노드에서 나가는 모든 간선을 제거했다고 가정합니다. 즉, 이 노드의 다음 노드(이웃 노드)들의 진입 차수를 1씩 감소시킵니다.
    *   진입 차수가 1 감소하여 0이 된 이웃 노드가 있다면, 그 노드 또한 큐에 추가합니다.
4.  **반복:** 큐가 빌 때까지 3번 과정을 반복합니다.

만약 모든 노드가 위상 정렬 결과에 포함되었다면 성공적으로 정렬된 것이고, 그렇지 않다면 그래프에 순환(Cycle)이 존재하여 위상 정렬이 불가능하다는 의미입니다.

## 3. 파이썬으로 구현해보기 🐍 (코드 예제)

이제 Kahn's Algorithm을 파이썬 코드로 직접 구현해봅시다.

**그래프 표현:**
*   `graph`: 각 노드가 어떤 노드로 연결되는지(어떤 작업이 다음 작업인지)를 저장하는 인접 리스트(adjacency list) 형태의 딕셔너리를 사용합니다.
*   `in_degree`: 각 노드의 진입 차수를 저장하는 딕셔너리를 사용합니다.

```python
from collections import deque

def topological_sort(graph_nodes, dependencies):
    """
    위상 정렬을 수행하는 Kahn's Algorithm 구현 함수입니다.

    Args:
        graph_nodes (list): 그래프의 모든 노드(작업) 리스트.
        dependencies (list): (pre_req, task) 형태의 의존성 튜플 리스트.
                             pre_req는 task의 선행 조건입니다.

    Returns:
        list: 위상 정렬된 노드들의 리스트. 만약 순환이 있다면 빈 리스트 반환.
    """

    # 1. 그래프 구성 및 진입 차수 계산
    graph = {node: [] for node in graph_nodes} # {노드: [연결된 노드들]}
    in_degree = {node: 0 for node in graph_nodes} # {노드: 진입 차수}

    for pre_req, task in dependencies:
        # pre_req -> task 의존성 추가
        graph[pre_req].append(task)
        # task의 진입 차수 증가
        in_degree[task] += 1

    # 2. 진입 차수가 0인 노드들을 큐에 추가 (시작점 찾기)
    queue = deque()
    for node in graph_nodes:
        if in_degree[node] == 0:
            queue.append(node)

    # 3. 위상 정렬 수행
    result = []
    while queue:
        current_node = queue.popleft() # 큐에서 노드 꺼내기
        result.append(current_node) # 결과 리스트에 추가

        # 현재 노드에서 나가는 간선들을 처리 (이웃 노드들의 진입 차수 감소)
        for neighbor in graph[current_node]:
            in_degree[neighbor] -= 1 # 이웃 노드의 진입 차수 1 감소
            if in_degree[neighbor] == 0: # 진입 차수가 0이 되면 큐에 추가
                queue.append(neighbor)

    # 4. 순환(Cycle) 확인
    # 모든 노드가 결과에 포함되지 않았다면, 순환이 존재한다는 의미
    if len(result) == len(graph_nodes):
        return result
    else:
        print("경고: 그래프에 순환이 존재하여 위상 정렬을 수행할 수 없습니다.")
        return []

# --- 예제 사용 ---
if __name__ == "__main__":
    # 예제 1: 기본적인 과목 수강 의존성
    print("--- 예제 1: 과목 수강 의존성 ---")
    nodes_ex1 = ['프로그래밍 기초', '자료구조', '알고리즘', '운영체제', '개발 프로젝트']
    dependencies_ex1 = [
        ('프로그래밍 기초', '자료구조'),
        ('자료구조', '알고리즘'),
        ('자료구조', '운영체제'),
        ('알고리즘', '개발 프로젝트'),
        ('운영체제', '개발 프로젝트')
    ]
    sorted_courses_ex1 = topological_sort(nodes_ex1, dependencies_ex1)
    if sorted_courses_ex1:
        print("정렬된 과목 순서:", sorted_courses_ex1)
    # 예상 출력: ['프로그래밍 기초', '자료구조', '알고리즘', '운영체제', '개발 프로젝트'] 또는
    #            ['프로그래밍 기초', '자료구조', '운영체제', '알고리즘', '개발 프로젝트']


    # 예제 2: 순환이 있는 경우 (위상 정렬 불가능)
    print("\n--- 예제 2: 순환이 있는 경우 ---")
    nodes_ex2 = ['A', 'B', 'C']
    dependencies_ex2 = [
        ('A', 'B'),
        ('B', 'C'),
        ('C', 'A') # A -> B -> C -> A 순환
    ]
    sorted_tasks_ex2 = topological_sort(nodes_ex2, dependencies_ex2)
    if sorted_tasks_ex2:
        print("정렬된 작업 순서:", sorted_tasks_ex2)

    # 예제 3: 좀 더 복잡한 의존성
    print("\n--- 예제 3: 복잡한 빌드 시스템 의존성 ---")
    nodes_ex3 = ['Install Deps', 'Compile Frontend', 'Compile Backend', 'Run Tests', 'Deploy']
    dependencies_ex3 = [
        ('Install Deps', 'Compile Frontend'),
        ('Install Deps', 'Compile Backend'),
        ('Compile Frontend', 'Run Tests'),
        ('Compile Backend', 'Run Tests'),
        ('Run Tests', 'Deploy')
    ]
    sorted_build_ex3 = topological_sort(nodes_ex3, dependencies_ex3)
    if sorted_build_ex3:
        print("정렬된 빌드 순서:", sorted_build_ex3)
    # 예상 출력: ['Install Deps', 'Compile Frontend', 'Compile Backend', 'Run Tests', 'Deploy'] 또는
    #            ['Install Deps', 'Compile Backend', 'Compile Frontend', 'Run Tests', 'Deploy']
```

### 코드 설명
1.  **초기화**: `graph` 딕셔너리는 각 노드(작업)가 완료된 후 어떤 노드를 진행할 수 있는지를 나타냅니다. `in_degree` 딕셔너리는 각 노드로 진입하는 간선(선행 작업)의 개수를 저장합니다.
2.  **그래프 및 진입 차수 구성**: `dependencies` 리스트를 순회하며 `graph`와 `in_degree`를 채웁니다. `(pre_req, task)` 형태의 의존성이 있으면 `pre_req`에서 `task`로 가는 간선이 있다는 뜻이므로 `graph[pre_req]`에 `task`를 추가하고 `task`의 `in_degree`를 1 증가시킵니다.
3.  **큐 초기화**: `in_degree`가 0인 모든 노드(즉, 선행 조건이 없는 노드)를 `deque`에 추가합니다. 이 노드들이 위상 정렬의 시작점이 됩니다.
4.  **위상 정렬 진행**: 큐가 비어있지 않은 동안 다음을 반복합니다.
    *   큐에서 가장 앞의 노드(`current_node`)를 꺼냅니다.
    *   `current_node`를 결과 리스트(`result`)에 추가합니다.
    *   `current_node`에서 나가는 모든 이웃 노드들에 대해, 이웃 노드의 `in_degree`를 1 감소시킵니다. 이는 `current_node`가 처리되었으므로 이제 이웃 노드의 선행 조건 하나가 만족되었다는 의미입니다.
    *   만약 어떤 이웃 노드의 `in_degree`가 0이 되면, 그 이웃 노드도 이제 선행 조건이 모두 만족되었으므로 큐에 추가하여 다음 처리 대상으로 만듭니다.
5.  **순환(Cycle) 감지**: 위상 정렬이 완료된 후, `result` 리스트의 길이가 `graph_nodes`의 길이와 같지 않다면, 이는 그래프 내에 순환이 존재하여 모든 노드를 정렬할 수 없었다는 의미입니다. 이 경우 경고 메시지를 출력하고 빈 리스트를 반환합니다.

## 4. 위상 정렬, 어디에 활용될까? 🌎 (활용 사례)

위상 정렬은 생각보다 우리 주변의 많은 곳에서 활용되고 있습니다.

*   **빌드 시스템 (Makefiles, CI/CD 파이프라인):** 소프트웨어 프로젝트를 빌드할 때, 어떤 파일(모듈)을 먼저 컴파일해야 하는지, 어떤 테스트를 먼저 실행해야 하는지 등의 의존성을 관리하여 올바른 순서로 빌드를 진행합니다.
*   **운영체제 (태스크 스케줄링):** 여러 작업을 병렬로 처리할 때, 작업 간의 의존성을 고려하여 실행 순서를 정합니다.
*   **컴파일러 (코드 최적화):** 코드 내의 명령어들 간의 의존성을 분석하여 실행 순서를 최적화합니다.
*   **데이터베이스 (트랜잭션 스케줄링):** 여러 트랜잭션이 동시에 실행될 때, 충돌을 방지하고 정확성을 유지하기 위해 실행 순서를 결정합니다.
*   **프리젠테이션 슬라이드 순서 결정:** 특정 슬라이드는 다른 슬라이드를 먼저 보여준 후에 보여져야 할 때.
*   **교육 과정 또는 학습 로드맵:** 선수 과목이 있는 경우, 수강 순서를 정할 때 사용될 수 있습니다.
