# 개발자라면 알아야 할 개념! 위상 정렬(Topological Sort) 개념과 파이썬 구현

## 1. 위상 정렬(Topological Sort)이란?

가장 먼저, 위상 정렬이 무엇인지부터 알아볼까요?

**위상 정렬은 방향성 비순환 그래프(DAG: Directed Acyclic Graph)의 정점들을 "방향에 거스르지 않도록" 일렬로 나열하는 것을 의미합니다.**

음... 말이 좀 어렵죠? 쉽게 풀어서 설명해 드릴게요.

**상상해 보세요!**

여러분은 대학교에서 여러 과목을 수강해야 합니다. 그런데 몇몇 과목들은 선수 과목이 존재합니다. 예를 들어:
*   `미적분`을 들어야 `물리학`을 들을 수 있습니다.
*   `자료구조`를 들어야 `알고리즘`을 들을 수 있습니다.
*   `운영체제`는 선수 과목이 없습니다.

이때, 여러분이 졸업을 위해 모든 과목을 이수해야 한다면, 어떤 순서로 과목들을 수강해야 할까요? 단순히 아무렇게나 들을 수는 없을 겁니다. 선수 과목을 먼저 이수해야만 다음 과목을 들을 수 있죠.

바로 이 "선수 과목을 먼저 이수한다"는 조건을 만족시키면서 모든 과목을 들을 수 있는 순서를 찾아내는 것이 **위상 정렬**입니다.

### 핵심 개념: 방향성 비순환 그래프 (DAG)

위상 정렬은 아무 그래프에나 적용할 수 있는 것이 아니라, 반드시 **방향성 비순환 그래프(DAG)** 에만 적용할 수 있습니다.

*   **방향성 그래프 (Directed Graph):** 간선(edge)에 방향이 있는 그래프입니다. 예를 들어 `A -> B`는 A에서 B로만 갈 수 있고, B에서 A로는 갈 수 없다는 의미입니다. (선수 과목 예시에서 `미적분 -> 물리학` 처럼요.)
*   **비순환 그래프 (Acyclic Graph):** 그래프 내에 순환(cycle)이 없는 그래프입니다. 즉, `A -> B -> C -> A` 와 같이 시작점으로 돌아오는 경로가 없어야 합니다. 만약 순환이 있다면? `A를 하려면 B, B를 하려면 C, C를 하려면 A`라는 모순적인 상황이 발생하여 올바른 순서를 찾을 수 없게 됩니다.

위상 정렬의 결과는 유일하지 않을 수도 있습니다. 여러 가지 가능한 순서가 있을 수 있지만, 모든 순서는 주어진 의존성 규칙을 만족합니다.

## 2. 위상 정렬은 어떻게 작동할까요? (Kahn의 알고리즘)

위상 정렬을 구현하는 방법은 크게 두 가지(Kahn의 알고리즘, DFS 기반 알고리즘)가 있습니다. 이 글에서는 초보자에게 좀 더 직관적으로 이해하기 쉬운 **Kahn의 알고리즘(Kahn's algorithm)** 을 중심으로 설명해 드릴게요.

Kahn의 알고리즘은 **"진입 차수(In-degree)"** 라는 개념을 활용합니다.

*   **진입 차수(In-degree):** 특정 정점(node)으로 들어오는 간선의 개수입니다. 선수 과목 예시에서 어떤 과목의 진입 차수가 0이라는 것은 그 과목을 듣기 위한 선수 과목이 없다는 뜻입니다.

**Kahn의 알고리즘 단계:**

1.  **모든 정점의 진입 차수 계산:** 그래프 내의 모든 정점에 대해 자신에게 들어오는 간선의 개수를 계산합니다.
2.  **진입 차수가 0인 정점을 큐에 추가:** 선수 과목이 없는(진입 차수가 0인) 과목들부터 시작해야겠죠? 이 과목들을 큐(Queue)에 넣습니다. (큐는 먼저 들어간 것이 먼저 나오는 자료구조입니다.)
3.  **큐에서 정점 추출 및 처리:**
    *   큐에서 정점 하나를 꺼냅니다. 이 정점은 이제 위상 정렬 결과에 포함될 수 있는 정점입니다.
    *   꺼낸 정점과 연결된 모든 이웃 정점(즉, 이 정점을 선수 과목으로 가지는 다음 과목들)의 진입 차수를 1씩 감소시킵니다. 왜냐하면 선수 과목이 하나 처리되었기 때문입니다.
    *   만약 어떤 이웃 정점의 진입 차수가 감소한 결과 0이 되었다면, 그 이웃 정점도 이제 선수 과목이 없어졌다는 의미이므로 큐에 추가합니다.
4.  **반복:** 큐가 빌 때까지 3단계를 반복합니다.
5.  **사이클 검사:** 만약 위상 정렬을 수행한 결과 정렬된 정점의 개수가 전체 정점의 개수보다 적다면, 그래프에 순환(Cycle)이 존재하여 위상 정렬이 불가능하다는 의미입니다.

## 3. 파이썬으로 위상 정렬 구현하기

이제 Kahn의 알고리즘을 파이썬 코드로 구현해 봅시다.

```python
from collections import defaultdict, deque

def topological_sort(graph, num_vertices):
    """
    Kahn의 알고리즘을 사용하여 위상 정렬을 수행합니다.
    :param graph: 인접 리스트 형태의 그래프 (예: {0: [1, 2], 1: [3], 2: [3]})
    :param num_vertices: 그래프의 전체 정점 개수
    :return: 위상 정렬된 정점 리스트 또는 순환이 있을 경우 None
    """
    
    # 1. 모든 정점의 진입 차수(in-degree)를 계산합니다.
    in_degree = defaultdict(int)
    for u in graph:
        for v in graph[u]:
            in_degree[v] += 1
    
    # 그래프에 없는 정점도 in_degree 딕셔너리에 포함될 수 있도록 초기화
    # (특히, 진출 간선만 있고 진입 간선이 없는 정점들을 위해)
    for i in range(num_vertices):
        if i not in in_degree:
            in_degree[i] = 0

    # 2. 진입 차수가 0인 정점을 큐에 추가합니다.
    queue = deque()
    for i in range(num_vertices):
        if in_degree[i] == 0:
            queue.append(i)
            
    result = [] # 위상 정렬 결과를 저장할 리스트
    
    # 3. 큐에서 정점 추출 및 처리 (4. 큐가 빌 때까지 반복)
    while queue:
        u = queue.popleft() # 큐에서 정점 하나를 꺼냅니다.
        result.append(u) # 결과 리스트에 추가합니다.
        
        # 꺼낸 정점(u)과 연결된 모든 이웃 정점(v)을 순회합니다.
        for v in graph[u]:
            in_degree[v] -= 1 # 이웃 정점의 진입 차수를 1 감소시킵니다.
            
            # 만약 이웃 정점의 진입 차수가 0이 되면 큐에 추가합니다.
            if in_degree[v] == 0:
                queue.append(v)
                
    # 5. 사이클 검사
    # 위상 정렬된 정점의 개수가 전체 정점의 개수와 다르면 그래프에 순환이 있다는 의미입니다.
    if len(result) == num_vertices:
        return result
    else:
        print("그래프에 순환이 존재하여 위상 정렬을 수행할 수 없습니다.")
        return None

# --- 사용 예시 ---

# 예시 1: 선수 과목 그래프
# 0: CS 기초, 1: 자료구조, 2: 미적분, 3: 알고리즘, 4: 물리학, 5: 졸업 프로젝트
# CS 기초 -> 자료구조, 미적분 -> 물리학, 자료구조 -> 알고리즘, 물리학 -> 졸업 프로젝트, 알고리즘 -> 졸업 프로젝트
graph1 = {
    0: [1],      # CS 기초 -> 자료구조
    2: [4],      # 미적분 -> 물리학
    1: [3],      # 자료구조 -> 알고리즘
    4: [5],      # 물리학 -> 졸업 프로젝트
    3: [5],      # 알고리즘 -> 졸업 프로젝트
    # 0, 1, 2, 3, 4, 5 외에 다른 정점은 없음을 가정
}
num_vertices1 = 6

print("--- 예시 1: 선수 과목 위상 정렬 ---")
sorted_order1 = topological_sort(graph1, num_vertices1)
if sorted_order1:
    print(f"위상 정렬 결과: {sorted_order1}")
    # 가능한 출력: [0, 2, 1, 4, 3, 5] 또는 [2, 0, 1, 4, 3, 5] 등 (순서는 유일하지 않을 수 있음)
    # 0(CS 기초), 2(미적분)부터 시작하여 의존성 순서에 따라 정렬됨을 확인할 수 있습니다.

print("\n")

# 예시 2: 순환이 있는 그래프
# 0 -> 1 -> 2 -> 0 (순환)
graph2 = {
    0: [1],
    1: [2],
    2: [0]
}
num_vertices2 = 3

print("--- 예시 2: 순환 그래프 ---")
sorted_order2 = topological_sort(graph2, num_vertices2)
if sorted_order2:
    print(f"위상 정렬 결과: {sorted_order2}")
```

**코드 설명:**

1.  **`defaultdict(int)` 와 `deque` 임포트:**
    *   `defaultdict(int)`: 딕셔너리에 없는 키에 접근할 때 자동으로 기본값(int의 경우 0)을 할당해 줍니다. `in_degree`를 계산할 때 유용합니다.
    *   `deque`: 양쪽 끝에서 빠르게 추가/삭제가 가능한 큐 구현체입니다. `list`의 `pop(0)`보다 효율적입니다.
2.  **`topological_sort` 함수:**
    *   `graph`: 인접 리스트 형태로 그래프를 표현합니다. `0: [1, 2]`는 0번 정점에서 1번과 2번 정점으로 간선이 있다는 의미입니다.
    *   `num_vertices`: 그래프의 전체 정점 개수를 알려줍니다.
3.  **진입 차수 계산:** `in_degree` 딕셔너리를 만들고, `graph`를 순회하며 각 정점 `v`의 `in_degree[v]` 값을 증가시킵니다.
    *   주의할 점은, `graph` 딕셔너리에 키로 존재하지 않지만 `num_vertices`에 포함되는 정점(진입 간선만 있고 진출 간선이 없는 정점)도 `in_degree`에 올바르게 초기화되도록 `for i in range(num_vertices)` 루프를 한 번 더 돌려줍니다.
4.  **큐 초기화:** `in_degree` 값이 0인 모든 정점을 `queue`에 추가합니다. 이들이 위상 정렬의 시작점이 됩니다.
5.  **메인 루프 (`while queue`):**
    *   큐에서 정점 `u`를 하나 꺼내 `result` 리스트에 추가합니다.
    *   `u`에서 나가는 모든 간선 (`u`의 이웃 `v`)에 대해 `in_degree[v]`를 1 감소시킵니다.
    *   만약 `in_degree[v]`가 0이 되면, `v`는 이제 모든 선수 조건이 충족되었으므로 큐에 추가하여 다음 처리 대상으로 만듭니다.
6.  **사이클 검사:** `result` 리스트의 길이가 `num_vertices`와 같으면 모든 정점이 정렬된 것이므로 유효한 위상 정렬입니다. 그렇지 않으면 순환이 존재하여 위상 정렬이 불가능합니다.

## 4. 실생활에서의 활용 예시

위상 정렬은 단순한 알고리즘을 넘어 실제 개발 환경에서 매우 유용하게 사용됩니다.

*   **빌드 시스템:** 소프트웨어 프로젝트를 빌드할 때, 어떤 파일이 어떤 파일에 의존하는지 파악하여 올바른 컴파일/링크 순서를 결정합니다. (예: `make`, `Gradle`, `Maven`)
*   **패키지 의존성 관리:** `npm` (Node.js), `pip` (Python), `apt` (Linux)와 같은 패키지 관리자는 라이브러리 설치 시 의존하는 다른 라이브러리들을 올바른 순서로 설치하기 위해 위상 정렬을 사용합니다.
*   **작업 스케줄링:** 복잡한 프로젝트에서 여러 작업 간의 선후 관계가 있을 때, 모든 작업을 완료할 수 있는 효율적인 순서를 찾습니다.
*   **컴파일러:** 컴파일러는 코드의 여러 최적화 단계나 분석 단계를 특정 순서로 실행해야 할 때 위상 정렬을 활용할 수 있습니다.
*   **데이터베이스 뷰 업데이트:** 여러 뷰(View)가 서로 의존하는 경우, 변경된 데이터를 올바른 순서로 업데이트해야 합니다.
