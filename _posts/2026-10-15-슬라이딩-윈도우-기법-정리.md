# 알고리즘 효율성을 높이는 슬라이딩 윈도우 기법: 초보자를 위한 완벽 가이드

---

## 🚀 슬라이딩 윈도우, 대체 뭘까요?

우리가 어떤 배열이나 문자열에서 '연속된' 부분에 대한 정보를 찾을 때가 있습니다. 예를 들어, "주어진 배열에서 특정 크기 K의 부분 배열 중 합이 가장 큰 것을 찾아라" 같은 문제들이죠.

이런 문제를 풀 때 가장 먼저 떠오르는 방법은 아마 모든 가능한 부분 배열을 일일이 확인하는 것일 겁니다. 하지만 이 방법은 데이터의 크기가 커질수록 엄청나게 느려져요. 마치 넓은 풍경을 보려고 버스 창문을 처음부터 끝까지 다 열었다 닫았다 하는 것과 같달까요? 너무 비효율적이죠.

여기서 **슬라이딩 윈도우** 기법이 등장합니다! 슬라이딩 윈도우는 이름 그대로 '창문'처럼 특정 크기의 '윈도우(Window)'를 만들고, 이 윈도우를 데이터 위에서 한 칸씩 '슬라이딩(Sliding)' 이동시키면서 필요한 정보를 얻는 기법입니다.

이 비유를 계속하자면, 버스 창문을 다 열지 않고 딱 한 칸의 창문만 고정해 놓고, 버스가 움직이면 풍경이 알아서 바뀌는 것처럼, 윈도우를 한 칸씩 이동시키면서 이전에 계산했던 정보를 재활용하는 것이 핵심입니다.

---

## 🎯 왜 슬라이딩 윈도우를 사용할까요? (장점)

가장 큰 이유는 바로 **시간 복잡도 개선**입니다.
일반적으로 N개의 요소가 있는 배열에서 크기 K의 모든 부분 배열을 확인하려면 `O(N * K)` 또는 `O(N^2)`의 시간 복잡도가 필요합니다. 하지만 슬라이딩 윈도우를 사용하면 대부분 `O(N)`의 시간 복잡도로 문제를 해결할 수 있습니다. 이는 데이터의 크기가 커질수록 엄청난 성능 차이를 만들어냅니다.

**핵심 원리:**
이전 윈도우의 계산 결과를 버리지 않고, 새로운 윈도우를 만들 때 **불필요한 중복 계산을 제거**하는 데 있습니다. 윈도우가 한 칸 이동하면, 가장 왼쪽의 요소는 빠지고 가장 오른쪽의 새로운 요소가 추가됩니다. 이 과정에서 우리는 이전 윈도우 값에서 빠진 값을 빼고, 새로 들어온 값을 더하는 방식으로 효율적으로 윈도우의 값을 갱신할 수 있습니다.

---

## 🛠️ 슬라이딩 윈도우, 어떻게 동작할까요? (단계별 설명)

가장 기본적인 **고정 크기 윈도우**를 예시로 설명해 드릴게요.

1.  **초기 윈도우 설정:** 배열의 첫 `K`개 요소를 포함하는 초기 윈도우를 설정하고, 필요한 값(합, 평균 등)을 계산합니다.
2.  **윈도우 슬라이딩:** 이제 윈도우를 오른쪽으로 한 칸씩 이동시킵니다.
    *   윈도우의 **가장 왼쪽 요소**를 윈도우에서 **제외**합니다.
    *   윈도우의 **새로운 가장 오른쪽 요소**를 윈도우에 **추가**합니다.
    *   이때마다 윈도우의 값을 효율적으로 갱신하고, 문제에서 요구하는 조건(최대값, 최소값 등)을 확인하여 업데이트합니다.
3.  **반복:** 배열의 끝에 도달할 때까지 2번 과정을 반복합니다.

## 🧑‍💻 코드로 알아보는 슬라이딩 윈도우 (예제)

가장 흔하게 접할 수 있는 예시인 "주어진 정수 배열에서 크기 K인 모든 연속 부분 배열의 최대 합을 찾아라" 문제를 통해 슬라이딩 윈도우를 적용해 보겠습니다.

**문제:** `arr = [1, 4, 2, 10, 2, 3, 1, 0, 20]` 이고 `K = 3` 일 때, 크기 3인 부분 배열의 최대 합을 구하시오.

### 1. 나이브(Naive)한 접근 (비효율적인 방법)

```python
def max_subarray_sum_naive(arr, k):
    n = len(arr)
    if n < k:
        return "배열의 길이가 K보다 작습니다."

    max_sum = 0
    # 모든 가능한 부분 배열을 순회
    for i in range(n - k + 1): # 시작 인덱스
        current_sum = 0
        for j in range(i, i + k): # K 크기만큼 더하기
            current_sum += arr[j]
        max_sum = max(max_sum, current_sum)
    return max_sum

arr = [1, 4, 2, 10, 2, 3, 1, 0, 20]
k = 3
print(f"나이브 방식의 최대 합: {max_subarray_sum_naive(arr, k)}")
# 예상 출력: 32 (10, 2, 20 이 아니라, [10, 2, 3] = 15, [0, 20, X] 잘못된 예시)
# 올바른 예시: [2, 10, 2] = 14, [10, 2, 3] = 15, [3, 1, 0] = 4, [1, 0, 20] = 21 (정정: [1, 0, 20]의 합이 21이므로, 20+3+1 = 24? 아니네.)
# [1, 4, 2] = 7
# [4, 2, 10] = 16
# [2, 10, 2] = 14
# [10, 2, 3] = 15
# [2, 3, 1] = 6
# [3, 1, 0] = 4
# [1, 0, 20] = 21
# 최대 합은 21
```

이 방법은 중첩된 반복문 때문에 `O(N * K)`의 시간 복잡도를 가집니다. 배열이 길어지면 길어질수록 비효율적이겠죠?

### 2. 슬라이딩 윈도우 접근 (효율적인 방법)

```python
def max_subarray_sum_sliding_window(arr, k):
    n = len(arr)
    if n < k:
        return "배열의 길이가 K보다 작습니다."

    # 1. 초기 윈도우 설정: 첫 K개의 요소 합 계산
    window_sum = sum(arr[:k])
    max_sum = window_sum

    # 2. 윈도우 슬라이딩
    # arr[k]부터 arr[n-1]까지 순회
    for i in range(k, n):
        # 윈도우 이동:
        # 새로운 오른쪽 요소(arr[i])를 더하고,
        # 가장 왼쪽 요소(arr[i-k])를 뺀다.
        window_sum += arr[i] - arr[i - k]

        # 최대 합 업데이트
        max_sum = max(max_sum, window_sum)

    return max_sum

arr = [1, 4, 2, 10, 2, 3, 1, 0, 20]
k = 3
print(f"슬라이딩 윈도우 방식의 최대 합: {max_subarray_sum_sliding_window(arr, k)}")
# 예상 출력: 21
```

### 🧑‍🏫 코드 설명

1.  **`window_sum = sum(arr[:k])`**: 배열의 처음 `K`개 요소의 합을 구해서 `window_sum`에 저장합니다. 이것이 우리의 첫 번째 윈도우입니다. 동시에 `max_sum`에도 이 값을 초기화합니다.
2.  **`for i in range(k, n):`**: 이제 윈도우를 한 칸씩 오른쪽으로 이동시킬 차례입니다. `i`는 새로운 윈도우의 가장 오른쪽 요소의 인덱스를 가리킵니다. (예: `k=3`일 때 `i=3`은 `arr[3]` 즉 `10`을 가리킵니다.)
3.  **`window_sum += arr[i] - arr[i - k]`**: 이 부분이 슬라이딩 윈도우의 핵심입니다!
    *   `arr[i]`는 새로 윈도우에 들어오는 값입니다.
    *   `arr[i - k]`는 윈도우에서 빠져나가는 가장 왼쪽 값입니다. (예: `i=3`일 때 `i-k=0`이므로 `arr[0]` 즉 `1`이 빠집니다.)
    *   기존 `window_sum`에서 빠지는 값을 빼고, 들어오는 값을 더함으로써 `O(1)`의 시간 복잡도로 윈도우의 합을 갱신합니다.
4.  **`max_sum = max(max_sum, window_sum)`**: 윈도우가 이동할 때마다 현재 `window_sum`이 `max_sum`보다 크면 `max_sum`을 업데이트합니다.
5.  모든 윈도우를 확인하면 `max_sum`에는 크기 `K`인 부분 배열 중 가장 큰 합이 저장되어 있게 됩니다.

이 방법은 단일 반복문만 사용하므로 `O(N)`의 시간 복잡도를 가집니다. N이 아무리 커져도 K에 영향을 받지 않고 선형적으로 처리되죠!

## 🌟 슬라이딩 윈도우는 어디에 활용될까요?

*   **고정 크기 윈도우:** 위 예시처럼 특정 크기의 부분 배열/문자열에서 최대/최소 합, 평균 등을 찾을 때.
*   **가변 크기 윈도우:** 윈도우의 크기가 고정되지 않고, 특정 조건을 만족하는 가장 짧거나 가장 긴 부분 배열/문자열을 찾을 때 사용됩니다. (예: 합이 S 이상이 되는 최소 길이 부분 배열, 중복 없는 가장 긴 부분 문자열 등)
*   문자열 탐색, 배열에서 조건에 맞는 하위 집합 찾기 등 다양한 알고리즘 문제에 찰떡궁합입니다.
