# 파이썬 `with` 문 완전 정복: 컨텍스트 매니저, 더 이상 두렵지 않아요!

안녕하세요, 여러분! 파이썬 코드를 작성하다 보면 파일을 열고 닫거나, 데이터베이스 연결을 맺고 끊거나, 특정 작업을 위한 잠금을 설정했다가 해제하는 등 '자원 관리'가 필요한 경우가 참 많습니다. 혹시 파일을 열어놓고 닫는 걸 깜빡해서 리소스 누수가 발생하거나, 예외 상황 때문에 자원 해제가 제대로 안 되는 경험 있으신가요? 이런 문제들을 깔끔하고 안전하게 해결해주는 파이썬의 마법 같은 문법, 바로 `with` 문과 **컨텍스트 매니저(Context Manager)**에 대해 오늘 완벽하게 파헤쳐 보겠습니다!

초보자분들도 쉽게 이해할 수 있도록 친절하게 설명해 드릴 테니, 걱정 말고 따라오세요!

---

## 🧐 컨텍스트 매니저(Context Manager)는 도대체 뭘까요?

컨텍스트 매니저를 한마디로 정의하자면, **"어떤 작업이 시작될 때와 끝날 때 해야 할 일(자원 할당 및 해제, 설정 변경 및 복원 등)을 자동으로 처리해주는 객체"**입니다. 마치 특별한 방에 들어갈 때 문을 열어주고, 방에서 나올 때 문을 닫아주는 '문지기'와 같다고 생각하시면 됩니다. `with` 문은 바로 이 컨텍스트 매니저의 지시를 따르는 문법이고요.

가장 큰 장점은 다음과 같습니다:
1.  **자원 관리의 자동화:** 파일을 열면 자동으로 닫아주고, 잠금을 설정하면 자동으로 풀어주는 등, 개발자가 일일이 신경 쓰지 않아도 됩니다.
2.  **예외 안전성:** `with` 블록 안에서 어떤 예외가 발생하더라도 자원 해제는 *항상* 보장됩니다. `try...finally` 구문을 사용한 것과 같은 효과를 얻을 수 있죠.
3.  **코드의 간결성:** 자원 관리를 위한 반복적인 코드를 줄여주어 코드를 더 읽기 쉽고 간결하게 만듭니다.

## 🚀 `with` 문, 어떻게 사용할까요? (가장 흔한 예제)

`with` 문을 사용하는 가장 대표적인 예제는 바로 파일 입출력입니다. 파일을 열고 작업한 다음, 꼭 닫아줘야 하는데요. `with` 문을 사용하면 이 과정을 아주 쉽게 처리할 수 있습니다.

```python
# 파일 쓰기 예제
print("--- 파일 쓰기 시작 ---")
with open('my_file.txt', 'w', encoding='utf-8') as f:
    f.write('안녕하세요, 컨텍스트 매니저!\n')
    f.write('with 문 정말 편리하네요.\n')
print("--- 파일 쓰기 완료 (자동으로 파일 닫힘) ---")

# 파일 읽기 예제
print("\n--- 파일 읽기 시작 ---")
with open('my_file.txt', 'r', encoding='utf-8') as f:
    content = f.read()
    print(content)
print("--- 파일 읽기 완료 (자동으로 파일 닫힘) ---")

# with 문 없이 수동으로 닫을 경우 (번거롭고 에러 발생 위험)
# f = open('another_file.txt', 'w')
# try:
#     f.write('이건 수동으로 닫아야 해요.\n')
#     # 여기서 에러가 발생하면 f.close()가 실행되지 않을 수 있습니다!
# finally:
#     f.close()
```

위 코드에서 `open()` 함수는 파일 객체를 반환하는 동시에 컨텍스트 매니저 역할을 수행합니다.
*   `with open(...) as f:` 구문이 시작되면 `open()`이 내부적으로 `__enter__`라는 특별한 메서드를 호출하여 파일 객체(`f`)를 준비합니다.
*   `with` 블록 내부의 코드가 실행됩니다.
*   `with` 블록이 끝나면 (정상적으로 끝나든, 에러가 발생하든 상관없이) `open()`이 내부적으로 `__exit__`라는 특별한 메서드를 호출하여 파일을 *자동으로* 닫아줍니다.

정말 편리하죠? `f.close()`를 직접 호출할 필요가 없어 실수를 방지하고 코드를 훨씬 깔끔하게 유지할 수 있습니다.

## 🛠️ 나만의 컨텍스트 매니저 만들기: `__enter__`와 `__exit__`

파이썬의 모든 객체가 컨텍스트 매니저가 될 수 있는 것은 아닙니다. 컨텍스트 매니저가 되려면 두 가지 특별한 메서드, `__enter__`와 `__exit__`를 구현해야 합니다.

### 1. 클래스를 이용한 컨텍스트 매니저

가장 기본적인 방법은 클래스를 정의하고 그 안에 `__enter__`와 `__exit__` 메서드를 구현하는 것입니다.

*   `__enter__(self)`: `with` 블록이 시작될 때 호출됩니다. 이 메서드가 반환하는 값이 `as` 키워드 뒤의 변수에 할당됩니다.
*   `__exit__(self, exc_type, exc_val, exc_tb)`: `with` 블록이 끝날 때 호출됩니다.
    *   `exc_type`, `exc_val`, `exc_tb`: `with` 블록 내에서 예외가 발생했을 경우, 예외의 타입, 값, 트레이스백 정보를 담고 있습니다. 예외가 발생하지 않았다면 모두 `None`입니다.
    *   이 메서드가 `True`를 반환하면, `with` 블록 내부에서 발생한 예외를 "처리했다"고 간주하여 파이썬은 해당 예외를 다시 발생시키지 않고 넘어갑니다. `False` (또는 아무것도 반환하지 않음)를 반환하면 예외는 다시 발생합니다.

간단한 예시로, 코드 실행 시간을 측정해주는 컨텍스트 매니저를 만들어 볼까요?

```python
import time

class MyTimer:
    def __enter__(self):
        self.start_time = time.time()
        print("[타이머 시작] 작업을 시작합니다.")
        return self # 'as' 뒤 변수에 MyTimer 인스턴스 자신을 할당

    def __exit__(self, exc_type, exc_val, exc_tb):
        end_time = time.time()
        elapsed_time = end_time - self.start_time
        print(f"[타이머 종료] 작업이 {elapsed_time:.4f}초 걸렸습니다.")

        if exc_type: # 예외가 발생했다면
            print(f"!!! 경고: 작업 중 {exc_type.__name__} 예외가 발생했습니다: {exc_val}")
            # return True # True를 반환하면 예외를 숨길 수 있습니다. (여기서는 예외를 다시 발생시키도록 False 또는 None 반환)

print("--- MyTimer 컨텍스트 매니저 사용 ---")
with MyTimer() as timer:
    print("복잡한 계산을 하는 중...")
    time.sleep(1.5) # 1.5초 동안 대기
    print("계산 완료!")

print("\n--- 예외가 발생하는 경우 ---")
with MyTimer() as timer:
    print("문제 발생 가능성이 있는 작업...")
    time.sleep(0.5)
    raise ValueError("고의로 발생시킨 에러!") # 예외 발생
    print("이 코드는 실행되지 않습니다.")

print("프로그램은 계속 실행됩니다. (MyTimer의 __exit__이 예외를 처리하지 않았으므로)")
```

`MyTimer` 클래스는 `with` 블록이 시작될 때(`__enter__`) 시간을 기록하고, 블록이 끝날 때(`__exit__`) 걸린 시간을 계산하여 출력합니다. 심지어 블록 내에서 예외가 발생해도 `__exit__`는 항상 호출되어 시간을 측정하고 예외 정보를 출력해줍니다.

### 2. `contextlib.contextmanager` 데코레이터를 이용한 컨텍스트 매니저

클래스를 만드는 것이 번거롭다면, `contextlib` 모듈의 `contextmanager` 데코레이터를 사용하여 함수 기반으로 컨텍스트 매니저를 만들 수 있습니다. `yield` 키워드를 사용하는데, `yield` 전의 코드는 `__enter__` 부분처럼 동작하고, `yield` 후의 코드는 `__exit__` 부분처럼 동작합니다.

```python
from contextlib import contextmanager
import time

@contextmanager
def simple_timer():
    start_time = time.time()
    print("[간단 타이머 시작]")
    try:
        yield # 이 부분이 실행되면 with 블록으로 제어권이 넘어갑니다.
    finally:
        end_time = time.time()
        elapsed_time = end_time - start_time
        print(f"[간단 타이머 종료] 총 {elapsed_time:.4f}초 소요.")

print("\n--- simple_timer 함수 기반 컨텍스트 매니저 사용 ---")
with simple_timer():
    print("함수 기반 타이머로 작업 중...")
    time.sleep(0.8)
    print("작업 완료!")

print("\n--- 함수 기반 타이머에서 예외 발생 시 ---")
with simple_timer():
    print("예외 발생 가능성이 있는 작업...")
    time.sleep(0.3)
    1 / 0 # ZeroDivisionError 발생!
    print("이 코드는 실행되지 않습니다.")

print("프로그램은 계속 실행됩니다. (finally 덕분에 타이머는 종료됨)")
```

`simple_timer` 함수는 `yield`를 기준으로 두 부분으로 나뉩니다.
*   `yield` 이전: `with` 블록 진입 시 실행될 코드 (`__enter__` 역할).
*   `yield` 이후: `with` 블록 종료 시 실행될 코드 (`__exit__` 역할). `try...finally`를 사용하면 예외 발생 여부와 관계없이 항상 실행됨을 보장할 수 있습니다.
*   `yield`가 반환하는 값은 `as` 변수에 할당되지 않습니다. 만약 `as` 변수에 할당하고 싶다면 `yield` 뒤에 값을 명시하면 됩니다. (예: `yield self` 또는 `yield resource`)

함수 기반 컨텍스트 매니저는 짧고 간단한 로직에 매우 유용하며, 클래스 기반보다 작성하기 쉽다는 장점이 있습니다.

## 💡 컨텍스트 매니저의 다양한 활용 사례

파일 입출력 외에도 컨텍스트 매니저는 정말 많은 곳에 활용될 수 있습니다.

*   **데이터베이스 연결 관리:** 연결을 맺고 `commit`/`rollback` 후 연결을 해제합니다.
    ```python
    # 실제 DB 연결 코드는 더 복잡하지만, 개념은 이렇습니다.
    # from database import Connection

    # with Connection() as db_conn:
    #     db_conn.execute("INSERT INTO users VALUES ('Alice')")
    #     db_conn.commit()
    ```
*   **스레드/프로세스 잠금 (Lock) 관리:** 멀티태스킹 환경에서 공유 자원에 대한 접근을 제어할 때 잠금을 획득하고 해제합니다.
    ```python
    import threading

    lock = threading.Lock()

    def worker():
        with lock: # lock.acquire() 호출
            print(f"{threading.current_thread().name}: 락 획득, 공유 자원 접근...")
            time.sleep(0.1) # 자원 사용
        # with 블록 종료 시 lock.release() 자동 호출
        print(f"{threading.current_thread().name}: 락 해제, 작업 완료.")

    threads = [threading.Thread(target=worker, name=f"Thread-{i}") for i in range(3)]
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    print("\n모든 스레드 작업 완료.")
    ```
*   **작업 디렉토리 임시 변경:** 특정 작업을 위해 일시적으로 작업 디렉토리를 변경했다가 원상 복구합니다.
    ```python
    import os
    from contextlib import contextmanager

    @contextmanager
    def change_dir(new_path):
        old_path = os.getcwd() # 현재 작업 디렉토리 저장
        print(f"현재 디렉토리: {old_path}")
        os.chdir(new_path) # 새 디렉토리로 변경
        print(f"-> 변경된 디렉토리: {os.getcwd()}")
        try:
            yield
        finally:
            os.chdir(old_path) # 원래 디렉토리로 복원
            print(f"<- 원래 디렉토리로 복원: {os.getcwd()}")

    # 'temp_dir'이 없다면 생성합니다.
    if not os.path.exists('temp_dir'):
        os.makedirs('temp_dir')

    with change_dir('temp_dir'):
        print(f"현재 작업 중인 디렉토리: {os.getcwd()}")
        with open('test_file.txt', 'w') as f:
            f.write("이 파일은 temp_dir에 있습니다.")
        print("파일 생성 완료.")
    
    print(f"작업 후 최종 디렉토리: {os.getcwd()}")
    # temp_dir에 파일이 생성되었는지 확인해 보세요.
    ```

이처럼 `with` 문과 컨텍스트 매니저는 설정 -> 작업 -> 복원/해제 패턴이 필요한 모든 곳에 적용될 수 있습니다.

## 🌟 마치며

오늘은 파이썬의 강력한 기능인 `with` 문과 컨텍스트 매니저에 대해 알아보았습니다. 파일, 네트워크 소켓, 데이터베이스 연결, 잠금 등 다양한 자원들을 안전하고 효율적으로 관리할 수 있게 해주는 아주 유용한 도구라는 것을 느끼셨을 거예요.

*   **핵심 정리:**
    *   `with` 문은 컨텍스트 매니저와 함께 사용하여 자원 할당/해제를 자동으로 처리합니다.
    *   `open()`, `threading.Lock()` 등 많은 파이썬 내장 객체들이 이미 컨텍스트 매니저로 작동합니다.
    *   `__enter__`와 `__exit__` 메서드를 구현한 클래스를 만들거나, `contextlib.contextmanager` 데코레이터를 사용하여 나만의 컨텍스트 매니저를 만들 수 있습니다.
    *   주요 이점은 코드의 간결성, 안전한 자원 관리, 그리고 예외 발생 시에도 자원 해제가 보장된다는 점입니다.

이제 `with` 문을 사용하면 `try...finally` 구문을 일일이 작성할 필요 없이 훨씬 깔끔하고 안전한 코드를 작성할 수 있게 될 것입니다. 여러분의 파이썬 코드가 한층 더 견고해질 거예요!
