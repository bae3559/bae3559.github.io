# 파이썬 컨텍스트 매니저 with문 완전 정복: 더 이상 헷갈리지 마세요!

안녕하세요, 여러분! 개발 블로그 작가 개발몽키입니다. 🐒

파이썬 코드를 작성하다 보면 `with open("파일.txt", "r") as f:` 와 같은 문구를 자주 보셨을 거예요. 처음 접하면 "이 `with`문은 도대체 뭘까? `as f`는 또 뭐고?" 하고 궁금증을 가지거나, 그저 파일을 다루는 특별한 문법이겠거니 하고 넘어가는 경우가 많습니다.

하지만 이 `with`문 뒤에는 파이썬의 강력한 기능 중 하나인 **컨텍스트 매니저(Context Manager)**가 숨어있습니다. 오늘은 이 컨텍스트 매니저와 `with`문을 여러분이 완벽하게 이해하고, 심지어 직접 만들어서 활용할 수 있도록 친절하게 안내해 드릴게요!

자, 그럼 시작해 볼까요?

## 1. `with`문, 왜 필요한가요? 🤔

`with`문이 왜 필요한지 이해하려면, 먼저 `with`문이 없던 시절(?)의 불편함을 알아야 합니다. 대표적인 예시가 바로 **파일 처리**입니다.

파일을 열고 데이터를 읽거나 쓴 다음에는 반드시 **파일을 닫아줘야** 합니다. 파일을 닫지 않으면 다음과 같은 문제가 발생할 수 있습니다.

*   메모리 누수: 운영체제에 파일 핸들을 반환하지 않아 메모리를 계속 점유하게 됩니다.
*   데이터 손상: 캐시된 데이터가 디스크에 기록되지 않아 데이터가 유실될 수 있습니다.
*   다른 프로그램과의 충돌: 다른 프로그램이 해당 파일에 접근하지 못하게 될 수 있습니다.

일반적으로 파일을 열고 닫는 코드는 이렇게 작성할 수 있습니다.

```python
# 일반적인 파일 처리 (수동으로 닫기)
file = None
try:
    file = open("hello.txt", "w", encoding="utf-8")
    file.write("안녕하세요, 컨텍스트 매니저!\n")
    file.write("Python은 정말 멋져요!")
    print("파일에 내용을 썼습니다.")
except Exception as e:
    print(f"에러 발생: {e}")
finally:
    if file:
        file.close() # 파일을 닫는 것을 잊지 말아야 합니다!
        print("파일을 닫았습니다.")
```

위 코드에서 중요한 부분은 `finally` 블록입니다. `try` 블록 안에서 에러가 발생하더라도 `finally` 블록은 항상 실행되기 때문에, 파일을 안전하게 닫을 수 있습니다. 하지만 이 방식은 코드가 다소 길고 복잡해 보입니다.

여기서 `with`문이 등장합니다! `with`문을 사용하면 이렇게 바뀝니다.

```python
# with 문을 사용한 파일 처리
with open("hello.txt", "w", encoding="utf-8") as file:
    file.write("안녕하세요, 컨텍스트 매니저!\n")
    file.write("Python은 정말 멋져요!")
    print("파일에 내용을 썼습니다.")
# with 블록을 벗어나면 파일은 자동으로 닫힙니다!
print("with 블록 종료. 파일이 자동으로 닫혔습니다.")
```

훨씬 간결해졌죠? `with` 블록을 벗어나는 순간, 파이썬이 **알아서** 파일을 닫아줍니다. 개발자가 직접 `file.close()`를 호출할 필요가 없죠. 심지어 블록 내부에서 에러가 발생해도 파일은 안전하게 닫힙니다.

이 마법 같은 일이 가능한 이유는 바로 **컨텍스트 매니저** 덕분입니다.

## 2. 컨텍스트 매니저의 핵심: `__enter__`와 `__exit__` 🎩✨

`with`문이 동작하는 방식은 마치 특별한 방에 들어갔다가 나오는 것과 같습니다. 이 특별한 방의 문을 여는 역할과 닫는 역할을 하는 것이 바로 **컨텍스트 매니저**입니다.

모든 컨텍스트 매니저 객체는 두 가지 특별한 메서드를 가지고 있습니다.

1.  `__enter__(self)`: `with` 블록에 진입할 때 호출됩니다. 이 메서드가 반환하는 값이 `as` 키워드 뒤에 오는 변수(`as file`의 `file`)에 할당됩니다.
2.  `__exit__(self, exc_type, exc_val, exc_tb)`: `with` 블록에서 벗어날 때 호출됩니다. `with` 블록이 정상적으로 종료되든, 예외가 발생하든 상관없이 항상 호출됩니다.

    *   `exc_type`: 발생한 예외의 타입 (예: `ValueError`, `TypeError`). 예외가 없으면 `None`.
    *   `exc_val`: 발생한 예외의 값 (예: `ValueError("잘못된 값입니다")`). 예외가 없으면 `None`.
    *   `exc_tb`: 발생한 예외의 트레이스백(Traceback) 객체. 예외가 없으면 `None`.

`__exit__` 메서드가 `True`를 반환하면, `with` 블록 안에서 발생한 예외가 외부로 전파되지 않고 **억제됩니다**. `False` (혹은 아무것도 반환하지 않음)를 반환하면 예외가 정상적으로 전파됩니다.

## 3. 나만의 컨텍스트 매니저 만들기 🛠️

이제 `with`문과 컨텍스트 매니저가 어떻게 동작하는지 알았으니, 직접 나만의 컨텍스트 매니저를 만들어 봅시다! 두 가지 방법이 있습니다.

### 방법 1: 클래스를 이용한 컨텍스트 매니저

가장 기본적인 방법은 `__enter__`와 `__exit__` 메서드를 가진 클래스를 만드는 것입니다. 간단한 타이머를 만들어볼게요.

```python
import time

class MyTimer:
    def __enter__(self):
        """
        with 블록 진입 시 호출됩니다.
        타이머 시작 시간을 기록하고, 이 객체(self)를 반환하여 'as' 뒤 변수에 할당합니다.
        """
        self.start_time = time.time()
        print("--- [MyTimer] 타이머 시작! ---")
        return self # 'as' 뒤에 오는 객체 (여기서는 MyTimer 인스턴스 자체)

    def __exit__(self, exc_type, exc_val, exc_tb):
        """
        with 블록 종료 시 호출됩니다.
        경과 시간을 계산하고 출력하며, 예외 발생 여부를 확인합니다.
        """
        end_time = time.time()
        elapsed_time = end_time - self.start_time
        print(f"--- [MyTimer] 타이머 종료! 경과 시간: {elapsed_time:.4f}초 ---")

        if exc_type: # 예외가 발생했다면
            print(f"!!! [MyTimer] 에러 발생: {exc_val} ({exc_type.__name__})")
            # True를 반환하면 이 예외를 '잡아서' 외부로 전파되지 않게 합니다.
            # 여기서는 False (혹은 아무것도 반환하지 않아) 예외가 계속 전파되도록 합니다.
            return False
        print("--- [MyTimer] 정상 종료 ---")

# MyTimer 컨텍스트 매니저 사용 예시
print("--- MyTimer 사용 (정상 종료) ---")
with MyTimer() as timer_obj: # __enter__가 호출되고 timer_obj에 MyTimer 객체가 할당됨
    print("with 블록 내부: 2초 대기 중...")
    time.sleep(2)
    # timer_obj.start_time 등을 통해 객체에 접근할 수도 있습니다.
print("with 블록 외부: MyTimer 종료.\n")


print("--- MyTimer 사용 (예외 발생) ---")
try:
    with MyTimer(): # __enter__가 호출됨
        print("with 블록 내부: 1초 대기 중...")
        time.sleep(1)
        print("고의로 에러 발생: 1 / 0")
        result = 1 / 0 # ZeroDivisionError 발생
except ZeroDivisionError:
    print("with 블록 외부: ZeroDivisionError를 잡았습니다.")
print("with 블록 외부: MyTimer 종료 (예외 처리 완료).\n")
```

위 코드를 실행해보면 `with` 블록에 진입할 때 `__enter__`가, 블록을 벗어날 때 `__exit__`가 호출되는 것을 확인할 수 있습니다. 예외가 발생했을 때도 `__exit__`가 호출되어 `elapsed_time`을 출력하는 것을 볼 수 있죠!

### 방법 2: `contextlib` 모듈과 `@contextmanager` 데코레이터

클래스를 만드는 것이 번거롭거나, 컨텍스트 매니저가 간단한 로직만을 포함할 때는 `contextlib` 모듈의 `@contextmanager` 데코레이터를 사용하는 것이 훨씬 편리합니다.

이 방법은 **제너레이터(generator)**와 `yield` 키워드를 활용합니다.

```python
from contextlib import contextmanager
import time

@contextmanager
def simple_timer():
    """
    @contextmanager 데코레이터를 사용한 타이머 컨텍스트 매니저.
    """
    start_time = time.time()
    print("[simple_timer] 시작!")
    try:
        yield # 이곳이 with 블록이 실행되는 지점
        # yield 문 이전 코드는 __enter__ 로직으로 동작
    finally:
        # yield 문 이후 코드는 __exit__ 로직으로 동작
        end_time = time.time()
        elapsed_time = end_time - start_time
        print(f"[simple_timer] 종료! 경과 시간: {elapsed_time:.4f}초")

# simple_timer 컨텍스트 매니저 사용 예시
print("--- simple_timer 데코레이터 사용 ---")
with simple_timer():
    print("with 블록 내부: 1초 대기 중...")
    time.sleep(1)
    # yield된 것이 없으므로 'as' 뒤에 변수를 받을 수 없습니다.
print("with 블록 외부: simple_timer 종료.\n")

print("--- simple_timer 데코레이터 사용 (예외 발생) ---")
try:
    with simple_timer():
        print("with 블록 내부: 짧은 대기 후 에러 발생...")
        time.sleep(0.5)
        raise ValueError("일부러 발생시킨 에러!")
except ValueError as e:
    print(f"with 블록 외부: {e}를 잡았습니다.")
print("with 블록 외부: simple_timer 종료 (예외 처리 완료).\n")
```

`@contextmanager` 데코레이터를 사용하면, `yield` 문 이전의 코드는 `__enter__` 메서드의 로직처럼 동작하고, `yield` 문 이후의 코드는 `__exit__` 메서드의 로직처럼 동작합니다. 만약 `yield` 문에서 값을 반환하면, 그 값이 `as` 키워드 뒤의 변수에 할당됩니다. (위 예시에서는 반환값이 없으므로 `as`를 쓰지 않았습니다.)

`try...finally` 블록으로 `yield`를 감싸면, `with` 블록 내에서 예외가 발생하더라도 `finally` 블록의 코드가 실행되어 안전하게 리소스를 정리할 수 있습니다.

## 4. 언제 컨텍스트 매니저를 사용해야 할까요? 🎯

이제 컨텍스트 매니저를 만들고 사용할 수 있게 되었으니, 언제 이 강력한 기능을 활용해야 할지 알아봅시다.

컨텍스트 매니저는 **'시작(setup)'과 '종료(teardown)' 과정이 명확하게 구분되는 작업**에 매우 유용합니다.

*   **파일 처리:** `open()` 함수 (가장 흔한 예시)
*   **네트워크 소켓 연결:** `socket.socket()` 객체
*   **데이터베이스 연결:** `psycopg2`나 `SQLAlchemy` 같은 라이브러리의 커넥션 객체
*   **락(Lock) 획득 및 해제:** 멀티스레딩/멀티프로세싱 환경에서 공유 자원에 대한 접근 제어 (예: `threading.Lock`)
*   **임시 디렉토리 생성 및 삭제:** `tempfile.TemporaryDirectory()`
*   **자원 할당 및 해제:** 특정 자원을 사용하기 전에 할당하고, 사용 후에는 반드시 해제해야 하는 모든 경우

간단히 말해, 어떤 작업을 시작하기 전에 준비 과정이 필요하고, 작업이 끝난 후에는 반드시 뒷정리(리소스 해제)를 해야 하는 상황이라면 컨텍스트 매니저를 고려해 보세요! 코드를 훨씬 안전하고 읽기 쉽게 만들어 줄 것입니다.

## 맺음말

오늘은 파이썬의 `with`문과 컨텍스트 매니저에 대해 깊이 있게 알아보았습니다.

*   `with`문이 **파일 처리**와 같은 **리소스 관리**를 얼마나 간결하고 안전하게 만드는지.
*   컨텍스트 매니저가 `__enter__`와 `__exit__` 메서드를 통해 **자동으로 자원 할당/해제** 로직을 처리하는 원리.
*   클래스나 `@contextmanager` 데코레이터를 이용해 **나만의 컨텍스트 매니저를 만드는 방법**.

이해되셨나요? 이제 `with`문을 단순히 파일 열고 닫는 문법으로만 보지 않고, 그 안에 숨겨진 강력한 컨텍스트 매니저의 힘을 깨달으셨을 거예요. 앞으로 코드를 작성하실 때, '여기 `with`문을 쓸 수 있지 않을까?', '이 상황에 나만의 컨텍스트 매니저를 만들면 더 효율적이지 않을까?'라고 고민해 보세요!
