# [알고리즘 탐험] 모든 쌍 최단 경로를 찾아라! 플로이드-워셜 알고리즘 완벽 이해

안녕하세요, 개발 블로그 독자 여러분! 복잡한 문제 속에서 최적의 해답을 찾아내는 것은 개발자에게 늘 흥미로운 과제입니다. 특히 '최단 경로' 문제는 지도 앱, 네트워크 라우팅, 심지어 게임 AI에 이르기까지 다양한 분야에서 핵심적인 역할을 하죠. 오늘은 이 최단 경로 문제 중에서도 '모든 정점 쌍' 간의 최단 경로를 찾아주는 강력하고 직관적인 알고리즘, 바로 **플로이드-워셜(Floyd-Warshall) 알고리즘**에 대해 알아보는 시간을 갖겠습니다.

이 글을 통해 플로이드-워셜 알고리즘이 무엇인지, 어떻게 동작하는지, 그리고 실제 코드로 어떻게 구현하는지 초보자분들도 쉽게 이해하실 수 있도록 친절하게 설명해 드릴게요. 자, 그럼 함께 최단 경로의 세계로 떠나볼까요?

## 1. 플로이드-워셜 알고리즘이란?

플로이드-워셜 알고리즘은 그래프 내의 **모든 가능한 정점(노드) 쌍에 대한 최단 경로**를 찾는 알고리즘입니다. 보통 '모든 쌍 최단 경로(All-Pairs Shortest Path)' 문제를 해결하는 데 사용됩니다. 다익스트라(Dijkstra) 알고리즘이나 벨만-포드(Bellman-Ford) 알고리즘이 특정 시작점에서 다른 모든 정점까지의 최단 경로를 찾는 것과 대비됩니다.

이 알고리즘의 핵심은 **동적 프로그래밍(Dynamic Programming)** 기법에 있습니다. 즉, 문제를 더 작은 하위 문제로 나누고, 그 하위 문제들의 해답을 저장하고 재활용하여 최종 문제를 해결하는 방식이죠.

## 2. 알고리즘의 핵심 개념: '경유지'

플로이드-워셜 알고리즘의 가장 중요한 아이디어는 **'경유지(Intermediate Node)'**입니다.
어떤 두 정점 `i`에서 `j`로 가는 최단 경로를 찾을 때, 우리는 중간에 다른 정점 `k`를 거쳐 가는 것이 더 빠른지 아닌지를 계속해서 고려하게 됩니다.

간단하게 생각해볼까요? 서울에서 부산으로 가는 최단 경로를 찾고 있습니다. 기존에는 서울에서 부산으로 바로 가는 경로만 알고 있었는데, 대전을 경유하여 가는 경로가 더 짧다는 것을 알게 된다면, 우리는 서울에서 부산으로 가는 최단 경로를 대전을 경유하는 경로로 업데이트할 것입니다. 플로이드-워셜 알고리즘은 이 '대전(경유지)'의 역할을 그래프의 모든 정점에 대해 반복적으로 수행하는 것입니다.

알고리즘은 다음과 같은 과정을 거쳐 모든 쌍의 최단 경로를 찾습니다.

1.  **초기화:** `dist[i][j]` 배열을 만듭니다. `dist[i][j]`는 `i`에서 `j`로 가는 현재까지 알려진 최단 거리를 저장합니다.
    *   `i`에서 `j`로 가는 직접적인 간선이 있다면, `dist[i][j]`는 해당 간선의 가중치로 초기화합니다.
    *   `i`에서 `j`로 가는 직접적인 간선이 없다면, `dist[i][j]`는 '무한대'로 초기화합니다.
    *   자기 자신으로 가는 경로(`i`에서 `i`로)는 항상 0으로 초기화합니다.
2.  **경유지 반복:** 그래프의 모든 정점 `k`를 순회하며 '경유지'로 사용합니다.
    *   각 `k`에 대해, 모든 가능한 출발 정점 `i`와 도착 정점 `j`를 순회합니다.
    *   `i`에서 `j`로 가는 최단 경로가 '기존의 `dist[i][j]`'와 '`i`에서 `k`를 거쳐 `j`로 가는 경로(`dist[i][k] + dist[k][j]`)' 중 어느 것이 더 짧은지 비교합니다.
    *   더 짧은 경로가 발견되면 `dist[i][j]`를 해당 값으로 갱신합니다.
    *   즉, `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`

이 과정에서 가장 중요한 점은 **경유지 `k`를 가장 바깥쪽 루프에서 반복**한다는 것입니다. `k`가 차례로 0, 1, 2, ..., N-1까지 반복되면서, `k` 이하의 정점들만을 경유지로 사용했을 때의 최단 경로를 차례로 계산해 나가는 것이죠.

### 시간 복잡도

플로이드-워셜 알고리즘은 3중 반복문(`k`, `i`, `j`)으로 구성되기 때문에, 그래프의 정점 개수가 N일 때 **O(N^3)**의 시간 복잡도를 가집니다. N이 너무 큰 경우에는 비효율적일 수 있지만, N이 수백 개 정도일 때는 충분히 실용적입니다.

### 장점 및 단점

*   **장점:**
    *   **간단한 구현:** 3중 반복문으로 구현이 매우 직관적이고 쉽습니다.
    *   **음수 가중치 간선 처리:** 벨만-포드처럼 음수 가중치 간선이 있는 그래프에서도 최단 경로를 찾을 수 있습니다 (음수 사이클이 없는 경우).
    *   **음수 사이클 감지:** 만약 `dist[i][i]` 값이 음수가 된다면, 해당 그래프에 음수 사이클이 존재한다는 것을 의미합니다.
*   **단점:**
    *   **높은 시간 복잡도:** O(N^3)으로, 정점의 개수가 많아질수록 계산 시간이 급격히 늘어납니다. (N=1000 이면 10억 연산!)
    *   **특정 시작점 최단 경로에는 비효율적:** 특정 시작점에서 모든 다른 정점으로의 최단 경로만 필요하다면, 다익스트라(음수 간선 없을 때)나 벨만-포드(음수 간선 있을 때)가 더 효율적입니다.

## 3. 플로이드-워셜 알고리즘 코드 예제 (Python)

이제 실제 코드를 통해 플로이드-워셜 알고리즘을 구현하고 동작 방식을 살펴보겠습니다.
다음과 같은 그래프를 예시로 들어보겠습니다.

```
0번 노드 ---2---> 1번 노드
0번 노 ---X---> 2번 노드 (직접 연결 없음)
1번 노드 ---1---> 2번 노드
2번 노드 ---3---> 3번 노드
0번 노드 ---X---> 3번 노드 (직접 연결 없음)
```

이 그래프에서 0번 노드에서 3번 노드로 가는 최단 경로는 `0 -> 1 -> 2 -> 3` (총 비용: 2 + 1 + 3 = 6)이 됩니다.

```python
import math

# 무한대를 나타내기 위해 float('inf')를 사용합니다.
# 직접 연결되지 않은 경로의 초기 거리 값으로 사용됩니다.
INF = math.inf

def floyd_warshall(graph):
    """
    플로이드-워셜 알고리즘을 구현하여 모든 쌍 최단 경로를 계산합니다.

    Args:
        graph (list[list[int]]): 인접 행렬 형태로 표현된 그래프.
                                 graph[i][j]는 i에서 j로 가는 직접 간선의 가중치입니다.
                                 연결되지 않은 경우 INF로 표시됩니다.

    Returns:
        list[list[int]]: 모든 쌍 최단 경로를 담은 행렬 (dist[i][j]는 i에서 j로의 최단 거리).
    """
    n = len(graph) # 노드의 개수

    # 1. dist 행렬 초기화
    # dist[i][j]는 i에서 j로 가는 현재까지의 최단 거리를 저장합니다.
    dist = [[0] * n for _ in range(n)]

    for i in range(n):
        for j in range(n):
            if i == j:
                dist[i][j] = 0 # 자기 자신으로 가는 경로는 비용 0
            elif graph[i][j] != INF:
                dist[i][j] = graph[i][j] # 직접 연결된 경로는 그 가중치
            else:
                dist[i][j] = INF # 직접 연결되지 않았으면 무한대

    # 2. k를 경유지로 하여 최단 경로 갱신 (가장 중요한 부분!)
    # k는 '경유지'를 의미합니다. 모든 노드를 경유지로 한 번씩 고려합니다.
    for k in range(n):
        # i는 '출발 노드'를 의미합니다.
        for i in range(n):
            # j는 '도착 노드'를 의미합니다.
            for j in range(n):
                # i에서 j로 가는 기존 경로와
                # i에서 k를 거쳐 j로 가는 경로 (i -> k -> j) 중 더 짧은 것을 선택합니다.
                # '무한대' 경로가 포함된 덧셈은 여전히 무한대이므로,
                # 유효한 경로를 더하는 경우에만 비교를 수행합니다.
                if dist[i][k] != INF and dist[k][j] != INF:
                    dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])

    return dist

# --- 예제 그래프 정의 ---
# 4개 노드 (0번, 1번, 2번, 3번)를 가진 그래프
# graph_example[i][j]는 i에서 j로 가는 직접적인 경로의 비용입니다.
# INF는 직접적인 경로가 없음을 의미합니다.
graph_example = [
    [0, 2, INF, INF],      # 0번 노드에서 출발: 0->1 (2)
    [INF, 0, 1, INF],      # 1번 노드에서 출발: 1->2 (1)
    [INF, INF, 0, 3],      # 2번 노드에서 출발: 2->3 (3)
    [INF, INF, INF, 0]     # 3번 노드에서 출발
]

# 플로이드-워셜 알고리즘 실행
shortest_paths = floyd_warshall(graph_example)

print("모든 쌍 최단 경로 결과:")
for row in shortest_paths:
    # 출력 가독성을 위해 무한대 값은 'INF'로 표시합니다.
    print([val if val != INF else 'INF' for val in row])

```

### 코드 실행 결과 해석

위 코드를 실행하면 다음과 같은 결과가 출력됩니다.

```
모든 쌍 최단 경로 결과:
[0, 2, 3, 6]
['INF', 0, 1, 4]
['INF', 'INF', 0, 3]
['INF', 'INF', 'INF', 0]
```

이 행렬은 각 `dist[i][j]` 값을 나타냅니다.

*   `dist[0][0]` = 0 (0에서 0으로)
*   `dist[0][1]` = 2 (0에서 1로, 직접 경로)
*   `dist[0][2]` = 3 (0에서 2로, `0 -> 1 -> 2` 경로: 2 + 1 = 3)
*   `dist[0][3]` = 6 (0에서 3으로, `0 -> 1 -> 2 -> 3` 경로: 2 + 1 + 3 = 6)
*   `dist[1][0]` = 'INF' (1에서 0으로 가는 경로 없음)
*   `dist[1][2]` = 1 (1에서 2로, 직접 경로)
*   `dist[1][3]` = 4 (1에서 3으로, `1 -> 2 -> 3` 경로: 1 + 3 = 4)

보시는 것처럼 `0 -> 2`나 `0 -> 3`처럼 직접 경로가 없었거나 더 길었던 경로들이 경유지 `k`를 거쳐 더 짧은 경로로 업데이트된 것을 확인할 수 있습니다.

## 4. 언제 플로이드-워셜 알고리즘을 사용할까?

*   **모든 쌍의 최단 경로를 알고 싶을 때:** 가장 명확한 사용 사례입니다.
*   **그래프 크기가 상대적으로 작을 때:** N이 400~500 정도 이하일 때 효율적입니다.
*   **음수 간선이 존재하지만 음수 사이클은 없을 때:** 다익스트라는 음수 간선을 처리하지 못하므로, 이 경우 플로이드-워셜이 좋은 대안이 될 수 있습니다.
*   **연결 관계 파악 (Transitive Closure):** 특정 노드에서 특정 노드로 갈 수 있는지 여부만 알고 싶을 때 (가중치를 1로 설정하여 도달 가능 여부 파악).
