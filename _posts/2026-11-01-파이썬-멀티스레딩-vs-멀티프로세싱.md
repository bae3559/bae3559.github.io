# 파이썬 멀티스레딩 vs 멀티프로세싱: 당신의 코드를 더 빠르게!

안녕하세요, 여러분!
파이썬으로 개발하다 보면 "내 코드가 왜 이렇게 느리지?" 하고 답답함을 느끼는 순간이 오기 마련입니다. 특히 시간이 오래 걸리는 작업을 처리할 때면 더욱 그렇죠. 이때 우리는 코드의 실행 속도를 높이기 위한 **동시성(Concurrency)**과 **병렬성(Parallelism)** 기법을 고민하게 됩니다.

파이썬에서 이 두 가지 개념을 구현하는 대표적인 방법이 바로 **멀티스레딩(Multithreading)**과 **멀티프로세싱(Multiprocessing)**입니다. 비슷해 보이지만 그 작동 방식과 적합한 활용처가 전혀 다르답니다. 오늘은 이 두 가지 방법을 초보자도 쉽게 이해할 수 있도록 친절하게 설명해 드릴게요!

---

## 1. 파이썬 멀티스레딩 (Multithreading): 동시성의 마법

### 1.1. 멀티스레딩이란?

**스레드(Thread)**는 프로세스 내에서 실행되는 실행 단위입니다. 하나의 프로세스는 여러 개의 스레드를 가질 수 있으며, 이 스레드들은 프로세스의 메모리 공간을 공유합니다. 즉, 같은 코드와 데이터를 공유하면서 작업을 수행합니다.

멀티스레딩은 여러 개의 스레드를 동시에(정확히는 *동시처럼*) 실행하여 작업을 처리하는 방식입니다. 여러 작업을 번갈아가며 빠르게 수행하여 마치 동시에 처리되는 것처럼 보이게 만듭니다.

### 1.2. GIL (Global Interpreter Lock): 파이썬 멀티스레딩의 비밀

여기서 중요한 파이썬만의 특징이 등장합니다. 바로 **GIL(Global Interpreter Lock)**입니다.
파이썬 인터프리터는 한 번에 하나의 스레드만 파이썬 바이트코드를 실행하도록 허용하는 '글로벌 인터프리터 락(GIL)'이라는 메커니즘을 가지고 있습니다.

**이게 무슨 말이냐고요?**

비록 여러 개의 스레드를 만들더라도, CPU 코어가 여러 개 있더라도 파이썬 코드가 동시에 여러 스레드에서 병렬로 실행되지는 않는다는 뜻입니다. 마치 한 명의 요리사(프로세스)가 여러 개의 손(쓰레드)을 가지고 있지만, 동시에 하나의 작업만 수행할 수 있는 것과 비슷합니다. (한 손으로 양파 썰고, 다른 손으로 동시에 감자 썰기는 불가능하죠!)

**그렇다면 멀티스레딩이 쓸모없는 걸까요?**

전혀 아닙니다! GIL은 파이썬 *코드*의 병렬 실행을 막는 것이지, I/O 작업(입출력 작업)까지 막는 것은 아닙니다.
만약 여러분의 코드가 네트워크 요청, 파일 읽기/쓰기, 데이터베이스 접근 등 **I/O 바운드(I/O-bound)** 작업이 많다면, 한 스레드가 I/O 작업을 기다리는 동안(GIL을 잠시 놓아주는 동안) 다른 스레드가 파이썬 코드를 실행할 수 있습니다. 그래서 전체 작업 시간을 크게 단축시킬 수 있습니다!

### 1.3. 멀티스레딩 코드 예제 (I/O 바운드 작업)

파일 읽기처럼 시간이 걸리는 I/O 작업을 시뮬레이션 해보고, 멀티스레딩이 어떻게 성능을 향상시키는지 확인해 봅시다.

```python
import threading
import time

def io_bound_task(name):
    """
    I/O 바운드 작업을 시뮬레이션하는 함수
    (네트워크 요청, 파일 읽기 등)
    """
    print(f"[{name}] I/O 작업 시작...")
    time.sleep(2) # 2초 동안 대기하며 I/O 작업 시뮬레이션
    print(f"[{name}] I/O 작업 완료!")

if __name__ == "__main__":
    print("--- 단일 스레드 실행 ---")
    start_time = time.time()
    io_bound_task("Task 1 (Sync)")
    io_bound_task("Task 2 (Sync)")
    end_time = time.time()
    print(f"단일 스레드 실행 시간: {end_time - start_time:.2f}초\n") # 약 4초 소요

    print("--- 멀티 스레드 실행 ---")
    start_time = time.time()
    # Thread 객체 생성
    thread1 = threading.Thread(target=io_bound_task, args=("Task 1 (Thread)",))
    thread2 = threading.Thread(target=io_bound_task, args=("Task 2 (Thread)",))

    # 스레드 시작
    thread1.start()
    thread2.start()

    # 모든 스레드가 종료될 때까지 기다림
    thread1.join()
    thread2.join()

    end_time = time.time()
    print(f"멀티 스레드 실행 시간: {end_time - start_time:.2f}초") # 약 2초 소요
```

위 코드를 실행해 보면, 단일 스레드로는 약 4초가 걸리던 작업이 멀티스레딩을 사용하면 약 2초로 줄어드는 것을 볼 수 있습니다. 각 스레드가 I/O 대기 시간 동안 GIL을 양보했기 때문이죠!

## 2. 파이썬 멀티프로세싱 (Multiprocessing): 병렬성의 힘

### 2.1. 멀티프로세싱이란?

**프로세스(Process)**는 운영체제로부터 독립적인 메모리 공간을 할당받아 실행되는 프로그램의 인스턴스입니다. 멀티프로세싱은 여러 개의 독립적인 프로세스를 동시에 실행하여 작업을 처리하는 방식입니다.

각 프로세스는 자신만의 파이썬 인터프리터와 메모리 공간을 가지므로, 앞서 언급한 GIL의 제약을 받지 않습니다. 즉, CPU 코어가 여러 개라면 각 프로세스가 다른 CPU 코어에서 완전히 **병렬적**으로 실행될 수 있습니다. 마치 여러 명의 요리사(프로세스)가 각자 독립된 주방(메모리 공간)에서 동시에 다른 요리를 하는 것과 비슷합니다.

### 2.2. 멀티프로세싱의 활용: CPU 바운드 작업

멀티프로세싱은 CPU를 집중적으로 사용하는 **CPU 바운드(CPU-bound)** 작업에 매우 효과적입니다. 예를 들어, 대규모 데이터 분석, 복잡한 수학 계산, 이미지/비디오 처리와 같이 CPU 자원을 많이 소모하는 작업에 적합합니다. 각 프로세스가 독립적으로 계산을 수행하여 전체 작업 시간을 줄일 수 있습니다.

단점이라면 프로세스 생성 및 관리에 더 많은 오버헤드(비용)가 들고, 프로세스 간 데이터 공유가 멀티스레딩보다 복잡하다는 점입니다 (IPC - Inter-Process Communication).

### 2.3. 멀티프로세싱 코드 예제 (CPU 바운드 작업)

CPU를 많이 사용하는 복잡한 계산을 시뮬레이션하고, 멀티프로세싱이 어떻게 성능을 향상시키는지 확인해 봅시다.

```python
import multiprocessing
import time

def cpu_bound_task(name):
    """
    CPU 바운드 작업을 시뮬레이션하는 함수
    (복잡한 계산)
    """
    print(f"[{name}] CPU 작업 시작...")
    result = 0
    # 매우 큰 숫자를 반복하여 복잡한 계산 시뮬레이션
    for i in range(100_000_000): # 1억 번 반복
        result += i * i
    print(f"[{name}] CPU 작업 완료! 결과: {result % 100}") # 결과값 전체 출력 대신 모듈로 연산

if __name__ == "__main__": # Windows에서는 멀티프로세싱 시 이 부분이 필수입니다.
    print("--- 단일 프로세스 실행 ---")
    start_time = time.time()
    cpu_bound_task("Task 1 (Sync)")
    cpu_bound_task("Task 2 (Sync)")
    end_time = time.time()
    print(f"단일 프로세스 실행 시간: {end_time - start_time:.2f}초\n") # CPU 사양에 따라 다르지만 꽤 오래 걸림

    print("--- 멀티 프로세스 실행 ---")
    start_time = time.time()
    # Process 객체 생성
    process1 = multiprocessing.Process(target=cpu_bound_task, args=("Task 1 (Process)",))
    process2 = multiprocessing.Process(target=cpu_bound_task, args=("Task 2 (Process)",))

    # 프로세스 시작
    process1.start()
    process2.start()

    # 모든 프로세스가 종료될 때까지 기다림
    process1.join()
    process2.join()

    end_time = time.time()
    print(f"멀티 프로세스 실행 시간: {end_time - start_time:.2f}초") # 단일 프로세스 실행 시간의 약 절반
```

이 코드를 실행하면, 단일 프로세스로는 두 작업이 순차적으로 실행되어 긴 시간이 걸리지만, 멀티프로세싱을 사용하면 두 작업이 병렬로 실행되어 총 실행 시간이 절반 정도로 줄어드는 것을 확인할 수 있습니다.

## 3. 멀티스레딩 vs 멀티프로세싱: 핵심 비교

| 특징         | 멀티스레딩 (Multithreading)               | 멀티프로세싱 (Multiprocessing)                 |
| :----------- | :---------------------------------------- | :--------------------------------------------- |
| **개념**     | 프로세스 내에서 여러 스레드가 동시 실행     | 여러 독립적인 프로세스가 병렬 실행             |
| **메모리 공유** | **O** (같은 메모리 공간 공유)             | **X** (독립적인 메모리 공간 사용)              |
| **GIL 영향** | **받음** (한 번에 하나의 스레드만 Python 코드 실행) | **안 받음** (각 프로세스에 독립적인 GIL 존재) |
| **오버헤드** | 낮음 (스레드 생성 및 관리 비용)             | 높음 (프로세스 생성 및 관리 비용)              |
| **주요 사용처** | I/O 바운드 작업 (네트워크, 파일 입출력)   | CPU 바운드 작업 (복잡한 계산, 이미지 처리)     |
| **데이터 동기화** | Lock, Semaphore 등 필수 (경쟁 조건 방지) | IPC (파이프, 큐 등) 필요 (데이터 교환)         |
| **안정성**   | 한 스레드의 오류가 전체 프로세스에 영향     | 독립적이므로 한 프로세스 오류가 다른 프로세스에 미치는 영향 적음 |

## 4. 언제 무엇을 사용해야 할까?

가장 중요한 질문이죠! 상황에 따라 적절한 방법을 선택하는 것이 핵심입니다.

*   **I/O 바운드 작업 (파일 읽기/쓰기, 네트워크 통신 등): 멀티스레딩**
    *   CPU가 대기하는 시간이 긴 작업이라면, GIL이 해제되는 틈을 타 다른 스레드가 작업을 수행하여 효율을 높일 수 있습니다. 구현이 비교적 간단하고 오버헤드가 적습니다.

*   **CPU 바운드 작업 (복잡한 계산, 데이터 처리, 이미지/비디오 인코딩 등): 멀티프로세싱**
    *   CPU를 집중적으로 사용하는 작업이라면, GIL의 제약을 받지 않는 멀티프로세싱을 통해 실제 CPU 코어 수만큼 병렬로 작업을 수행하여 성능을 극대화할 수 있습니다.

*   **두 가지 모두 필요한 경우:**
    *   때로는 I/O 작업과 CPU 작업이 모두 많은 복합적인 상황이 발생할 수 있습니다. 이런 경우, `multiprocessing.pool.ThreadPool` 이나 `concurrent.futures` 모듈을 사용하여 스레드와 프로세스를 유연하게 조합하여 사용하는 것을 고려해볼 수 있습니다.

## 마무리하며

오늘은 파이썬 멀티스레딩과 멀티프로세싱에 대해 깊이 있게 알아보았습니다. 파이썬의 GIL 때문에 멀티스레딩이 오해를 받기도 하지만, I/O 바운드 작업에서는 여전히 강력한 도구입니다. 반면 CPU를 쥐어짜는 작업에는 멀티프로세싱이 정답이죠.

여러분의 프로그램이 어떤 특성을 가졌는지 파악하고, 그에 맞는 동시성/병렬성 기법을 적용한다면 훨씬 빠르고 효율적인 코드를 만들 수 있을 겁니다. 직접 예제 코드를 실행해 보면서 각 방식의 차이점을 몸으로 느껴보는 것이 가장 좋은 학습 방법입니다!
