# 파이썬 멀티스레딩 vs 멀티프로세싱: 초보자를 위한 완벽 가이드

안녕하세요, 여러분! 코드와 함께 성장하는 개발 블로그 작가입니다. 😉

혹시 파이썬으로 작성한 코드가 예상보다 느리게 실행되어서 답답함을 느껴본 적이 있으신가요? 특히 많은 양의 데이터를 처리하거나, 여러 작업을 동시에 수행해야 할 때 말이죠. 이때 우리는 프로그램의 성능을 향상시키기 위해 '동시성(Concurrency)' 또는 '병렬성(Parallelism)'이라는 개념을 활용합니다.

파이썬에서 이러한 작업을 가능하게 해주는 대표적인 두 가지 방법이 바로 **멀티스레딩(Multithreading)**과 **멀티프로세싱(Multiprocessing)**입니다. 오늘은 이 두 가지 개념이 무엇인지, 어떤 차이가 있는지, 그리고 언제 어떤 방법을 사용해야 하는지 초보자 눈높이에 맞춰 친절하게 설명해 드릴게요!

---

## 1. 멀티스레딩(Multithreading): 하나의 주방에서 여러 요리사가 함께!

### 🍽️ 개념 설명: 하나의 프로그램, 여러 개의 실행 흐름

멀티스레딩은 하나의 프로그램(프로세스) 안에서 여러 개의 '실행 흐름(Thread)'을 동시에 실행하는 방식입니다. 비유하자면, 하나의 큰 레스토랑 주방(프로그램)에서 여러 명의 요리사(스레드)가 각자 맡은 요리(작업)를 동시에 진행하는 것과 같습니다. 이 요리사들은 같은 주방을 사용하므로, 냉장고의 재료(메모리)를 공유합니다.

**장점:**
*   **경량(Lightweight):** 스레드는 프로세스보다 생성 및 관리 비용이 적습니다.
*   **메모리 공유 용이:** 같은 메모리 공간을 공유하기 때문에 스레드 간 데이터 공유가 비교적 쉽습니다.

**단점:**
*   **GIL (Global Interpreter Lock):** 파이썬의 가장 큰 특징이자 제약사항입니다. GIL 때문에 **한 번에 하나의 스레드만이 파이썬 바이트코드를 실행**할 수 있습니다. 즉, CPU를 사용하는 작업(CPU-bound)에서는 진정한 병렬 처리가 불가능합니다. 마치 여러 요리사가 있지만, 한 번에 한 명만 도마를 쓸 수 있는 것과 비슷하죠.
*   **경쟁 상태(Race Condition):** 여러 스레드가 동시에 공유하는 데이터에 접근하려 할 때 문제가 발생할 수 있습니다. (예: 두 요리사가 동시에 같은 재료를 집으려 할 때) 이를 해결하기 위해 락(Lock) 같은 동기화 메커니즘이 필요하며, 이는 코드 복잡성을 증가시킵니다.

**언제 사용할까요?**
주로 **I/O 바운드(I/O-bound) 작업**에 효과적입니다. I/O 바운드 작업은 CPU 연산보다는 파일 읽기/쓰기, 네트워크 통신(데이터 다운로드/업로드), 사용자 입력 대기 등 외부 장치의 응답을 기다리는 시간이 긴 작업을 말합니다. 스레드가 I/O 작업을 기다리는 동안 GIL이 해제되어 다른 스레드가 CPU를 사용할 수 있기 때문에 효율적입니다.

### 🧑‍💻 멀티스레딩 코드 예제 (I/O-bound)

아래 코드는 웹 페이지를 비동기적으로(동시에처럼) 가져오는 상황을 시뮬레이션합니다. `time.sleep`은 네트워크 요청을 보내고 응답을 기다리는 I/O 작업을 흉내 낸 것입니다.

```python
import time
import threading

def fetch_url(url):
    print(f"[{threading.current_thread().name}] Fetching {url}...")
    time.sleep(2) # 실제 네트워크 요청처럼 2초 대기 (I/O 작업 흉내)
    print(f"[{threading.current_thread().name}] Finished fetching {url}")
    return f"Data from {url}"

# --- 순차 실행 ---
print("--- 순차 실행 (Sequential) ---")
start_time_seq = time.time()
urls = ["url_1", "url_2", "url_3"]
for url in urls:
    fetch_url(url)
end_time_seq = time.time()
print(f"순차 실행 총 소요 시간: {end_time_seq - start_time_seq:.2f}초\n")

# --- 멀티스레딩 실행 ---
print("--- 멀티스레딩 실행 (Multithreading) ---")
start_time_thread = time.time()
threads = []
for i, url in enumerate(urls):
    # 스레드 생성: target으로 실행할 함수, args로 함수의 인자 전달
    thread = threading.Thread(target=fetch_url, args=(url,), name=f"Thread-{i+1}")
    threads.append(thread)
    thread.start() # 스레드 시작

# 모든 스레드가 종료될 때까지 기다림
for thread in threads:
    thread.join()

end_time_thread = time.time()
print(f"멀티스레딩 실행 총 소요 시간: {end_time_thread - start_time_thread:.2f}초")
```

**예상 출력 및 설명:**
순차 실행 시 각 `fetch_url` 함수가 2초씩 걸리므로 총 6초 정도가 소요됩니다. 하지만 멀티스레딩으로 실행하면, 각 스레드가 `time.sleep(2)` 동안 대기하는 동안 GIL이 해제되어 다른 스레드가 실행을 시작할 수 있습니다. 따라서 약 2초 정도만에 모든 작업이 완료되는 것을 볼 수 있습니다. (물론 스레드 생성 및 관리 오버헤드가 약간 있습니다.)

## 2. 멀티프로세싱(Multiprocessing): 여러 개의 독립적인 레스토랑!

### 🍳 개념 설명: 여러 개의 독립적인 프로그램

멀티프로세싱은 운영체제로부터 완전히 독립적인 메모리 공간을 할당받는 여러 개의 '프로세스'를 동시에 실행하는 방식입니다. 다시 레스토랑 비유를 들자면, 여러 개의 독립적인 레스토랑(프로세스)이 각자 고유한 주방(메모리)과 요리사(실행 흐름)를 가지고 각자의 요리(작업)를 하는 것과 같습니다. 서로 간섭하지 않으며, 각자의 공간에서 자유롭게 일합니다.

**장점:**
*   **진정한 병렬 처리:** 각 프로세스는 독립적인 파이썬 인터프리터와 GIL을 가지고 있기 때문에, 여러 개의 CPU 코어에서 **동시에** 파이썬 코드를 실행할 수 있습니다. GIL의 제약을 받지 않습니다!
*   **안정성:** 한 프로세스에서 오류가 발생해도 다른 프로세스에 영향을 주지 않아 프로그램 전체의 안정성이 높습니다.
*   **자원 격리:** 각 프로세스가 독립적인 메모리 공간을 가지므로 데이터 충돌(경쟁 상태) 문제가 기본적으로 발생하지 않습니다.

**단점:**
*   **높은 오버헤드:** 프로세스 생성 및 전환 비용이 스레드보다 훨씬 높습니다. 운영체제로부터 독립적인 메모리 공간을 할당받아야 하기 때문입니다.
*   **데이터 공유 복잡성:** 각 프로세스가 독립적인 메모리를 사용하므로, 데이터를 공유하려면 큐(Queue), 파이프(Pipe), 매니저(Manager) 등 특별한 IPC(Inter-Process Communication) 메커니즘을 사용해야 합니다.

**언제 사용할까요?**
주로 **CPU 바운드(CPU-bound) 작업**에 효과적입니다. CPU 바운드 작업은 복잡한 계산, 이미지/비디오 처리, 데이터 분석 등 CPU를 집중적으로 사용하는 작업을 말합니다. GIL의 영향을 받지 않고 여러 CPU 코어를 최대한 활용할 수 있기 때문에 병렬 처리의 이점을 톡톡히 누릴 수 있습니다.

### 🧑‍💻 멀티프로세싱 코드 예제 (CPU-bound)

아래 코드는 숫자의 제곱근을 계산하는 CPU 집약적인 작업을 시뮬레이션합니다.

```python
import time
import multiprocessing
import math

def calculate_squares(numbers):
    print(f"[{multiprocessing.current_process().name}] Calculating squares...")
    result = []
    for num in numbers:
        # 매우 복잡한 계산을 가정 (CPU 사용)
        [math.sqrt(i) for i in range(1_000_000)] # 100만 번 제곱근 계산 반복
        result.append(num * num)
    print(f"[{multiprocessing.current_process().name}] Finished calculations.")
    return result

# --- 순차 실행 ---
print("--- 순차 실행 (Sequential) ---")
start_time_seq = time.time()
numbers_to_process = [1, 2, 3, 4] # 간단하게 4개의 작업
calculate_squares(numbers_to_process)
end_time_seq = time.time()
print(f"순차 실행 총 소요 시간: {end_time_seq - start_time_seq:.2f}초\n")

# --- 멀티프로세싱 실행 ---
print("--- 멀티프로세싱 실행 (Multiprocessing) ---")
start_time_process = time.time()
processes = []
# 작업을 2개씩 나누어 각 프로세스에 할당
chunk_size = len(numbers_to_process) // 2
chunks = [numbers_to_process[i:i + chunk_size] for i in range(0, len(numbers_to_process), chunk_size)]

for i, chunk in enumerate(chunks):
    # 프로세스 생성: target으로 실행할 함수, args로 함수의 인자 전달
    process = multiprocessing.Process(target=calculate_squares, args=(chunk,), name=f"Process-{i+1}")
    processes.append(process)
    process.start() # 프로세스 시작

# 모든 프로세스가 종료될 때까지 기다림
for process in processes:
    process.join()

end_time_process = time.time()
print(f"멀티프로세싱 실행 총 소요 시간: {end_time_process - start_time_process:.2f}초")
```

**예상 출력 및 설명:**
`calculate_squares` 함수는 100만 번의 제곱근 계산을 포함하고 있어 CPU를 많이 사용합니다. 순차 실행 시에는 모든 숫자에 대한 계산을 한 번에 처리하므로 상당한 시간이 걸립니다. 하지만 멀티프로세싱으로 실행하면, 여러 개의 프로세스가 동시에 각자의 `calculate_squares` 함수를 실행하여 CPU 코어를 병렬적으로 사용합니다. 따라서 전체 실행 시간이 크게 단축되는 것을 볼 수 있습니다. (예시에서는 작업을 2개로 나누었으므로 대략 절반의 시간으로 줄어들 것입니다.)

## 3. 멀티스레딩 vs 멀티프로세싱: 언제 무엇을 사용할까?

정리하자면, 두 방법 모두 여러 작업을 동시에 처리하는 것처럼 보이게 하지만, 내부 동작 방식과 사용 사례가 명확히 다릅니다.

| 특징           | 멀티스레딩(Multithreading)           | 멀티프로세싱(Multiprocessing)          |
| :------------- | :----------------------------------- | :----------------------------------- |
| **개념**       | 하나의 프로세스 내 여러 실행 흐름    | 여러 개의 독립적인 프로세스          |
| **메모리**     | 공유                                 | 독립적                               |
| **GIL 영향**   | 받음 (CPU 바운드 작업 병렬 처리 불가)| 받지 않음 (각 프로세스 독립적인 GIL) |
| **진정한 병렬**| X (동시성)                           | O (병렬성)                           |
| **오버헤드**   | 낮음 (경량)                          | 높음 (무겁고 느림)                   |
| **데이터 공유**| 용이하나 경쟁 상태 문제 발생 가능    | 복잡 (IPC 메커니즘 필요)             |
| **안정성**     | 한 스레드 오류가 전체 프로세스 영향  | 한 프로세스 오류가 다른 프로세스에 영향 없음 |
| **주요 활용**  | **I/O 바운드 작업** (네트워크, 파일 입출력 등) | **CPU 바운드 작업** (복잡한 계산, 데이터 처리 등) |

**결론적으로:**

*   **외부와의 통신(네트워크 요청, 파일 읽기/쓰기 등)으로 인해 대기 시간이 긴 작업이라면 → 멀티스레딩**
*   **순수하게 CPU를 많이 사용하는 복잡한 계산 작업이라면 → 멀티프로세싱**
