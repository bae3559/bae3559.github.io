# [자료구조/알고리즘] 최소 신장 트리(MST) 파헤치기: 크루스칼과 프림 알고리즘 A to Z

안녕하세요, 개발 블로그 독자 여러분! 🚀 오늘은 네트워크 설계, 교통망 최적화, 통신 시스템 구축 등 우리 주변의 다양한 문제 해결에 핵심적인 역할을 하는 매우 중요한 알고리즘, 바로 **최소 신장 트리(Minimum Spanning Tree, MST)**에 대해 이야기해보려 합니다. 특히, MST를 찾는 대표적인 두 가지 방법인 **크루스칼(Kruskal) 알고리즘**과 **프림(Prim) 알고리즘**을 초보자도 이해하기 쉽게 친절하게 설명해 드릴게요. 개념부터 실제 파이썬 코드 예제까지 함께 살펴보겠습니다!

## 💡 최소 신장 트리(MST)는 왜 필요할까요?

여러분은 혹시 이런 고민을 해보신 적이 있나요?

*   여러 도시에 전기를 공급하기 위해 발전소에서 각 도시를 연결해야 하는데, 전선 설치 비용을 **최소화**하고 싶어요.
*   회사 네트워크를 구축해야 하는데, 모든 컴퓨터가 서로 통신할 수 있으면서도 케이블 설치 비용을 **가장 적게** 들이고 싶어요.
*   긴급 구호 물품을 여러 재난 지역에 전달해야 하는데, 모든 지역에 접근 가능하면서도 이동 거리를 **최소화**하고 싶어요.

이러러한 문제들은 모두 "모든 정점(node)을 연결하면서, 간선(edge)들의 가중치(weight) 합을 최소로 하는 트리"를 찾는 것으로 해결할 수 있습니다. 이것이 바로 **최소 신장 트리(MST)**입니다!

---

## 🗺️ 최소 신장 트리(MST)의 기본 개념

본격적으로 알고리즘을 살펴보기 전에, 몇 가지 핵심 용어를 정리하고 갈게요.

*   **그래프(Graph):** 정점(Vertex, 노드)과 이들을 잇는 간선(Edge)으로 구성된 자료구조입니다.
*   **가중치(Weight):** 간선에 부여된 값으로, 거리, 비용, 시간 등을 나타냅니다. MST 문제에서는 이 가중치의 합을 최소화하는 것이 목표입니다.
*   **트리(Tree):** 사이클(Cycle, 순환)이 없는 그래프의 일종입니다.
*   **신장 트리(Spanning Tree):** 그래프의 모든 정점을 포함하면서 사이클이 없는 트리입니다. 간선의 개수는 항상 `정점의 개수 - 1` 입니다.
*   **최소 신장 트리(Minimum Spanning Tree, MST):** 그래프의 모든 정점을 연결하는 신장 트리 중에서, 간선들의 가중치 합이 가장 작은 트리입니다.

쉽게 말해, MST는 **"주어진 모든 지점을 가장 저렴한 비용으로, 끊기지 않게, 그리고 빙빙 돌지 않게 연결하는 방법"**이라고 생각하시면 됩니다.

이제 이 MST를 찾는 두 가지 대표적인 알고리즘인 크루스칼 알고리즘과 프림 알고리즘을 알아보겠습니다. 두 알고리즘 모두 **탐욕적인(Greedy) 방식**을 사용합니다. 즉, 각 단계에서 가장 최적이라고 판단되는 선택을 해서 최종적으로 전체 최적 해를 찾아내는 방식이죠.

## 1. 크루스칼(Kruskal) 알고리즘

크루스칼 알고리즘은 **"가장 저렴한 간선부터 차례대로 선택하되, 사이클을 만들지 않는 선에서 트리를 확장해나가는 방식"**입니다.

### 📝 크루스칼 알고리즘의 동작 방식

1.  **모든 간선을 가중치에 따라 오름차순으로 정렬합니다.** (가장 저렴한 간선부터!)
2.  **그래프의 각 정점을 독립적인 집합으로 초기화합니다.** (서로소 집합(Disjoint Set Union, DSU) 자료구조 사용)
3.  **정렬된 간선을 하나씩 확인하면서 다음을 수행합니다.**
    *   선택된 간선의 양 끝 정점이 **서로 다른 집합**에 속해 있다면, 이 간선을 MST에 추가합니다. 그리고 두 정점이 속한 집합을 **하나로 합칩니다.** (즉, 사이클이 생기지 않는다는 의미!)
    *   만약 두 정점이 **이미 같은 집합**에 속해 있다면, 이 간선을 추가하면 사이클이 생기므로 버립니다.
4.  MST에 `정점의 개수 - 1`개의 간선이 추가될 때까지 3번 과정을 반복합니다.

### 🧩 서로소 집합(Disjoint Set Union, DSU)이란?

크루스칼 알고리즘에서 가장 중요한 보조 자료구조는 바로 **서로소 집합(Disjoint Set Union, DSU)**입니다. DSU는 여러 개의 원소들을 서로소(disjoint)인 집합들로 나누어 관리하는 자료구조입니다. `find` 연산으로 어떤 원소가 속한 집합의 대표 원소를 찾고, `union` 연산으로 두 집합을 합치는 기능을 제공합니다. 이를 통해 두 정점이 이미 같은 집합에 속해 있는지(즉, 연결되어 있는지) 효율적으로 판단하여 사이클 형성을 방지할 수 있습니다.

### 🐍 파이썬으로 구현하는 크루스칼 알고리즘

다음 그래프를 예시로 들어보겠습니다.

```
정점: 0, 1, 2, 3, 4, 5, 6
간선: (0,1,9), (0,2,10), (1,3,10), (1,4,5), (2,3,9), (2,5,7), (3,4,8), (3,5,4), (4,6,3), (5,6,12)
(u, v, weight)
```

```python
import heapq

# --- 서로소 집합 (Disjoint Set Union, DSU) 구현 ---
# find: 특정 원소가 속한 집합의 대표 원소를 찾습니다. (경로 압축 최적화)
def find_parent(parent, i):
    if parent[i] == i:
        return i
    parent[i] = find_parent(parent, parent[i])
    return parent[i]

# union: 두 원소가 속한 집합을 합칩니다. (랭크 또는 크기 기반 합치기 최적화)
def union_parents(parent, a, b):
    a = find_parent(parent, a)
    b = find_parent(parent, b)
    if a < b: # 더 작은 번호의 부모로 합치는 규칙 (또는 랭크, 크기 등)
        parent[b] = a
    else:
        parent[a] = b

# --- 크루스칼 알고리즘 ---
def kruskal_mst(vertices, edges):
    mst_edges = []
    total_weight = 0
    parent = [i for i in range(vertices)] # 각 정점이 자기 자신을 부모로 초기화

    # 1. 모든 간선을 가중치에 따라 오름차순으로 정렬
    edges.sort(key=lambda x: x[2]) # (u, v, weight) -> weight 기준으로 정렬

    # 2. 정렬된 간선을 하나씩 확인
    for u, v, weight in edges:
        # 3. 사이클이 생기지 않는다면 (두 정점이 서로 다른 집합에 속해 있다면)
        if find_parent(parent, u) != find_parent(parent, v):
            union_parents(parent, u, v) # 두 집합을 합침
            mst_edges.append((u, v, weight))
            total_weight += weight
            
            # MST에 (정점 개수 - 1)개의 간선이 추가되면 종료
            if len(mst_edges) == vertices - 1:
                break

    return total_weight, mst_edges

# --- 예제 그래프 ---
V = 7 # 정점의 개수 (0부터 6까지)
# 간선 정보: (정점1, 정점2, 가중치)
edge_list = [
    (0, 1, 9), (0, 2, 10),
    (1, 3, 10), (1, 4, 5),
    (2, 3, 9), (2, 5, 7),
    (3, 4, 8), (3, 5, 4),
    (4, 6, 3),
    (5, 6, 12)
]

min_total_weight, mst_result = kruskal_mst(V, edge_list)

print(f"--- 크루스칼 알고리즘 결과 ---")
print(f"최소 신장 트리의 총 가중치: {min_total_weight}")
print(f"최소 신장 트리를 구성하는 간선: {mst_result}")
# 예상 출력:
# 최소 신장 트리의 총 가중치: 38
# 최소 신장 트리를 구성하는 간선: [(4, 6, 3), (3, 5, 4), (1, 4, 5), (2, 5, 7), (3, 4, 8), (0, 1, 9)]
```

크루스칼 알고리즘은 간선 중심(Edge-centric)으로 동작하며, 희소 그래프(sparse graph, 간선이 적은 그래프)에서 효율적입니다.

## 2. 프림(Prim) 알고리즘

프림 알고리즘은 **"하나의 정점에서 시작하여 점차 트리를 확장해나가는 방식"**입니다. 이미 MST에 포함된 정점과 MST에 포함되지 않은 정점 사이에 있는 간선들 중에서 가장 저렴한 간선을 선택하여 MST를 키워 나갑니다.

### 📝 프림 알고리즘의 동작 방식

1.  **임의의 시작 정점(Start Vertex)을 하나 선택하여 MST에 포함시킵니다.** (어떤 정점에서 시작해도 결과는 동일합니다.)
2.  MST에 포함된 정점과 MST에 포함되지 않은 정점들을 연결하는 모든 간선 중에서, **가장 가중치가 작은 간선**을 찾습니다.
3.  찾은 간선을 MST에 추가하고, 그 간선의 다른 쪽 끝 정점도 MST에 포함시킵니다. (이때, Priority Queue(우선순위 큐)를 사용하여 가장 가중치가 작은 간선을 효율적으로 찾습니다.)
4.  MST에 `정점의 개수 - 1`개의 간선이 추가될 때까지 2번, 3번 과정을 반복합니다.

### 🧩 프림 알고리즘과 우선순위 큐

프림 알고리즘은 '가장 저렴한 간선'을 계속해서 찾아야 하므로, **우선순위 큐(Priority Queue)**를 사용하면 매우 효율적입니다. 우선순위 큐는 데이터가 삽입될 때마다 우선순위(여기서는 간선의 가중치)에 따라 정렬되며, 가장 우선순위가 높은(가중치가 가장 낮은) 데이터를 가장 먼저 추출할 수 있습니다.

### 🐍 파이썬으로 구현하는 프림 알고리즘

위에서 사용한 동일한 그래프를 예시로 들어보겠습니다.

```python
import heapq

# --- 프림 알고리즘 ---
def prim_mst(vertices, graph):
    mst_weight = 0
    mst_edges = []
    
    # MST에 포함되었는지 여부를 저장하는 배열
    # 초기에는 모두 False (포함되지 않음)
    visited = [False] * vertices
    
    # 우선순위 큐 (min_heap): (가중치, 현재 정점, 다음 정점) 형태
    # 초기에는 시작 정점(0)에서 시작하며, 가중치는 0
    # (가중치, 도착 정점, 출발 정점) 형태로 저장하여 나중에 간선 구성을 쉽게 함
    min_heap = [(0, 0, -1)] # (weight, to_vertex, from_vertex)
    
    while min_heap:
        weight, u, from_v = heapq.heappop(min_heap)
        
        # 이미 방문한 정점이라면 스킵 (사이클 방지 및 중복 처리 방지)
        if visited[u]:
            continue
            
        visited[u] = True # 현재 정점을 MST에 포함시킴
        mst_weight += weight
        if from_v != -1: # 시작 정점 제외
            mst_edges.append((from_v, u, weight))
            
        # 현재 정점 u와 연결된 모든 간선 확인
        for v, w in graph[u]:
            if not visited[v]: # 아직 MST에 포함되지 않은 정점이라면
                heapq.heappush(min_heap, (w, v, u)) # 우선순위 큐에 추가
                
        # 모든 정점이 MST에 포함되었는지 확인 (간선 개수 또는 방문 여부로 판단)
        if len(mst_edges) == vertices - 1:
            break

    return mst_weight, mst_edges

# --- 예제 그래프 ---
V = 7 # 정점의 개수 (0부터 6까지)
# 인접 리스트 형태로 그래프 표현: graph[u] = [(v, weight), ...]
graph_adj_list = [[] for _ in range(V)]

# 간선 추가 (양방향 그래프)
def add_edge(graph, u, v, weight):
    graph[u].append((v, weight))
    graph[v].append((u, weight))

add_edge(graph_adj_list, 0, 1, 9)
add_edge(graph_adj_list, 0, 2, 10)
add_edge(graph_adj_list, 1, 3, 10)
add_edge(graph_adj_list, 1, 4, 5)
add_edge(graph_adj_list, 2, 3, 9)
add_edge(graph_adj_list, 2, 5, 7)
add_edge(graph_adj_list, 3, 4, 8)
add_edge(graph_adj_list, 3, 5, 4)
add_edge(graph_adj_list, 4, 6, 3)
add_edge(graph_adj_list, 5, 6, 12)

min_total_weight_prim, mst_result_prim = prim_mst(V, graph_adj_list)

print(f"\n--- 프림 알고리즘 결과 ---")
print(f"최소 신장 트리의 총 가중치: {min_total_weight_prim}")
print(f"최소 신장 트리를 구성하는 간선: {mst_result_prim}")
# 예상 출력 (간선의 순서는 다를 수 있음):
# 최소 신장 트리의 총 가중치: 38
# 최소 신장 트리를 구성하는 간선: [(4, 6, 3), (3, 5, 4), (1, 4, 5), (2, 5, 7), (3, 4, 8), (0, 1, 9)]
```

프림 알고리즘은 정점 중심(Vertex-centric)으로 동작하며, 밀집 그래프(dense graph, 간선이 많은 그래프)에서 효율적입니다.

## 크루스칼 vs. 프림: 언제 무엇을 쓸까?

두 알고리즘 모두 MST를 찾는 데 사용되지만, 어떤 상황에서 더 유리할까요?

| 특징           | 크루스칼(Kruskal) 알고리즘                               | 프림(Prim) 알고리즘                                       |
| :------------- | :------------------------------------------------------- | :-------------------------------------------------------- |
| **핵심 아이디어** | 가장 가중치가 작은 간선부터 선택 (사이클 생성 방지)      | 임의의 정점에서 시작하여 트리를 점차 확장 (가장 가까운 노드 선택) |
| **자료구조**   | 서로소 집합(Disjoint Set Union, DSU)                     | 우선순위 큐(Priority Queue)                               |
| **그래프 표현** | 간선 리스트가 편리                                       | 인접 리스트가 편리                                        |
| **주요 사용처** | 간선의 수가 적은 **희소 그래프(Sparse Graph)**에 유리  | 간선의 수가 많은 **밀집 그래프(Dense Graph)**에 유리    |
| **시간 복잡도** | O(E log E) 또는 O(E log V) (간선 정렬 + DSU)              | O(E log V) 또는 O(V^2) (우선순위 큐 사용 여부에 따라)     |
| **직관성**     | "가장 싼 길부터 연결" 이라는 아이디어가 비교적 직관적   | "가장 가까운 곳으로 확장" 이라는 아이디어가 비교적 직관적 |

*   **희소 그래프 (Sparse Graph):** 간선(E)의 수가 정점(V)의 수에 비해 많지 않은 그래프 (E ≈ V)
*   **밀집 그래프 (Dense Graph):** 간선(E)의 수가 정점(V)의 수에 비해 매우 많은 그래프 (E ≈ V^2)

간단히 말해, 복잡한 네트워크에서 연결해야 할 지점은 많지만, 연결 가능한 경로의 수가 제한적이라면 **크루스칼**이, 모든 지점이 거의 모든 다른 지점과 연결될 수 있는 상황(즉, 가능한 간선이 매우 많은 상황)이라면 **프림**이 더 유리하다고 생각하시면 됩니다.
