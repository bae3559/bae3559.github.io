## 🤯 위상 정렬, 왜 필요할까요?

새로운 프로젝트를 시작하거나, 어떤 복잡한 시스템을 구축할 때 "이 작업은 저 작업이 끝나야 시작할 수 있는데...", "이 모듈은 저 모듈이 먼저 빌드되어야 해!" 같은 의존성 문제에 부딪힐 때가 많습니다. 어떤 순서로 작업을 진행해야 효율적이고 오류 없이 완료할 수 있을까요?

바로 이럴 때 '위상 정렬'이 빛을 발합니다! 위상 정렬은 이러한 **선행 조건(prerequisite)**이 있는 작업들을 순서대로 나열해 주는 알고리즘입니다.

예를 들어,
*   대학교 수강 과목: '자료구조'를 들으려면 '프로그래밍 기초'를 먼저 수강해야 합니다.
*   소프트웨어 빌드: 'A 라이브러리'는 'B 라이브러리'를 사용하므로, B가 먼저 컴파일되어야 합니다.
*   음식 조리 과정: 밥을 지으려면 쌀을 씻고 물을 넣은 다음 취사 버튼을 눌러야 하죠. (어떤 과정이 먼저 와야 할까요?)

이 모든 것이 위상 정렬의 적용 예시입니다. 복잡한 의존 관계 속에서 올바른 순서를 찾아주는 것이죠.

## 🧐 위상 정렬의 핵심 개념: DAG (방향 비순환 그래프)

위상 정렬을 이해하려면 먼저 **방향 비순환 그래프(DAG: Directed Acyclic Graph)**라는 개념을 알아야 합니다.

*   **방향(Directed):** 정점(노드) 간의 연결(간선)에 방향이 있다는 뜻입니다. 예를 들어, A → B는 "A 다음에 B"라는 순서가 있다는 의미입니다. A가 B보다 선행되어야 합니다.
*   **비순환(Acyclic):** 그래프 안에 '사이클(Cycle)'이 없다는 뜻입니다. 사이클이란 A → B → C → A 와 같이 시작점으로 다시 돌아오는 경로를 말합니다. 만약 사이클이 있다면, 예를 들어 '자료구조'를 들으려면 '프로그래밍 기초'를 들어야 하고, '프로그래밍 기초'를 들으려면 '자료구조'를 들어야 하는 무한 루프에 빠지게 되겠죠? 이런 경우에는 올바른 순서를 정할 수 없습니다.

결론적으로, **위상 정렬은 방향 비순환 그래프(DAG)에서만 적용될 수 있으며, 모든 정점을 방향에 거스르지 않도록 '선형'으로 나열하는 것을 의미합니다.**

## 💡 위상 정렬 알고리즘: 칸(Kahn) 알고리즘

위상 정렬을 구현하는 방법은 크게 두 가지가 있습니다:
1.  **칸(Kahn) 알고리즘:** 진입 차수(In-degree)를 이용하는 방식
2.  **DFS(깊이 우선 탐색) 기반 알고리즘:** 재귀 호출과 스택을 이용하는 방식

여기서는 직관적이고 이해하기 쉬운 **칸(Kahn) 알고리즘**을 살펴보겠습니다.

**'진입 차수(In-degree)'**란 특정 정점으로 **들어오는 간선(edge)의 개수**를 의미합니다. 예를 들어, A → B와 C → B 두 개의 간선이 있다면, B의 진입 차수는 2가 됩니다.

칸 알고리즘의 단계는 다음과 같습니다.

1.  **모든 정점의 진입 차수 계산하기:** 각 정점으로 들어오는 간선이 몇 개인지 세어둡니다.
2.  **진입 차수가 0인 정점들을 큐(Queue)에 추가하기:** 진입 차수가 0이라는 것은 이 정점에 선행되는 작업이 없다는 뜻이므로, 가장 먼저 시작할 수 있는 작업들입니다.
3.  **큐가 빌 때까지 반복:**
    a.  큐에서 정점 `u`를 하나 꺼냅니다. `u`는 현재 순서에서 가장 먼저 처리될 수 있는 정점입니다.
    b.  꺼낸 정점 `u`를 결과 목록에 추가합니다.
    c.  `u`에서 나가는 모든 간선에 연결된 이웃 정점 `v`의 **진입 차수를 1 감소시킵니다.** `u`가 처리되었으니, `u`를 선행 조건으로 가졌던 `v`는 이제 `u`라는 선행 조건 하나를 충족한 셈입니다.
    d.  만약 이웃 정점 `v`의 진입 차수가 0이 되면, `v`도 이제 선행 조건이 모두 충족되었으므로 큐에 추가합니다.
4.  **사이클 검사:** 만약 최종 결과 목록에 담긴 정점의 개수가 전체 그래프의 정점 개수보다 적다면, 그래프에 사이클이 존재하여 위상 정렬이 불가능하다는 의미입니다. (사이클이 있으면 진입 차수가 0이 되는 노드가 더 이상 생기지 않아 큐가 비어버립니다.)

## 💻 파이썬으로 위상 정렬 구현하기

이제 칸 알고리즘을 파이썬 코드로 구현해 보겠습니다.

```python
from collections import defaultdict, deque

def topological_sort(graph):
    # 1. 모든 정점의 진입 차수(in-degree) 계산 및 모든 정점 추출
    in_degree = defaultdict(int)
    all_nodes = set() # 그래프에 존재하는 모든 정점을 저장
    
    for u in graph:
        all_nodes.add(u) # 현재 정점(u) 추가
        for v in graph[u]:
            in_degree[v] += 1 # v의 진입 차수 증가
            all_nodes.add(v) # 이웃 정점(v) 추가

    # 주의: 간선이 없는 고립된 정점도 all_nodes에 포함되어야 함
    # 위 반복문에서 u, v로 모두 걸러지지만, 그래프 정의 방식에 따라
    # 명시적으로 graph.keys() 등을 순회하여 all_nodes를 초기화할 수도 있음.
    # 여기서는 defaultdict를 사용했으므로 위 방식으로 충분.

    # 2. 진입 차수가 0인 정점들을 큐에 추가
    queue = deque()
    for node in all_nodes:
        if in_degree[node] == 0:
            queue.append(node)

    result = [] # 위상 정렬 결과를 저장할 리스트
    
    # 3. 큐가 빌 때까지 반복
    while queue:
        u = queue.popleft() # 큐에서 정점 하나를 꺼냄
        result.append(u)    # 결과 목록에 추가
        
        # u에서 나가는 모든 간선에 연결된 이웃 정점 v의 진입 차수 감소
        for v in graph[u]:
            in_degree[v] -= 1
            # 진입 차수가 0이 되면 큐에 추가
            if in_degree[v] == 0:
                queue.append(v)
    
    # 4. 결과의 정점 개수가 전체 정점 개수와 다르면 사이클 존재
    if len(result) != len(all_nodes):
        print("그래프에 사이클이 존재하여 위상 정렬이 불가능합니다!")
        return [] # 위상 정렬이 불가능하므로 빈 리스트 반환
    
    return result

# --- 예제 그래프 ---

# 예제 1: 일반적인 DAG
# A -> B
# A -> C
# B -> D
# C -> D
# D -> E
example_graph1 = {
    'A': ['B', 'C'],
    'B': ['D'],
    'C': ['D'],
    'D': ['E'],
    'E': [], # E는 더 이상 나가는 간선이 없으므로 빈 리스트
    'F': [], # 고립된 노드 (graph 딕셔너리에 키로 존재하면 처리됨)
}

# 예제 2: 고립된 노드가 명시적으로 포함된 경우
example_graph2 = {
    'X': ['Y'],
    'Y': ['Z'],
    'P': [], # P는 누구와도 연결되어 있지 않은 고립된 노드
    'Q': [], # Q도 고립된 노드
}

# 예제 3: 사이클이 있는 그래프 (위상 정렬 불가능)
cyclic_graph = {
    'M': ['N'],
    'N': ['O'],
    'O': ['M'] # O에서 M으로 돌아가는 사이클
}

print("--- 예제 1 위상 정렬 ---")
print("그래프:", example_graph1)
print("결과:", topological_sort(example_graph1))
# 예상 출력 (순서는 다를 수 있음): ['A', 'F', 'B', 'C', 'D', 'E'] 또는 ['A', 'F', 'C', 'B', 'D', 'E']

print("\n--- 예제 2 위상 정렬 (고립 노드 포함) ---")
print("그래프:", example_graph2)
print("결과:", topological_sort(example_graph2))
# 예상 출력 (P, Q, X, Y, Z의 순서는 다를 수 있음): ['P', 'Q', 'X', 'Y', 'Z']

print("\n--- 예제 3 위상 정렬 (사이클) ---")
print("그래프:", cyclic_graph)
print("결과:", topological_sort(cyclic_graph))
# 예상 출력: "그래프에 사이클이 존재하여 위상 정렬이 불가능합니다!" 메시지 후 []
```

### 코드 해설
1.  **`defaultdict(int)`:** `in_degree` 딕셔너리를 초기화합니다. 아직 진입 차수가 계산되지 않은 정점은 자동으로 0으로 처리됩니다.
2.  **`all_nodes`:** `set()`을 사용하여 그래프에 존재하는 모든 고유한 정점들을 저장합니다. 이는 `in_degree`를 계산할 때 고려되지 않을 수 있는, 간선이 없는 정점(고립 노드)이나 오직 들어오는 간선만 있는 정점들도 위상 정렬 결과에 포함시키고, 나중에 사이클 여부를 정확히 판단하기 위해 사용됩니다.
3.  **`deque`:** `collections` 모듈의 `deque`는 양쪽 끝에서 빠르게 요소를 추가하거나 제거할 수 있어 큐로 사용하기에 매우 효율적입니다.
4.  **`while queue:` 루프:** 큐가 빌 때까지 반복하여 위상 정렬 순서를 만듭니다.
5.  **사이클 검사:** `len(result) != len(all_nodes)` 조건으로 사이클 여부를 확인합니다. 사이클이 있으면 모든 정점이 큐에 들어갈 기회를 얻지 못하고 큐가 비어버리므로, 결과 목록의 길이가 전체 정점 수보다 짧게 됩니다.
