# 파이썬 멀티스레딩 vs 멀티프로세싱: 언제 무엇을 써야 할까? (초보자 가이드)

안녕하세요, 개발 블로그 독자 여러분! 🚀

느릿느릿한 코드 때문에 답답했던 경험 있으신가요? 특히 대량의 데이터를 처리하거나 여러 작업을 동시에 수행해야 할 때, 프로그램이 한참을 멈춰있으면 효율성이 떨어지죠. 이때 우리는 '병렬 처리' 또는 '동시성'이라는 개념에 눈을 돌리게 됩니다. 파이썬에서는 이러한 문제를 해결하기 위해 크게 **멀티스레딩(Multithreading)**과 **멀티프로세싱(Multiprocessing)**이라는 두 가지 방법을 제공합니다.

오늘은 이 두 가지 개념이 무엇인지, 어떤 차이가 있는지, 그리고 언제 어떤 방법을 사용해야 효율적인지 초보자분들도 쉽게 이해할 수 있도록 친절하게 설명해 드릴게요. 코드 예제와 함께 자세히 살펴보겠습니다!

---

## 1. 멀티스레딩 (Multithreading): 하나의 몸에 여러 팔

### 1.1. 멀티스레딩이란?
멀티스레딩은 하나의 **프로세스(Process)** 안에서 여러 개의 **스레드(Thread)**를 동시에 실행하는 방식입니다. 프로세스는 운영체제로부터 독립적인 메모리 공간을 할당받아 실행되는 프로그램의 단위이고, 스레드는 이 프로세스 안에서 실행되는 '작업 흐름'의 단위라고 생각하시면 됩니다.

비유하자면, 한 사람(프로세스)이 여러 개의 팔(스레드)을 가지고 동시에 여러 작업을 수행하는 것과 비슷해요. 팔들이 같은 몸을 공유하기 때문에 같은 기억(메모리)에 접근할 수 있습니다.

### 1.2. 파이썬과 GIL (Global Interpreter Lock)
여기서 중요한 파이썬만의 특징이 등장합니다: 바로 **GIL(Global Interpreter Lock)**입니다. 파이썬 인터프리터는 한 번에 하나의 스레드만 파이썬 바이트코드를 실행할 수 있도록 GIL을 사용합니다. 이는 파이썬의 메모리 관리를 단순화하고 안정성을 높이는 장점이 있지만, 동시에 **CPU-bound(연산 중심) 작업에서는 진정한 병렬 처리가 불가능하다는 단점**을 가져옵니다.

즉, 아무리 CPU 코어가 많아도 파이썬 멀티스레딩은 CPU 연산을 한 번에 한 스레드만 처리할 수 있습니다. 마치 여러 요리사가 같은 주방에서 요리하는데, 가장 중요한 도구(예: 칼)는 한 번에 한 명만 쓸 수 있도록 잠겨있는 것과 같아요. 다른 요리사들은 칼이 비어있을 때까지 기다려야 합니다.

하지만! GIL은 **I/O-bound(입출력 중심) 작업**에서는 스레드가 I/O 작업을 기다리는 동안(예: 네트워크 응답, 파일 읽기) 다른 스레드가 CPU를 사용할 수 있도록 잠시 GIL을 놓아줍니다. 따라서 멀티스레딩은 네트워크 통신이나 파일 입출력처럼 CPU 연산보다는 "기다림"이 많은 작업에 아주 효과적입니다.

### 1.3. 코드 예제: I/O 바운드 작업에 멀티스레딩 적용하기

아래 예제는 `time.sleep()`을 사용하여 네트워크 요청이나 파일 읽기처럼 대기 시간이 필요한 I/O 바운드 작업을 시뮬레이션합니다. 3개의 스레드가 각각 2초씩 대기하지만, 총 실행 시간은 2초에 가깝게 나옵니다.

```python
import threading
import time

def io_bound_task(name):
    """I/O 바운드 작업을 시뮬레이션하는 함수"""
    print(f"스레드 {name}: 작업 시작 (I/O 대기 중...)")
    time.sleep(2) # 2초 동안 대기 (네트워크 요청, 파일 읽기 등)
    print(f"스레드 {name}: 작업 완료")

if __name__ == "__main__":
    start_time = time.time()
    threads = []

    # 3개의 스레드 생성 및 시작
    for i in range(3):
        thread = threading.Thread(target=io_bound_task, args=(f"#{i+1}",))
        threads.append(thread)
        thread.start()

    # 모든 스레드가 종료될 때까지 기다림
    for thread in threads:
        thread.join()

    end_time = time.time()
    print(f"\n총 실행 시간: {end_time - start_time:.2f}초")
```

**실행 결과:**
```
스레드 #1: 작업 시작 (I/O 대기 중...)
스레드 #2: 작업 시작 (I/O 대기 중...)
스레드 #3: 작업 시작 (I/O 대기 중...)
스레드 #1: 작업 완료
스레드 #2: 작업 완료
스레드 #3: 작업 완료

총 실행 시간: 2.01초
```
보시면 3개의 스레드가 동시에 작업을 시작하고, 각 2초씩 기다리는 작업임에도 불구하고 총 실행 시간은 약 2초에 불과합니다. 이는 한 스레드가 I/O 대기 상태일 때 GIL이 해제되어 다른 스레드가 실행될 수 있었기 때문입니다.

### 1.4. 멀티스레딩의 장단점
*   **장점:**
    *   스레드 생성 및 전환 비용이 프로세스보다 훨씬 가볍습니다.
    *   같은 프로세스 내에서 메모리(변수, 데이터 등)를 공유하기 쉽습니다.
*   **단점:**
    *   파이썬 GIL 때문에 CPU 바운드 작업에서는 진정한 병렬 처리가 불가능합니다.
    *   여러 스레드가 공유 메모리에 동시에 접근할 때 동기화 문제(Race Condition)가 발생할 수 있어 Lock, Semaphore 등 복잡한 동기화 메커니즘이 필요합니다.

## 2. 멀티프로세싱 (Multiprocessing): 여러 몸에 여러 팔

### 2.1. 멀티프로세싱이란?
멀티프로세싱은 이름 그대로 여러 개의 **프로세스(Process)**를 동시에 실행하는 방식입니다. 각 프로세스는 운영체제로부터 독립적인 메모리 공간을 할당받으며, 서로 완전히 독립적으로 실행됩니다.

비유하자면, 여러 사람(프로세스)이 각자의 몸과 팔을 가지고 각자 다른 주방에서 요리하는 것과 같습니다. 각자 독립적이기 때문에 다른 사람의 영향을 받지 않고, 동시에 여러 요리를 할 수 있습니다.

### 2.2. GIL 우회와 진정한 병렬 처리
각 프로세스는 자신만의 파이썬 인터프리터와 GIL을 가집니다. 따라서 파이썬의 GIL로부터 자유로워지며, CPU 코어 개수만큼의 **진정한 병렬 처리**를 수행할 수 있습니다. 이는 특히 고성능 CPU를 사용하는 시스템에서 CPU-bound(연산 중심) 작업을 처리할 때 큰 이점을 가집니다.

### 2.3. 코드 예제: CPU 바운드 작업에 멀티프로세싱 적용하기

아래 예제는 각 프로세스가 매우 긴 반복문을 실행하여 CPU 연산을 집중적으로 수행하는 CPU 바운드 작업을 시뮬레이션합니다. 3개의 프로세스가 동시에 작업을 수행하므로, 단일 프로세스로 실행할 때보다 훨씬 빠른 결과를 보여줍니다.

```python
import multiprocessing
import time

def cpu_bound_task(name, count):
    """CPU 바운드 작업을 시뮬레이션하는 함수"""
    print(f"프로세스 {name}: 작업 시작 (CPU 연산 중...)")
    total = 0
    for i in range(count):
        total += i * i # 복잡한 연산 시뮬레이션
    print(f"프로세스 {name}: 작업 완료 (결과 일부: {total % 1000})") # 결과 일부만 출력

if __name__ == "__main__":
    start_time = time.time()
    processes = []
    
    # 각 프로세스에서 수행할 연산량 (매우 큰 숫자)
    task_count = 50_000_000 

    # 3개의 프로세스 생성 및 시작
    for i in range(3):
        process = multiprocessing.Process(target=cpu_bound_task, args=(f"#{i+1}", task_count))
        processes.append(process)
        process.start()

    # 모든 프로세스가 종료될 때까지 기다림
    for process in processes:
        process.join()

    end_time = time.time()
    print(f"\n총 실행 시간: {end_time - start_time:.2f}초")
```

**실행 결과 (예시, 시스템마다 다를 수 있음):**
```
프로세스 #1: 작업 시작 (CPU 연산 중...)
프로세스 #2: 작업 시작 (CPU 연산 중...)
프로세스 #3: 작업 시작 (CPU 연산 중...)
프로세스 #1: 작업 완료 (결과 일부: 12)
프로세스 #2: 작업 완료 (결과 일부: 12)
프로세스 #3: 작업 완료 (결과 일부: 12)

총 실행 시간: 6.54초
```
만약 이 작업을 싱글 프로세스로 3번 반복했다면 `(6.54초 / 3) * 3 = 19.62초` 가 걸렸을 것입니다. 하지만 멀티프로세싱을 사용하면 CPU 코어를 활용하여 훨씬 빠르게 작업을 완료할 수 있습니다.

### 2.4. 멀티프로세싱의 장단점
*   **장점:**
    *   파이썬 GIL의 영향을 받지 않아 CPU 바운드 작업에서 진정한 병렬 처리가 가능합니다.
    *   각 프로세스가 독립적이므로, 하나의 프로세스에 문제가 생겨도 다른 프로세스에는 영향을 주지 않아 안정성이 높습니다.
*   **단점:**
    *   프로세스 생성 및 전환 비용이 스레드보다 훨씬 무겁습니다.
    *   각 프로세스가 독립적인 메모리 공간을 가지므로, 데이터를 공유하려면 `Queue`나 `Pipe`와 같은 **IPC(Inter-Process Communication)** 메커니즘을 사용해야 해서 복잡합니다.

## 3. 언제 무엇을 사용해야 할까? (핵심 요약)

자, 이제 가장 중요한 질문에 답할 시간입니다. 언제 멀티스레딩을 사용하고, 언제 멀티프로세싱을 사용해야 할까요?

| 특징           | 멀티스레딩 (Multithreading)                                    | 멀티프로세싱 (Multiprocessing)                                      |
| :------------- | :------------------------------------------------------------- | :------------------------------------------------------------------ |
| **목표**       | I/O 대기 시간을 활용한 **동시성(Concurrency)**              | 여러 CPU 코어를 활용한 **진정한 병렬성(Parallelism)**             |
| **GIL 영향**   | GIL의 영향을 받음 (CPU 바운드 작업에 비효율적)                 | GIL의 영향을 받지 않음 (CPU 코어 완벽 활용)                         |
| **메모리 공유** | 쉽다 (같은 프로세스 메모리 공유)                               | 어렵다 (각 프로세스 독립 메모리, IPC 필요)                          |
| **자원 소모**  | 가볍다 (스레드 생성/전환 비용 낮음)                            | 무겁다 (프로세스 생성/전환 비용 높음)                               |
| **안정성**     | 한 스레드 오류가 전체 프로세스에 영향 가능                       | 한 프로세스 오류가 다른 프로세스에 영향 X (높은 안정성)             |
| **주요 활용**  | **I/O 바운드 작업:** 웹 스크래핑, 네트워크 요청, 파일 입출력 등 | **CPU 바운드 작업:** 복잡한 계산, 데이터 처리, 이미지/영상 처리 등 |

**간단하게 정리하면:**

*   **멀티스레딩**은 "기다리는 시간"이 많은 작업에 적합합니다. (네트워크 요청, 파일 읽고 쓰기 등)
*   **멀티프로세싱**은 "열심히 계산하는 시간"이 많은 작업에 적합합니다. (복잡한 수학 연산, 데이터 분석, 이미지 처리 등)

## 결론

파이썬에서 멀티스레딩과 멀티프로세싱은 프로그램의 성능을 향상시키기 위한 강력한 도구입니다. 하지만 각각의 장단점과 파이썬 GIL이라는 특성을 이해하고, 자신이 해결하려는 문제의 특성(I/O 바운드인지, CPU 바운드인지)에 따라 적절한 방법을 선택하는 것이 중요합니다.

무작정 "병렬 처리"라는 말에 현혹되어 아무 방법이나 적용하기보다는, 오늘 배운 내용을 바탕으로 여러분의 코드에 가장 효율적인 방법을 찾아보시길 바랍니다! 궁금한 점이 있다면 언제든지 댓글로 남겨주세요. 다음에는 더 유익한 내용으로 찾아오겠습니다!
