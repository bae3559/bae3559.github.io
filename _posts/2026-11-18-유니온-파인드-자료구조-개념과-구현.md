# [자료구조] 유니온-파인드 (Union-Find): 합쳐지고 찾아지는 마법 같은 친구들

## 💡 유니온-파인드, 왜 필요할까요? (문제 상황)

상상해 보세요. 여러분이 SNS를 개발하고 있는데, 다음과 같은 기능을 구현해야 합니다.
1.  **두 사람이 친구 관계인지 확인:** A와 B가 친구이고, B와 C가 친구라면, A와 C도 간접적으로는 같은 '친구 그룹'에 속해 있다고 볼 수 있겠죠?
2.  **새로운 친구 관계 추가:** D와 E가 친구가 되었다면, 이 두 사람을 하나의 친구 그룹으로 묶어야 합니다.

이처럼 **'서로소 집합(Disjoint Set)'**이라는 개념을 다룰 때 유니온-파인드는 빛을 발합니다. 서로소 집합이란, 공통 원소를 가지고 있지 않은 집합들을 의미합니다. 위 예시에서는 각 친구 그룹이 하나의 서로소 집합이 됩니다. 즉, 유니온-파인드는 여러 개의 서로소 집합들을 관리하며, 두 원소가 같은 집합에 속해 있는지 확인하거나, 두 집합을 하나로 합치는 연산을 매우 효율적으로 수행하게 해주는 자료구조입니다.

## 🎯 유니온-파인드의 핵심 개념: Find와 Union

유니온-파인드는 이름에서 알 수 있듯이, 딱 두 가지 핵심 연산으로 이루어져 있습니다.

1.  ### `Find(x)` 연산: '대표자'를 찾아라!
    특정 원소 `x`가 어떤 집합에 속해 있는지 알아내기 위해, 그 집합의 '대표자(Representative)'를 찾아주는 연산입니다. 각 집합은 하나의 대표자를 가지며, 같은 집합에 속한 모든 원소는 동일한 대표자를 가리키게 됩니다.

    *   **예시:** 한 마을의 모든 주민은 그 마을의 '이장님'을 대표자로 가집니다. `Find(김철수)` 연산은 김철수 씨가 속한 마을의 이장님을 찾아주는 것과 같습니다.

2.  ### `Union(x, y)` 연산: 두 집합을 '합쳐라'!
    두 원소 `x`와 `y`가 속한 각각의 집합을 하나의 집합으로 합치는 연산입니다. 이 연산을 수행하면 `x`와 `y`는 이제 같은 집합에 속하게 됩니다.

    *   **예시:** 옆 마을과 우리 마을이 통합되었다면, 두 마을의 주민들은 이제 같은 대표자를 가지게 됩니다.

## 🧑‍💻 유니온-파인드 구현하기 (feat. Python)

이제 이 개념들을 코드로 옮겨볼 시간입니다. 유니온-파인드는 주로 배열(또는 리스트)을 사용하여 구현합니다. `parent` 배열은 각 원소의 부모를 저장하며, `parent[i] = i`인 경우는 `i`가 해당 집합의 대표자임을 의미합니다.

### 1. 기본 구현 (Basic Implementation)

가장 기본적인 형태의 유니온-파인드입니다.

```python
class UnionFindBasic:
    def __init__(self, n):
        # 각 원소의 부모를 저장하는 배열
        # 처음에는 자기 자신이 부모 (대표자)
        self.parent = list(range(n))

    def find(self, i):
        # i의 대표자(루트)를 찾는 연산
        # 만약 i가 자기 자신을 부모로 가리키고 있다면, i는 대표자
        if self.parent[i] == i:
            return i
        # 그렇지 않다면, 부모를 따라 계속 찾아 올라간다
        return self.find(self.parent[i])

    def union(self, i, j):
        # i와 j가 속한 집합을 합치는 연산
        # 각 원소의 대표자를 찾는다
        root_i = self.find(i)
        root_j = self.find(j)

        # 만약 두 대표자가 다르다면, 두 집합을 합친다
        if root_i != root_j:
            # 보통 한쪽 대표자를 다른 쪽 대표자의 자식으로 만든다
            self.parent[root_j] = root_i
            return True # 합치기 성공
        return False # 이미 같은 집합에 속해 있음

# 예시 사용
print("--- 기본 유니온-파인드 ---")
uf_basic = UnionFindBasic(5) # 0, 1, 2, 3, 4 다섯 개의 원소
print(f"초기 parent: {uf_basic.parent}") # [0, 1, 2, 3, 4]

uf_basic.union(0, 1) # 0과 1 연결
uf_basic.union(1, 2) # 1과 2 연결 (결국 0, 1, 2가 같은 집합)
uf_basic.union(3, 4) # 3과 4 연결

print(f"Union 후 parent: {uf_basic.parent}") # [0, 0, 0, 3, 3] (경로 압축 없음)

print(f"0의 대표자: {uf_basic.find(0)}") # 0
print(f"1의 대표자: {uf_basic.find(1)}") # 0
print(f"2의 대표자: {uf_basic.find(2)}") # 0
print(f"3의 대표자: {uf_basic.find(3)}") # 3
print(f"4의 대표자: {uf_basic.find(4)}") # 3

print(f"0과 2는 같은 집합인가? {uf_basic.find(0) == uf_basic.find(2)}") # True
print(f"0과 3은 같은 집합인가? {uf_basic.find(0) == uf_basic.find(3)}") # False
```

### 2. 효율성을 위한 최적화 (Optimizations)

위 기본 구현은 특정 상황에서 비효율적일 수 있습니다. 예를 들어, 모든 원소가 일렬로 연결된 `0 -> 1 -> 2 -> ... -> N-1` 같은 형태가 되면, `Find(N-1)` 연산은 N번의 재귀 호출을 수행해야 합니다. 이는 O(N)의 시간 복잡도를 가집니다. 유니온-파인드의 진정한 가치는 이 연산들을 거의 상수 시간에 가깝게 만들 수 있다는 데 있습니다. 이를 위해 두 가지 최적화 기법을 사용합니다.

#### 2.1. 경로 압축 (Path Compression) - `Find` 연산 최적화

`Find` 연산을 수행하면서, 거쳐 가는 모든 노드들이 최종 대표자를 직접 가리키도록 부모를 갱신합니다. 이렇게 하면 다음번에 같은 노드의 `Find` 연산이 호출될 때 훨씬 빠르게 대표자를 찾을 수 있습니다.

```python
    def find(self, i):
        # i가 자기 자신을 부모로 가리키고 있다면, i는 대표자
        if self.parent[i] == i:
            return i
        # 경로 압축: i의 부모를 재귀적으로 찾은 후, 그 대표자를 i의 새로운 부모로 설정
        self.parent[i] = self.find(self.parent[i])
        return self.parent[i]
```
이 한 줄의 마법 같은 코드가 트리의 깊이를 획기적으로 줄여줍니다.

#### 2.2. 유니온 바이 랭크/사이즈 (Union by Rank/Size) - `Union` 연산 최적화

`Union` 연산을 수행할 때, 단순히 한쪽 대표자를 다른 쪽의 자식으로 만드는 것이 아니라, 트리의 높이(랭크)나 집합의 크기(사이즈)를 고려하여 합칩니다.
*   **랭크(Rank) 기반:** 높이가 낮은 트리를 높이가 높은 트리에 붙여서 전체 트리의 높이가 급격히 증가하는 것을 방지합니다.
*   **사이즈(Size) 기반:** 원소의 개수가 적은 집합을 원소의 개수가 많은 집합에 붙여서 트리가 한쪽으로 치우치는 것을 방지합니다.

두 방법 모두 목적은 같습니다: 트리의 깊이를 최대한 얕게 유지하는 것. 여기서는 구현이 비교적 직관적인 '사이즈 기반 유니온'을 사용하겠습니다.

```python
class UnionFindOptimized:
    def __init__(self, n):
        self.parent = list(range(n))
        # 각 집합의 크기를 저장하는 배열
        # 처음에는 각 원소가 하나의 집합이므로 크기는 1
        self.size = [1] * n

    def find(self, i):
        # 경로 압축 적용
        if self.parent[i] == i:
            return i
        self.parent[i] = self.find(self.parent[i])
        return self.parent[i]

    def union(self, i, j):
        root_i = self.find(i)
        root_j = self.find(j)

        if root_i != root_j:
            # 사이즈를 비교하여 더 큰 집합 아래에 작은 집합을 붙인다
            if self.size[root_i] < self.size[root_j]:
                root_i, root_j = root_j, root_i # root_i가 항상 더 크거나 같도록 스왑

            self.parent[root_j] = root_i # 작은 집합을 큰 집합 아래에 붙인다
            self.size[root_i] += self.size[root_j] # 큰 집합의 사이즈를 업데이트
            return True
        return False

    # 두 원소가 같은 집합에 속해 있는지 확인하는 편의 메서드
    def is_connected(self, i, j):
        return self.find(i) == self.find(j)

# 예시 사용
print("\n--- 최적화된 유니온-파인드 ---")
uf_optimized = UnionFindOptimized(7) # 0부터 6까지 7개의 원소
print(f"초기 parent: {uf_optimized.parent}, size: {uf_optimized.size}")

uf_optimized.union(0, 1)
uf_optimized.union(1, 2)
uf_optimized.union(3, 4)
uf_optimized.union(5, 6)

print(f"Union(0,1), (1,2), (3,4), (5,6) 후")
print(f"parent: {uf_optimized.parent}, size: {uf_optimized.size}")
# 이때 parent와 size는 경로 압축이 아직 '명시적으로' 일어나지 않아 완벽히 정리되어 보이지 않을 수 있음.
# find를 호출하면 경로 압축이 동작하며 parent 배열이 정리됨.

print(f"0의 대표자: {uf_optimized.find(0)}, parent: {uf_optimized.parent}") # 0
print(f"1의 대표자: {uf_optimized.find(1)}, parent: {uf_optimized.parent}") # 0 (1의 부모가 0으로 직접 연결됨)
print(f"2의 대표자: {uf_optimized.find(2)}, parent: {uf_optimized.parent}") # 0 (2의 부모가 0으로 직접 연결됨)
print(f"집합 {uf_optimized.find(0)}의 크기: {uf_optimized.size[uf_optimized.find(0)]}")

uf_optimized.union(0, 3) # 0,1,2 집합과 3,4 집합 합치기
print(f"Union(0,3) 후 parent: {uf_optimized.parent}, size: {uf_optimized.size}")

print(f"0과 4는 연결되어 있는가? {uf_optimized.is_connected(0, 4)}") # True
print(f"2와 5는 연결되어 있는가? {uf_optimized.is_connected(2, 5)}") # False

# 추가 연결
uf_optimized.union(2, 5) # 0,1,2,3,4 집합과 5,6 집합 합치기
print(f"Union(2,5) 후 parent: {uf_optimized.parent}, size: {uf_optimized.size}")
print(f"4와 6은 연결되어 있는가? {uf_optimized.is_connected(4, 6)}") # True
```

### 3. 시간 복잡도 (Time Complexity)

경로 압축과 랭크/사이즈 기반 유니온이라는 두 가지 최적화를 함께 사용하면, 유니온-파인드의 시간 복잡도는 놀랍게도 **거의 상수 시간**에 가깝습니다. 정확히는 **아커만 함수(Ackermann function)의 역함수(Inverse Ackermann function, α(N))**에 비례하는데, 이 함수는 N이 아무리 커져도 4 이하의 매우 작은 값을 가집니다. 따라서 실제 문제 풀이에서는 거의 O(1)에 가깝다고 생각하시면 됩니다. 이는 유니온-파인드가 매우 강력한 자료구조로 평가받는 이유입니다.

## 🌟 유니온-파인드의 활용 분야

유니온-파인드는 그 효율성 덕분에 다양한 알고리즘 문제와 실제 시스템에서 활용됩니다.

*   **그래프의 연결 요소(Connected Components) 찾기:** 그래프에서 서로 연결된 노드들의 그룹을 찾는 데 사용됩니다.
*   **최소 신장 트리(Minimum Spanning Tree, MST) 알고리즘:** 특히 **크루스칼(Kruskal's) 알고리즘**에서 간선을 연결할 때 사이클이 발생하는지 여부를 효율적으로 판단하는 데 핵심적인 역할을 합니다.
*   **네트워크 연결성 확인:** 특정 네트워크에서 두 노드가 연결되어 있는지 여부를 빠르게 확인해야 할 때 유용합니다.
*   **게임 개발:** 맵 상의 특정 지역들이 연결되어 있는지 판단하거나, 몬스터 그룹을 관리하는 등에 응용될 수 있습니다.
