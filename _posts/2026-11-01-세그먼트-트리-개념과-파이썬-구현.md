# 세그먼트 트리, 데이터의 구간을 효율적으로 다루는 마법 지팡이 (개념과 파이썬 구현)

안녕하세요, 효율적인 데이터 처리를 사랑하는 개발 블로그 작가입니다.

데이터를 다루다 보면 특정 '구간'에 대한 정보를 빠르게 얻고 싶을 때가 많습니다. 예를 들어, 거대한 배열에서 특정 구간의 합, 최솟값, 최댓값 등을 구하는 문제 말이죠. 일반적인 방법으로는 매번 O(N)의 시간이 걸립니다. 하지만 데이터의 크기가 너무 크거나, 특정 요소의 값을 변경(업데이트)하는 작업이 빈번하게 일어난다면 어떨까요? 매번 O(N)으로 처리하는 것은 비효율적이다 못해 시스템 전체의 병목 현상을 초래할 수 있습니다.

이럴 때 빛을 발하는 자료구조가 바로 **세그먼트 트리(Segment Tree)**입니다! 세그먼트 트리는 배열의 특정 '구간'에 대한 질의(Query)와 '점(Point)' 업데이트를 O(log N)이라는 아주 빠른 시간 복잡도로 처리할 수 있게 해주는 강력한 도구입니다.

오늘은 세그먼트 트리가 무엇인지, 어떻게 동작하는지, 그리고 파이썬으로 어떻게 구현하는지 함께 알아보겠습니다. 초보자분들도 이해하기 쉽도록 친절하게 설명해 드릴게요!

---

## 1. 세그먼트 트리란 무엇인가요?

세그먼트 트리는 이름처럼 배열의 '구간(Segment)'에 대한 정보를 저장하는 트리 기반의 자료구조입니다. 전체 배열을 절반씩 쪼개고, 또 그 절반을 쪼개는 방식으로 트리 구조를 만듭니다. 마치 스포츠 대회의 토너먼트 대진표와 비슷하다고 생각할 수 있습니다.

*   **리프 노드(Leaf Node)**: 트리의 가장 아래에 있는 노드들로, 원본 배열의 개별 요소를 나타냅니다. (예: `arr[0]`, `arr[1]`, ...)
*   **내부 노드(Internal Node)**: 자식 노드들이 나타내는 구간의 정보를 결합한 결과를 저장합니다. 예를 들어, 자식 노드가 `[0,1]` 구간의 합(3)과 `[2,3]` 구간의 합(7)을 가지고 있다면, 부모 노드는 `[0,3]` 구간의 합(10)을 저장하는 식입니다.

이렇게 구성된 트리는 배열의 모든 구간에 대한 정보를 계층적으로 가지고 있기 때문에, 어떤 구간에 대한 질의가 들어와도 트리의 깊이(log N)만큼만 탐색하면 원하는 정보를 얻을 수 있습니다.

---

## 2. 세그먼트 트리는 어떻게 동작하나요?

세그먼트 트리의 핵심 동작은 크게 세 가지입니다: 트리 구축, 구간 질의, 그리고 값 업데이트.

### 2.1. 트리 구축 (Build)

세그먼트 트리는 재귀적으로 구축됩니다. 원본 배열 `arr`의 `start`부터 `end`까지의 구간을 담당하는 노드를 `node`라고 할 때,

1.  **기저 조건**: 만약 `start`와 `end`가 같다면 (즉, 리프 노드에 도달했다면), `node`에 `arr[start]` 값을 저장합니다.
2.  **재귀 호출**: 그렇지 않다면, `mid = (start + end) // 2`를 기준으로 구간을 절반으로 나눕니다.
    *   왼쪽 자식 노드에게 `[start, mid]` 구간의 트리를 만들도록 재귀 호출합니다.
    *   오른쪽 자식 노드에게 `[mid + 1, end]` 구간의 트리를 만들도록 재귀 호출합니다.
3.  **값 계산**: 두 자식 노드로부터 값을 받아와 `node`에 현재 구간 `[start, end]`의 값을 계산하여 저장합니다. (예: 두 자식 노드의 합, 최솟값 등)

세그먼트 트리는 대략 `N`개의 리프 노드를 가지며, 전체 노드 수는 `2N-1` 정도 됩니다. 구현의 편의를 위해 보통 원본 배열 크기 `N`의 4배 정도 되는 크기의 배열을 `tree`로 사용합니다.

### 2.2. 구간 질의 (Query)

원하는 구간 `[query_start, query_end]`가 주어졌을 때, 해당 구간에 대한 정보를 얻기 위해 트리를 탐색합니다. 현재 노드가 담당하는 구간 `[start, end]`와 질의 구간 `[l, r]`을 비교하여 다음 세 가지 경우 중 하나를 따릅니다.

1.  **완전 포함 (Total Overlap)**: 현재 노드의 구간 `[start, end]`가 질의 구간 `[l, r]`에 완전히 포함될 때 (`l <= start` 이고 `end <= r`).
    *   더 이상 깊이 들어갈 필요 없이, 현재 노드가 저장하고 있는 값을 바로 반환합니다.
2.  **완전 벗어남 (No Overlap)**: 현재 노드의 구간 `[start, end]`가 질의 구간 `[l, r]`과 전혀 겹치지 않을 때 (`r < start` 이거나 `end < l`).
    *   이 노드는 질의에 필요한 정보를 가지고 있지 않으므로, 연산에 영향을 주지 않는 '항등원'을 반환합니다. (예: 합이라면 0, 최솟값이라면 무한대 `math.inf`)
3.  **부분 포함 (Partial Overlap)**: 그 외의 경우 (부분적으로 겹칠 때).
    *   왼쪽 자식과 오른쪽 자식에게 각각 재귀적으로 질의를 보냅니다.
    *   두 자식 노드로부터 받은 결과를 합쳐서 반환합니다.

### 2.3. 값 업데이트 (Update)

원본 배열의 특정 인덱스 `idx`의 값이 `new_value`로 변경되었을 때, 트리를 업데이트하는 과정입니다.

1.  **리프 노드 찾기**: `idx`에 해당하는 리프 노드를 찾아 내려갑니다.
2.  **값 변경**: 해당 리프 노드의 값을 `new_value`로 변경합니다. 동시에 원본 배열 `arr[idx]`도 `new_value`로 업데이트합니다.
3.  **부모 노드 업데이트**: 리프 노드부터 루트 노드까지 거슬러 올라가면서, 경로에 있는 모든 부모 노드들의 값을 변경된 자식 값에 맞춰 재계산합니다.

## 3. 파이썬으로 세그먼트 트리 구현하기

이제 앞서 설명한 개념들을 바탕으로 파이썬으로 세그먼트 트리를 구현해 보겠습니다. 여기서는 `merge_func` 인자를 받아 다양한 연산(합, 최솟값, 최댓값 등)을 수행할 수 있도록 유연하게 구현할 것입니다.

```python
import math

class SegmentTree:
    def __init__(self, arr, merge_func, identity_element):
        """
        SegmentTree를 초기화합니다.
        :param arr: 원본 배열
        :param merge_func: 두 자식 노드의 값을 합치는 함수 (예: lambda x, y: x + y, min, max)
        :param identity_element: 연산의 항등원 (예: 합의 경우 0, 최솟값의 경우 math.inf, 최댓값의 경우 -math.inf)
        """
        self.array = arr
        self.n = len(arr)
        # 트리는 원본 배열 크기의 약 4배 정도의 크기를 갖도록 합니다. (노드 번호 1부터 시작)
        self.tree = [0] * (4 * self.n)
        self.merge_func = merge_func
        self.identity_element = identity_element

    def _build(self, node, start, end):
        """
        재귀적으로 Segment Tree를 구축합니다.
        :param node: 현재 트리의 노드 번호
        :param start: 현재 노드가 담당하는 배열의 시작 인덱스
        :param end: 현재 노드가 담당하는 배열의 끝 인덱스
        """
        if start == end: # 리프 노드인 경우
            self.tree[node] = self.array[start]
            return
        
        mid = (start + end) // 2
        # 왼쪽 자식: 2 * node, 오른쪽 자식: 2 * node + 1
        self._build(2 * node, start, mid)
        self._build(2 * node + 1, mid + 1, end)
        
        # 자식 노드들의 값을 합쳐 현재 노드의 값을 결정
        self.tree[node] = self.merge_func(self.tree[2 * node], self.tree[2 * node + 1])

    def build(self):
        """외부에서 호출되는 트리 구축 메서드"""
        self._build(1, 0, self.n - 1)

    def _query(self, node, start, end, l, r):
        """
        재귀적으로 [l, r] 구간에 대한 질의를 수행합니다.
        :param node: 현재 트리의 노드 번호
        :param start: 현재 노드가 담당하는 배열의 시작 인덱스
        :param end: 현재 노드가 담당하는 배열의 끝 인덱스
        :param l: 질의 구간의 시작 인덱스
        :param r: 질의 구간의 끝 인덱스
        """
        # 1. 현재 노드의 구간이 질의 구간과 전혀 겹치지 않을 때
        if r < start or end < l:
            return self.identity_element # 항등원 반환

        # 2. 현재 노드의 구간이 질의 구간에 완전히 포함될 때
        if l <= start and end <= r:
            return self.tree[node]

        # 3. 현재 노드의 구간이 질의 구간에 부분적으로 겹칠 때
        mid = (start + end) // 2
        p1 = self._query(2 * node, start, mid, l, r) # 왼쪽 자식에게 질의
        p2 = self._query(2 * node + 1, mid + 1, end, l, r) # 오른쪽 자식에게 질의
        return self.merge_func(p1, p2) # 두 자식의 결과를 합쳐 반환

    def query(self, l, r):
        """
        외부에서 호출되는 구간 질의 메서드
        :param l: 질의 구간의 시작 인덱스
        :param r: 질의 구간의 끝 인덱스
        """
        if not (0 <= l <= r < self.n):
            raise IndexError("Query range is out of bounds.")
        return self._query(1, 0, self.n - 1, l, r)

    def _update(self, node, start, end, idx, val):
        """
        재귀적으로 특정 인덱스(idx)의 값을 업데이트합니다.
        :param node: 현재 트리의 노드 번호
        :param start: 현재 노드가 담당하는 배열의 시작 인덱스
        :param end: 현재 노드가 담당하는 배열의 끝 인덱스
        :param idx: 업데이트할 배열의 인덱스
        :param val: 새로운 값
        """
        if start == end: # 리프 노드에 도달하면 값 업데이트
            self.array[idx] = val # 원본 배열도 업데이트
            self.tree[node] = val
            return

        mid = (start + end) // 2
        if start <= idx <= mid: # 업데이트할 인덱스가 왼쪽 자식 구간에 있을 때
            self._update(2 * node, start, mid, idx, val)
        else: # 업데이트할 인덱스가 오른쪽 자식 구간에 있을 때
            self._update(2 * node + 1, mid + 1, end, idx, val)
        
        # 자식 노드의 값이 변경되었으므로 현재 노드의 값도 재계산
        self.tree[node] = self.merge_func(self.tree[2 * node], self.tree[2 * node + 1])

    def update(self, idx, val):
        """
        외부에서 호출되는 값 업데이트 메서드
        :param idx: 업데이트할 배열의 인덱스
        :param val: 새로운 값
        """
        if not (0 <= idx < self.n):
            raise IndexError("Index for update is out of bounds.")
        self._update(1, 0, self.n - 1, idx, val)

# --- 사용 예시 ---

print("--- 합 계산 세그먼트 트리 예시 ---")
arr_sum = [1, 2, 3, 4, 5, 6, 7, 8]
seg_tree_sum = SegmentTree(arr_sum, lambda x, y: x + y, 0) # 합의 항등원은 0
seg_tree_sum.build()

print(f"원본 배열: {seg_tree_sum.array}")
print(f"전체 [0, 7] 구간 합: {seg_tree_sum.query(0, 7)}") # 1+2+...+8 = 36
print(f"[2, 5] 구간 합: {seg_tree_sum.query(2, 5)}") # 3+4+5+6 = 18

print("\n--- 값 업데이트 후 ---")
seg_tree_sum.update(3, 10) # arr_sum[3]을 4에서 10으로 변경
print(f"인덱스 3을 10으로 업데이트 후 배열: {seg_tree_sum.array}")
print(f"[2, 5] 구간 합 (업데이트 후): {seg_tree_sum.query(2, 5)}") # 3+10+5+6 = 24

print("\n--- 최솟값 계산 세그먼트 트리 예시 ---")
arr_min = [5, 2, 8, 1, 9, 3]
seg_tree_min = SegmentTree(arr_min, min, math.inf) # 최솟값의 항등원은 무한대 (어떤 수와 비교해도 자기 자신이 최솟값)
seg_tree_min.build()

print(f"원본 배열 (최솟값): {seg_tree_min.array}")
print(f"[0, 5] 구간 최솟값: {seg_tree_min.query(0, 5)}") # 1
print(f"[0, 2] 구간 최솟값: {seg_tree_min.query(0, 2)}") # 2 (5, 2, 8 중)

print("\n--- 값 업데이트 후 (최솟값) ---")
seg_tree_min.update(0, 0) # arr_min[0]을 5에서 0으로 변경
print(f"인덱스 0을 0으로 업데이트 후 배열 (최솟값): {seg_tree_min.array}")
print(f"[0, 2] 구간 최솟값 (업데이트 후): {seg_tree_min.query(0, 2)}") # 0 (0, 2, 8 중)

print("\n--- 최댓값 계산 세그먼트 트리 예시 ---")
arr_max = [10, 20, 5, 30, 15]
seg_tree_max = SegmentTree(arr_max, max, -math.inf) # 최댓값의 항등원은 -무한대
seg_tree_max.build()

print(f"원본 배열 (최댓값): {seg_tree_max.array}")
print(f"[0, 4] 구간 최댓값: {seg_tree_max.query(0, 4)}") # 30
print(f"[0, 2] 구간 최댓값: {seg_tree_max.query(0, 2)}") # 20 (10, 20, 5 중)
```

## 4. 시간 및 공간 복잡도

*   **트리 구축 (Build)**: 모든 노드를 한 번씩 방문하므로 **O(N)**
*   **구간 질의 (Query)**: 트리의 깊이(log N)만큼 탐색하므로 **O(log N)**
*   **값 업데이트 (Update)**: 리프 노드부터 루트까지 올라가는 경로만 탐색하므로 **O(log N)**
*   **공간 복잡도**: 원본 배열의 크기 `N`에 비례하는 트리를 저장하므로 **O(N)**

세그먼트 트리는 질의와 업데이트 모두 로그 시간에 처리할 수 있어, 많은 데이터를 다루는 상황에서 매우 효율적입니다.

---

## 5. 언제 세그먼트 트리를 사용하면 좋을까요?

세그먼트 트리는 다음과 같은 상황에서 특히 유용합니다:

*   **잦은 구간 질의와 점 업데이트가 필요한 경우**: 경쟁 프로그래밍 문제에서 단골로 등장하며, 구간 합/최솟값/최댓값 등을 빠르게 찾아야 할 때 사용됩니다.
*   **데이터가 정적이지 않고 계속 변경되는 경우**: 배열의 특정 값이 변경되더라도 전체 구간 정보를 빠르게 갱신하고 다시 질의할 수 있습니다.
*   **다양한 구간 연산**: 합, 최솟값, 최댓값뿐만 아니라 GCD(최대공약수), XOR 등 결합 가능한 어떤 연산이든 적용할 수 있습니다.
