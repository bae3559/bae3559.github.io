# 파이썬 메모리, 그 속살을 들여다보다: 참조 카운트와 가비지 컬렉션

안녕하세요, 개발 블로그 독자 여러분! 🚀

파이썬은 우리가 코드를 작성할 때 메모리 관리에 대해 크게 신경 쓰지 않아도 되도록 설계된 언어입니다. 마치 마법처럼, 필요할 때 메모리를 할당하고 필요 없으면 알아서 회수해주는 것 같죠. 하지만 이 "마법"의 이면에는 강력하고 정교한 메커니즘이 숨어 있습니다. 바로 **참조 카운트(Reference Counting)**와 **가비지 컬렉션(Garbage Collection)**입니다.

오늘은 파이썬이 어떻게 메모리를 관리하는지, 왜 이 두 가지 메커니즘이 필요한지, 그리고 개발자로서 우리가 알아두면 좋은 점은 무엇인지 함께 깊이 파고들어 보겠습니다. 초보 개발자분들도 쉽게 이해할 수 있도록 친절하게 설명해 드릴게요!

---

## 1. 파이썬의 모든 것은 '객체'로부터

파이썬에서는 숫자, 문자열, 리스트, 함수 등 여러분이 다루는 모든 것이 **객체(Object)**입니다. 이 객체들은 컴퓨터 메모리 어딘가에 저장됩니다. 변수는 단순히 이 객체들을 가리키는 **이름표(참조)**에 불과합니다.

각 객체는 고유한 메모리 주소(ID)를 가지고 있으며, 특정 크기의 메모리를 차지합니다. `id()` 함수로 객체의 메모리 주소를, `sys.getsizeof()` 함수로 객체의 크기를 확인할 수 있습니다.

```python
import sys

# 다양한 타입의 객체들
a = 10
b = "안녕하세요, 파이썬!"
c = [1, 2, 3]
d = {"name": "Alice", "age": 30}

print(f"정수 10의 ID: {id(a)}, 크기: {sys.getsizeof(a)} 바이트")
print(f"문자열 '{b}'의 ID: {id(b)}, 크기: {sys.getsizeof(b)} 바이트")
print(f"리스트 {c}의 ID: {id(c)}, 크기: {sys.getsizeof(c)} 바이트")
print(f"딕셔너리 {d}의 ID: {id(d)}, 크기: {sys.getsizeof(d)} 바이트")
```

**실행 결과 예시:**
```
정수 10의 ID: 140735504781704, 크기: 28 바이트
문자열 '안녕하세요, 파이썬!'의 ID: 1989467770800, 크기: 67 바이트
리스트 [1, 2, 3]의 ID: 1989467770944, 크기: 80 바이트
딕셔너리 {'name': 'Alice', 'age': 30}의 ID: 1989467771024, 크기: 232 바이트
```
보시다시피, 같은 타입이라도 값의 크기에 따라 차지하는 메모리도 달라집니다. 파이썬은 이렇게 생성된 객체들을 어떻게 효율적으로 관리하고 언제 메모리에서 해제할까요?

## 2. 핵심 메커니즘 1: 참조 카운트 (Reference Counting)

파이썬의 메모리 관리에서 가장 기본적이고 핵심적인 메커니즘은 바로 **참조 카운트(Reference Counting)**입니다.

모든 파이썬 객체는 자신의 **참조 카운트**를 가지고 있습니다. 이 카운트는 해당 객체를 가리키는 변수(참조)의 개수를 의미합니다.

*   **참조 카운트 증가:**
    *   객체에 새로운 변수가 할당될 때 (예: `b = a`)
    *   객체가 컨테이너(리스트, 튜플, 딕셔너리 등)에 포함될 때
    *   객체가 함수의 인자로 전달될 때
*   **참조 카운트 감소:**
    *   변수가 다른 객체에 재할당될 때 (예: `a = 20`)
    *   변수가 `del` 문으로 삭제될 때 (예: `del a`)
    *   함수가 종료되어 지역 변수가 사라질 때
    *   컨테이너에서 객체가 제거될 때

**참조 카운트가 0이 되면?**
어떤 객체의 참조 카운트가 0이 되면, 더 이상 그 객체를 사용하는 변수가 없다는 뜻입니다. 파이썬은 이 객체가 더 이상 필요 없다고 판단하고, 즉시 메모리에서 **해제(deallocate)**하여 다른 곳에서 사용할 수 있도록 합니다.

`sys` 모듈의 `getrefcount()` 함수를 사용하여 객체의 참조 카운트를 확인할 수 있습니다.
**주의:** `sys.getrefcount()` 함수 자체도 인자로 전달된 객체에 대한 임시 참조를 생성하므로, 실제 참조 카운트보다 항상 1이 더 높게 나옵니다. 이 점을 감안해서 봐야 합니다.

```python
import sys

my_list = [1, 2, 3]
print(f"1. 초기 my_list 참조 카운트: {sys.getrefcount(my_list) - 1}") # -1을 하는 이유: getrefcount() 호출 자체도 하나의 참조를 추가하기 때문

another_ref = my_list # 새로운 변수가 my_list를 참조
print(f"2. another_ref 할당 후: {sys.getrefcount(my_list) - 1}")

def func(obj):
    print(f"3. 함수 인자로 전달 후: {sys.getrefcount(obj) - 1}")
    return obj

returned_ref = func(my_list) # 함수 인자로 전달
print(f"4. 함수에서 리턴된 참조: {sys.getrefcount(my_list) - 1}")

del another_ref # another_ref 참조 삭제
print(f"5. another_ref 삭제 후: {sys.getrefcount(my_list) - 1}")

del returned_ref # returned_ref 참조 삭제
print(f"6. returned_ref 삭제 후: {sys.getrefcount(my_list) - 1}")

# my_list 변수를 다른 값으로 재할당 (기존 리스트에 대한 참조 해제)
my_list = None
# 이 시점에서 기존 [1,2,3] 리스트의 참조 카운트는 0이 되어 메모리에서 해제됩니다.
print(f"7. my_list에 None 할당 후: (더 이상 my_list가 기존 객체를 참조하지 않음)")
```

**실행 결과 예시:**
```
1. 초기 my_list 참조 카운트: 1
2. another_ref 할당 후: 2
3. 함수 인자로 전달 후: 3
4. 함수에서 리턴된 참조: 3
5. another_ref 삭제 후: 2
6. returned_ref 삭제 후: 1
7. my_list에 None 할당 후: (더 이상 my_list가 기존 객체를 참조하지 않음)
```
이처럼 참조 카운트는 직관적이고 효율적입니다. 객체가 더 이상 사용되지 않을 때 즉시 메모리를 회수하여 메모리 단편화를 줄이고 프로그램의 성능을 향상시킵니다. 하지만 참조 카운트만으로는 해결할 수 없는 문제가 하나 있습니다.

## 3. 참조 카운트의 맹점: 순환 참조 (Circular References)

참조 카운트는 대부분의 상황에서 잘 작동하지만, 치명적인 약점이 있습니다. 바로 **순환 참조(Circular References)**입니다.

순환 참조는 두 개 이상의 객체가 서로를 참조하며 고리처럼 얽혀 있는 상황을 말합니다. 예를 들어, 객체 A가 객체 B를 참조하고, 객체 B가 다시 객체 A를 참조하는 경우입니다.

```python
class Node:
    def __init__(self, value):
        self.value = value
        self.next = None
        self.prev = None # 순환 참조를 위해 prev 속성을 추가

    def __del__(self):
        """객체가 소멸될 때 호출되는 메서드 (디스트럭터)"""
        print(f"Node {self.value}가 소멸되었습니다.")

# 순환 참조 발생 예시
print("--- 순환 참조 시작 ---")
node1 = Node(1)
node2 = Node(2)

node1.next = node2 # node1 -> node2
node2.prev = node1 # node2 -> node1

# 이 시점에서:
# node1의 참조 카운트: (node1 변수) + (node2.prev) = 2
# node2의 참조 카운트: (node2 변수) + (node1.next) = 2

print("외부 참조를 제거합니다...")
del node1
del node2

# 이제 node1과 node2 변수는 사라졌지만,
# node1 객체와 node2 객체는 서로를 참조하고 있기 때문에
# 각자의 참조 카운트가 1이 됩니다 (0이 되지 않습니다!).
# 따라서 __del__ 메서드가 호출되지 않고 메모리에 남아있게 됩니다.
print("외부 참조가 모두 사라졌지만, Node 객체들은 소멸되지 않았을 수 있습니다.")
print("--- 순환 참조 종료 ---")
```

**실행 결과 예시:**
```
--- 순환 참조 시작 ---
외부 참조를 제거합니다...
외부 참조가 모두 사라졌지만, Node 객체들은 소멸되지 않았을 수 있습니다.
--- 순환 참조 종료 ---
```
위 예시에서 `Node 1`과 `Node 2`는 서로를 참조하고 있으므로, `del node1`과 `del node2`를 해도 각 객체의 참조 카운트는 1로 남아있게 됩니다. 결과적으로 `__del__` 메서드가 호출되지 않으므로, 이 객체들은 메모리에서 해제되지 않고 **메모리 누수(Memory Leak)**로 이어집니다.

## 4. 핵심 메커니즘 2: 가비지 컬렉션 (Garbage Collection)

참조 카운트의 약점인 순환 참조를 해결하기 위해 파이썬은 **가비지 컬렉터(Garbage Collector)**를 사용합니다. 파이썬의 가비지 컬렉터는 주로 **세대별 가비지 컬렉션(Generational Garbage Collection)** 방식을 사용하며, `gc` 모듈을 통해 제어할 수 있습니다.

가비지 컬렉터의 역할은 다음과 같습니다:
1.  **순환 참조 탐지:** 참조 카운트가 0이 아니지만, 외부에서 더 이상 접근할 수 없는(고립된) 순환 참조 그룹을 찾아냅니다.
2.  **객체 회수:** 탐지된 순환 참조 그룹에 속한 객체들을 메모리에서 해제합니다.

파이썬의 가비지 컬렉터는 모든 객체를 검사하는 것이 아니라, 객체의 "수명"을 기준으로 세대(generation)를 나누어 관리합니다.
*   **세대 0 (Youngest):** 가장 최근에 생성된 객체들. 가장 자주 검사합니다.
*   **세대 1 (Middle):** 세대 0에서 살아남은 객체들. 덜 자주 검사합니다.
*   **세대 2 (Oldest):** 세대 1에서 살아남은 객체들. 가장 드물게 검사합니다.

새로운 객체는 세대 0에 할당되고, 가비지 컬렉션이 실행될 때마다 살아남은 객체들은 다음 세대로 이동합니다. 이는 대부분의 객체가 단명한다는 "약한 세대 가설(Generational Hypothesis)"에 기반한 효율적인 전략입니다.

`gc.collect()` 함수를 호출하여 가비지 컬렉터를 수동으로 실행할 수 있습니다.

```python
import gc

# 위의 Node 클래스 재사용 (__del__ 메서드 포함)
class Node:
    def __init__(self, value):
        self.value = value
        self.next = None
        self.prev = None

    def __del__(self):
        print(f"Node {self.value}가 소멸되었습니다.")

print("--- 가비지 컬렉션 예제 ---")
# 순환 참조를 생성합니다.
node_a = Node(10)
node_b = Node(20)

node_a.next = node_b
node_b.prev = node_a

# 외부 참조를 제거합니다.
# 이 시점에서 node_a와 node_b 객체는 서로 참조하고 있어 참조 카운트가 0이 되지 않습니다.
del node_a
del node_b

print("\n가비지 컬렉터 실행 전...")
# 아직 __del__이 호출되지 않았을 것입니다.

print("가비지 컬렉터 강제 실행...")
collected_count = gc.collect() # 가비지 컬렉터 강제 실행
print(f"{collected_count}개의 객체가 수거되었습니다.")
# 이제 Node 10, 20의 __del__이 호출되어 소멸됨을 확인할 수 있습니다.

print("--- 가비지 컬렉션 예제 종료 ---")
```

**실행 결과 예시:**
```
--- 가비지 컬렉션 예제 ---

가비지 컬렉터 실행 전...
가비지 컬렉터 강제 실행...
Node 10가 소멸되었습니다.
Node 20가 소멸되었습니다.
2개의 객체가 수거되었습니다.
--- 가비지 컬렉션 예제 종료 ---
```
`gc.collect()`를 호출하자마자 순환 참조로 인해 고립되었던 `Node 10`과 `Node 20` 객체가 소멸되는 것을 확인할 수 있습니다. 파이썬은 주기적으로 이 가비지 컬렉터를 자동으로 실행하여 메모리 누수를 방지합니다.

## 5. 메모리 풀 (Memory Pools) - 파이썬의 똑똑한 최적화

참조 카운트와 가비지 컬렉션 외에도, 파이썬(특히 CPython 구현)은 메모리 사용을 최적화하기 위해 **메모리 풀(Memory Pools)**이라는 기술을 사용합니다. 이는 작고 자주 사용되는 객체들(예: 작은 정수, 짧은 문자열)을 미리 할당해두거나 재사용하여 메모리 할당/해제 비용을 줄이는 방식입니다.

예를 들어, 파이썬은 일반적으로 -5부터 256까지의 정수 객체들을 미리 생성해두고 재사용합니다. 따라서 이 범위 내의 같은 값을 가진 정수들은 실제로 같은 메모리 주소를 가리킵니다.

```python
a = 10
b = 10
c = 300
d = 300

print(f"a = {a}, b = {b}")
print(f"a == b: {a == b}") # 값 비교
print(f"a is b: {a is b}") # 객체 ID(메모리 주소) 비교

print(f"\nc = {c}, d = {d}")
print(f"c == d: {c == d}")
print(f"c is d: {c is d}")
```

**실행 결과:**
```
a = 10, b = 10
a == b: True
a is b: True # -5 ~ 256 범위의 정수는 같은 객체를 참조

c = 300, d = 300
c == d: True
c is d: False # 256을 초과하는 정수는 매번 새로운 객체로 생성
```
`a is b`가 `True`인 반면 `c is d`는 `False`인 것을 볼 수 있습니다. 이는 작은 정수들이 미리 할당된 메모리 풀에서 재사용되기 때문입니다. 이런 최적화는 파이썬 애플리케이션의 성능을 향상시키는 데 기여합니다.

## 맺음말

오늘은 파이썬 메모리 관리의 두 가지 핵심 기둥인 **참조 카운트**와 **가비지 컬렉션**, 그리고 **메모리 풀**까지 깊이 있게 살펴보았습니다.

*   파이썬의 모든 것은 **객체**이며, 변수는 객체를 가리키는 **참조**입니다.
*   **참조 카운트**는 객체를 가리키는 참조의 개수를 세어 0이 되면 즉시 메모리에서 해제합니다.
*   **가비지 컬렉션**은 참조 카운트만으로는 해결할 수 없는 **순환 참조** 문제를 해결하기 위해 주기적으로 실행됩니다.
*   **메모리 풀**은 작고 자주 사용되는 객체를 미리 할당/재사용하여 성능을 최적화합니다.
