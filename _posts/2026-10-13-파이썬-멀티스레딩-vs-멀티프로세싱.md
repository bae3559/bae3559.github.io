# 파이썬 멀티스레딩 vs 멀티프로세싱: 개념부터 코드 예제까지 완벽 해부!

안녕하세요, 개발자 여러분! 바쁜 현대 사회처럼 우리 컴퓨터도 한 번에 여러 작업을 처리해야 할 때가 많습니다. 웹 서버는 수많은 요청을 동시에 처리해야 하고, 데이터 분석 프로그램은 방대한 양의 데이터를 빠르게 처리해야 하죠. 이럴 때 '동시성(Concurrency)'과 '병렬성(Parallelism)'이라는 개념이 중요해집니다.

파이썬에서 이런 동시성과 병렬성을 구현하는 대표적인 방법 두 가지가 바로 **멀티스레딩(Multithreading)**과 **멀티프로세싱(Multiprocessing)**입니다. 이름도 비슷하고 하는 일도 비슷해 보여서 많은 분들이 헷갈려 하시는데요, 오늘은 이 둘의 차이점을 개념부터 코드 예제까지 친절하게 파헤쳐 보겠습니다!

---

## 🚀 왜 동시성/병렬성이 필요할까요?

간단한 예시를 들어볼게요. 여러분이 점심 식사를 준비해야 한다고 가정해 봅시다.
*   밥을 짓고 (10분)
*   반찬을 만드는 (20분)
*   국을 끓이는 (15분)

이렇게 세 가지 작업을 순서대로 한다면 총 45분이라는 시간이 걸릴 겁니다. 하지만 만약 여러분이 밥솥에 밥을 앉혀놓고 (밥솥이 밥 짓는 동안 기다리지 않고!) 바로 반찬을 만들고, 동시에 국도 끓일 수 있다면 어떨까요? 훨씬 짧은 시간에 모든 식사 준비를 마칠 수 있겠죠?

컴퓨터 작업도 마찬가지입니다.
*   **I/O 바운드(I/O-Bound) 작업**: 파일 읽기/쓰기, 네트워크 요청처럼 CPU보다는 외부 장치의 응답을 기다리는 시간이 긴 작업.
*   **CPU 바운드(CPU-Bound) 작업**: 복잡한 계산, 이미지 처리, 암호화/복호화처럼 CPU 연산에 대부분의 시간을 소요하는 작업.

이런 작업들을 효율적으로 처리하기 위해 멀티스레딩과 멀티프로세싱을 사용합니다.

---

## 🧵 멀티스레딩 (Multithreading): GIL과 I/O 바운드 작업

### 개념 설명: "한 지붕 아래 여러 작업자"

멀티스레딩은 하나의 프로그램(프로세스) 내에서 여러 개의 `스레드(Thread)`를 동시에 실행하는 방식입니다. 여기서 스레드는 프로세스 내에서 실행되는 가장 작은 단위의 작업 흐름이라고 생각할 수 있습니다.

*   **메모리 공유**: 스레드들은 같은 프로세스 내에 존재하기 때문에 코드, 데이터, 힙(heap) 영역 등 **메모리를 서로 공유**합니다. 이는 스레드 간 데이터 교환이 쉽고 빠르다는 장점이 있지만, 동시에 여러 스레드가 같은 데이터를 수정하려 할 때 문제가 발생할 수 있어 동기화(Synchronization)가 필요합니다.
*   **가볍고 빠름**: 프로세스를 새로 생성하는 것보다 스레드를 생성하는 것이 훨씬 가볍고 빠릅니다.

여기까지만 들으면 멀티스레딩이 완벽한 해결책 같지만, 파이썬에는 **GIL(Global Interpreter Lock)**이라는 독특한 녀석이 있습니다.

### 파이썬의 GIL(Global Interpreter Lock)

GIL은 파이썬 인터프리터 자체에 걸려있는 잠금장치입니다. 무슨 일을 하든 **한 번에 오직 하나의 스레드만이 파이썬 바이트코드를 실행할 수 있도록 강제**합니다.

이게 무슨 말이냐고요? 여러분이 아무리 여러 개의 스레드를 만들어서 동시에 CPU를 사용하는 작업을 시키더라도, GIL 때문에 결국 한 번에 한 스레드만 실행되고 나머지 스레드는 대기하게 됩니다. 마치 한 명씩만 들어갈 수 있는 화장실 문 앞에서 여러 명이 줄 서서 기다리는 것과 비슷합니다.

**결론적으로, 파이썬의 멀티스레딩은 CPU-바운드 작업에서 '진정한 병렬 처리'를 제공하지 않습니다.**

그럼 멀티스레딩은 쓸모가 없을까요? 아닙니다! GIL은 파이썬 바이트코드 실행에만 관여합니다. 만약 스레드가 **I/O 작업(파일 읽기, 네트워크 요청 등)으로 인해 대기 상태**에 들어가면, 파이썬은 GIL을 놓아주고 다른 스레드가 실행될 수 있도록 합니다.

따라서 **멀티스레딩은 I/O-바운드 작업에서 성능 향상에 큰 도움**이 됩니다. 하나의 스레드가 네트워크 요청을 보내고 응답을 기다리는 동안, 다른 스레드가 다른 요청을 보내거나 다른 I/O 작업을 처리할 수 있기 때문이죠.

### 멀티스레딩 코드 예제 (I/O 바운드 작업)

두 개의 작업을 병렬로 실행하여 총 소요 시간을 단축하는 예시입니다. 여기서는 `time.sleep()`으로 네트워크 요청 대기 시간을 흉내 냈습니다.

```python
import threading
import time

def io_bound_task(name):
    """네트워크 요청과 같은 I/O 바운드 작업을 시뮬레이션합니다."""
    print(f"[{name}] 작업 시작...")
    time.sleep(2) # 2초 동안 대기 (I/O 작업이라고 가정)
    print(f"[{name}] 작업 완료!")

if __name__ == "__main__":
    start_time = time.time()

    # --- 순차 실행 (Multithreading X) ---
    print("--- 순차 실행 시작 ---")
    io_bound_task("순차-1")
    io_bound_task("순차-2")
    end_time = time.time()
    print(f"순차 실행 총 소요 시간: {end_time - start_time:.2f}초\n") # 약 4초

    # --- 멀티스레딩 실행 ---
    start_time = time.time()
    print("--- 멀티스레딩 실행 시작 ---")

    thread1 = threading.Thread(target=io_bound_task, args=("스레드-1",))
    thread2 = threading.Thread(target=io_bound_task, args=("스레드-2",))

    thread1.start() # 스레드 시작
    thread2.start() # 스레드 시작

    thread1.join() # 스레드 종료 대기
    thread2.join() # 스레드 종료 대기

    end_time = time.time()
    print(f"멀티스레딩 실행 총 소요 시간: {end_time - start_time:.2f}초") # 약 2초
```

**예상 결과:**
순차 실행 시 약 4초가 걸리던 작업이 멀티스레딩을 사용하면 약 2초 만에 완료되는 것을 볼 수 있습니다. 이는 한 스레드가 대기하는 동안 다른 스레드가 작업을 시작할 수 있었기 때문입니다.

## 🍽️ 멀티프로세싱 (Multiprocessing): 진정한 병렬 처리와 CPU 바운드 작업

### 개념 설명: "각자 다른 부엌에서 일하는 요리사들"

멀티프로세싱은 이름 그대로 여러 개의 `프로세스(Process)`를 동시에 실행하는 방식입니다. 운영체제 관점에서 프로세스는 완전히 독립적인 실행 단위입니다.

*   **메모리 독립**: 각 프로세스는 운영체제로부터 완전히 **독립된 메모리 공간**을 할당받습니다. 이는 프로세스 간에 데이터를 직접 공유할 수 없다는 의미입니다. 데이터를 공유하려면 파이프(Pipe), 큐(Queue), 공유 메모리(Shared Memory) 같은 특별한 IPC(Inter-Process Communication) 메커니즘을 사용해야 합니다.
*   **무겁고 느림**: 프로세스를 새로 생성하는 것은 스레드를 생성하는 것보다 훨씬 많은 자원을 소모하고 시간이 오래 걸립니다.
*   **GIL로부터 자유**: 가장 중요한 특징! 각 프로세스는 자신만의 파이썬 인터프리터와 GIL을 가지고 있습니다. 따라서 **각 프로세스는 독립적으로 CPU 코어를 사용하여 파이썬 코드를 실행할 수 있습니다.** 즉, GIL의 제약 없이 **진정한 병렬 처리**가 가능합니다.

이러한 특성 때문에 멀티프로세싱은 **CPU-바운드 작업에서 압도적인 성능 향상**을 보여줍니다. 컴퓨터에 여러 개의 CPU 코어가 있다면, 각 코어에 하나씩 프로세스를 할당하여 동시에 작업을 처리할 수 있습니다.

### 멀티프로세싱 코드 예제 (CPU 바운드 작업)

CPU 연산을 많이 소모하는 계산 작업을 병렬로 실행하여 총 소요 시간을 단축하는 예시입니다.

```python
import multiprocessing
import time
import math

def cpu_bound_task(name, num_iterations):
    """복잡한 계산과 같은 CPU 바운드 작업을 시뮬레이션합니다."""
    print(f"[{name}] 작업 시작...")
    result = 0
    for i in range(num_iterations):
        result += math.sqrt(i) * math.log(i + 1) # 복잡한 연산
    print(f"[{name}] 작업 완료! (결과 일부: {result:.2f})")

if __name__ == "__main__":
    iterations_per_task = 50_000_000 # 각 작업의 반복 횟수

    start_time = time.time()
    # --- 순차 실행 (Multiprocessing X) ---
    print("--- 순차 실행 시작 ---")
    cpu_bound_task("순차-1", iterations_per_task)
    cpu_bound_task("순차-2", iterations_per_task)
    end_time = time.time()
    print(f"순차 실행 총 소요 시간: {end_time - start_time:.2f}초\n") # 약 10초 내외 (CPU 성능에 따라 다름)

    # --- 멀티프로세싱 실행 ---
    start_time = time.time()
    print("--- 멀티프로세싱 실행 시작 ---")

    # multiprocessing.Process 사용 시에는 `if __name__ == "__main__":` 블록 안에 코드를 넣어야 합니다.
    # 이는 Windows 환경에서 프로세스가 올바르게 생성되도록 하는 데 특히 중요합니다.
    process1 = multiprocessing.Process(target=cpu_bound_task, args=("프로세스-1", iterations_per_task))
    process2 = multiprocessing.Process(target=cpu_bound_task, args=("프로세스-2", iterations_per_task))

    process1.start() # 프로세스 시작
    process2.start() # 프로세스 시작

    process1.join() # 프로세스 종료 대기
    process2.join() # 프로세스 종료 대기

    end_time = time.time()
    print(f"멀티프로세싱 실행 총 소요 시간: {end_time - start_time:.2f}초") # 약 5초 내외 (CPU 코어 수에 따라 다름)
```

**예상 결과:**
순차 실행 시 약 10초(예시)가 걸리던 작업이 멀티프로세싱을 사용하면 약 5초(예시) 만에 완료되는 것을 볼 수 있습니다. 이는 두 개의 프로세스가 CPU의 서로 다른 코어를 사용하여 **동시에** 계산 작업을 수행했기 때문입니다.

## 🧐 언제 무엇을 선택해야 할까요?

정리하자면,

| 특징            | 멀티스레딩 (Multithreading)               | 멀티프로세싱 (Multiprocessing)             |
| :-------------- | :---------------------------------------- | :--------------------------------------- |
| **메모리**      | 프로세스 내에서 공유                      | 각 프로세스가 독립적인 메모리 가짐       |
| **GIL 영향**    | CPU 바운드 작업에 GIL의 제약 있음         | GIL의 제약 없음 (각자 GIL 가짐)         |
| **생성 비용**   | 낮음 (가벼움)                             | 높음 (무거움)                            |
| **데이터 교환** | 쉬움 (직접 접근 가능, 동기화 필요)        | 어려움 (IPC 메커니즘 필요)               |
| **주요 사용처** | I/O-바운드 작업 (네트워크, 파일 입출력 등) | CPU-바운드 작업 (복잡한 계산, 데이터 처리 등) |
| **병렬성**      | `asyncio`와 같은 비동기 처리에 가까움     | 진정한 병렬 처리 가능                    |

### 현명한 선택 가이드

*   **대부분의 작업이 외부 응답을 기다리는 I/O-바운드 작업이라면?**
    *   **멀티스레딩**을 고려하세요. GIL 때문에 진정한 병렬성은 아니지만, 한 스레드가 대기하는 동안 다른 스레드가 작업을 진행하여 효율을 높일 수 있습니다. (하지만 파이썬 3.4부터는 I/O 바운드 작업에 더 최적화된 `asyncio` 라이브러리를 사용하는 것이 일반적입니다.)
*   **컴퓨터의 여러 CPU 코어를 활용하여 복잡한 계산을 빠르게 처리하고 싶다면?**
    *   **멀티프로세싱**을 사용하세요. 각 프로세스가 독립적인 파이썬 인터프리터를 가지고 있어 GIL의 제약 없이 진정한 병렬 처리가 가능합니다.

## 🌟 결론

파이썬에서 동시성과 병렬성을 다루는 멀티스레딩과 멀티프로세싱은 언뜻 비슷해 보이지만, 내부 동작 방식과 적합한 사용 시나리오가 명확히 다릅니다. 파이썬의 GIL이라는 특성을 이해하고, 여러분이 해결하고자 하는 문제가 I/O-바운드인지 CPU-바운드인지 정확히 파악하는 것이 중요합니다.

이제 여러분도 이 두 가지 강력한 도구를 적재적소에 활용하여 더 빠르고 효율적인 파이썬 프로그램을 만들 수 있을 것입니다. 직접 코드를 실행해보며 그 차이를 느껴보는 것이 가장 좋은 학습 방법이니, 꼭 한 번씩 시도해 보세요!
