# 투 포인터 기법 완전 정복: 효율적인 알고리즘의 비밀

안녕하세요! 효율적인 코드 작성을 즐기는 개발 블로그 작가입니다.
알고리즘 문제 풀이를 하다 보면 '어떻게 하면 이 코드를 더 빠르게 만들 수 있을까?' 고민해본 적 많으실 겁니다. 특히 이중 반복문(nested loops)을 사용하면 쉽게 풀리는 문제들도 많지만, 시간 복잡도가 O(n^2)로 늘어나면서 제한 시간을 초과하기 일쑤죠.

오늘 소개해드릴 **투 포인터(Two Pointers)** 기법은 바로 이런 상황에서 빛을 발하는 강력한 기술입니다. 배열이나 리스트와 같은 선형 자료구조에서 특정 조건을 만족하는 부분을 찾을 때, 이 기법을 활용하면 시간 복잡도를 O(n^2)에서 O(n)으로 획기적으로 줄일 수 있습니다. 마치 마법처럼요!

초보자분들도 쉽게 이해할 수 있도록 친절하게 설명해 드릴 테니, 저와 함께 투 포인터의 세계로 떠나볼까요?

---

## 🚀 투 포인터(Two Pointers)란 무엇인가요?

이름 그대로 **두 개의 포인터(인덱스)**를 사용하여 데이터를 탐색하는 알고리즘 기법입니다. 여기서 '포인터'는 보통 배열의 인덱스를 의미하며, 이 두 인덱스를 움직여가며 원하는 조건을 만족하는 구간이나 값을 찾아냅니다.

왜 두 개를 쓸까요? 하나의 포인터로 전체를 탐색하는 것보다, 두 개의 포인터가 서로 다른 역할 또는 다른 방향으로 움직이면서 불필요한 탐색을 줄이고, 중복 계산을 피할 수 있기 때문입니다.

### ✨ 투 포인터의 주요 활용 시나리오

투 포인터는 주로 다음과 같은 상황에서 유용하게 사용됩니다:

1.  **정렬된 배열에서 특정 조건을 만족하는 쌍 찾기**: 합이 특정 값이 되는 두 수 찾기, 특정 구간의 합 구하기 등
2.  **배열의 특정 부분(sub-array) 탐색**: 슬라이딩 윈도우(Sliding Window) 기법과 연관되기도 합니다.
3.  **연결 리스트(Linked List) 문제**: 중간 노드 찾기, 사이클 감지 등
4.  **회문(Palindrome) 검사**: 문자열이 앞뒤로 같은지 확인
5.  **중복 제거**: 정렬된 배열에서 중복 요소를 효율적으로 제거

### ✌️ 투 포인터의 두 가지 주요 유형

투 포인터는 크게 두 가지 움직임 패턴으로 나눌 수 있습니다.

1.  **서로 다른 방향으로 움직이는 포인터 (Opposite-Direction Pointers)**:
    *   하나의 포인터는 배열의 시작점에서, 다른 하나는 끝점에서 시작하여 서로를 향해 움직입니다.
    *   주로 정렬된 배열에서 두 요소의 합, 차이, 곱 등이 특정 조건을 만족하는 경우에 사용됩니다.
    *   예: 합이 target인 두 수 찾기, 회문 판별

2.  **같은 방향으로 움직이는 포인터 (Same-Direction Pointers)**:
    *   두 포인터 모두 배열의 시작점(또는 근처)에서 시작하여 같은 방향(주로 오른쪽)으로 움직입니다.
    *   하나는 '느린 포인터(slow pointer)' 역할을, 다른 하나는 '빠른 포인터(fast pointer)' 역할을 하기도 합니다.
    *   주로 중복 요소 제거, 특정 조건 만족하는 부분 배열 찾기(슬라이딩 윈도우), 연결 리스트의 사이클 감지 등에 사용됩니다.

## 🧑‍💻 코드 예제로 배우는 투 포인터

이제 실제 코드를 통해 투 포인터 기법을 자세히 알아보겠습니다.

### 예제 1: 정렬된 배열에서 합이 특정 값(Target Sum)이 되는 두 수 찾기 (Opposite-Direction Pointers)

**문제**: 정렬된(오름차순) 배열 `nums`와 정수 `target`이 주어졌을 때, 배열에서 두 요소를 더하여 `target`이 되는 쌍이 있는지 확인하는 함수를 작성하세요.

**Brute-Force (비효율적인 방법)**: 이중 반복문을 사용하면 모든 가능한 쌍을 확인하여 `O(n^2)`의 시간 복잡도를 가집니다.

```python
def find_sum_pair_brute_force(nums, target):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return True # 찾음
    return False # 못 찾음

# 예시
print(find_sum_pair_brute_force([1, 2, 3, 4, 5], 7)) # True
print(find_sum_pair_brute_force([1, 2, 3, 4, 5], 10)) # False
```

**투 포인터 (효율적인 방법)**:
배열이 정렬되어 있다는 중요한 힌트가 있습니다! 이 힌트를 이용해 투 포인터를 사용하면 `O(n)`으로 해결할 수 있습니다.

1.  `left` 포인터를 배열의 가장 왼쪽(인덱스 0)에 둡니다.
2.  `right` 포인터를 배열의 가장 오른쪽(인덱스 `len(nums) - 1`)에 둡니다.
3.  `left`가 `right`보다 작을 때까지 반복합니다.
    *   현재 `left`와 `right`가 가리키는 요소의 합(`current_sum = nums[left] + nums[right]`)을 계산합니다.
    *   만약 `current_sum`이 `target`과 같다면, 우리가 원하는 쌍을 찾았으므로 `True`를 반환합니다.
    *   만약 `current_sum`이 `target`보다 작다면, 합을 더 크게 만들어야 합니다. 배열이 정렬되어 있으므로 `left`를 오른쪽으로 한 칸 이동(`left += 1`)시켜 더 큰 숫자를 더합니다.
    *   만약 `current_sum`이 `target`보다 크다면, 합을 더 작게 만들어야 합니다. 마찬가지로 `right`를 왼쪽으로 한 칸 이동(`right -= 1`)시켜 더 작은 숫자를 더합니다.
4.  반복문이 종료될 때까지 찾지 못했다면 `False`를 반환합니다.

```python
def find_sum_pair_two_pointers(nums, target):
    left = 0
    right = len(nums) - 1

    while left < right:
        current_sum = nums[left] + nums[right]

        if current_sum == target:
            return True  # 합이 target과 같으면 찾음!
        elif current_sum < target:
            left += 1  # 합이 target보다 작으면, left를 오른쪽으로 옮겨 합을 증가
        else: # current_sum > target
            right -= 1 # 합이 target보다 크면, right를 왼쪽으로 옮겨 합을 감소
    
    return False # 루프가 끝날 때까지 못 찾음

# 예시
print(f"배열 [1, 2, 3, 4, 5]에서 합이 7인 쌍: {find_sum_pair_two_pointers([1, 2, 3, 4, 5], 7)}")   # True
print(f"배열 [1, 2, 3, 4, 5]에서 합이 10인 쌍: {find_sum_pair_two_pointers([1, 2, 3, 4, 5], 10)}") # False
print(f"배열 [2, 7, 11, 15]에서 합이 9인 쌍: {find_sum_pair_two_pointers([2, 7, 11, 15], 9)}")   # True (2 + 7)
print(f"배열 [1, 3, 5, 8, 12]에서 합이 13인 쌍: {find_sum_pair_two_pointers([1, 3, 5, 8, 12], 13)}") # True (1 + 12 또는 5 + 8)
```

**설명**:
이 방법은 `left`와 `right` 포인터가 한 번씩만 배열을 훑고 지나가므로, `O(n)`의 시간 복잡도를 가집니다. `target`과의 비교를 통해 다음 탐색 범위를 좁히는 것이 핵심입니다.

### 예제 2: 정렬된 배열에서 중복 제거 (Same-Direction Pointers)

**문제**: 정렬된 배열 `nums`가 주어졌을 때, 각 요소가 한 번만 나타나도록 중복을 제거하고, 새로운 배열의 길이를 반환하세요. 이 때, 추가적인 공간(배열)을 사용하지 않고 제자리(in-place)에서 수정해야 합니다.

**투 포인터 (효율적인 방법)**:
`i` (느린 포인터)와 `j` (빠른 포인터) 두 개를 사용합니다. `i`는 중복이 제거된 배열의 마지막 유니크한 요소의 위치를 가리키고, `j`는 배열 전체를 순회하며 새로운 유니크한 요소를 탐색합니다.

1.  배열이 비어있다면 0을 반환합니다.
2.  `i` 포인터를 0으로 초기화합니다 (첫 번째 요소는 항상 유니크하다고 가정).
3.  `j` 포인터를 1부터 배열의 끝까지 순회합니다.
4.  `nums[j]`가 `nums[i]`와 다르다면, `nums[j]`는 새로운 유니크한 요소입니다.
    *   `i`를 한 칸 앞으로 이동(`i += 1`).
    *   `nums[i]`에 `nums[j]` 값을 복사합니다. (중복이 제거된 새 배열의 다음 위치에 유니크한 값 저장)
5.  `nums[j]`가 `nums[i]`와 같다면, `nums[j]`는 중복된 요소이므로 아무것도 하지 않고 `j`만 다음 칸으로 이동시킵니다.
6.  `j`가 배열의 끝에 도달하면 반복을 멈춥니다.
7.  `i + 1`이 중복이 제거된 배열의 새로운 길이가 됩니다.

```python
def remove_duplicates(nums):
    if not nums: # 배열이 비어있는 경우
        return 0

    i = 0 # '느린' 포인터: 중복이 제거된 배열의 다음 유니크한 요소가 들어갈 위치
    # nums[0...i]는 중복이 없는 요소들로 채워진다.

    for j in range(1, len(nums)): # '빠른' 포인터: 배열의 모든 요소를 순회
        # 현재 j가 가리키는 값(nums[j])이 i가 가리키는 값(nums[i])과 다르면
        # nums[j]는 새로운 유니크한 값이다.
        if nums[j] != nums[i]:
            i += 1 # 느린 포인터를 한 칸 전진
            nums[i] = nums[j] # 새로운 유니크한 값을 i 위치에 저장
    
    # 중복 제거 후의 배열 길이는 i + 1 이다. (0부터 시작하므로)
    return i + 1

# 예시
nums1 = [1, 1, 2]
new_length1 = remove_duplicates(nums1)
print(f"원본: [1, 1, 2] -> 새 길이: {new_length1}, 배열: {nums1[:new_length1]}") # 출력: 새 길이: 2, 배열: [1, 2]

nums2 = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]
new_length2 = remove_duplicates(nums2)
print(f"원본: [0, 0, 1, 1, 1, 2, 2, 3, 3, 4] -> 새 길이: {new_length2}, 배열: {nums2[:new_length2]}") # 출력: 새 길이: 5, 배열: [0, 1, 2, 3, 4]
```

**설명**:
이 기법은 `j` 포인터가 배열을 한 번 순회하고, `i` 포인터도 최대 한 번 순회하므로, `O(n)`의 시간 복잡도를 가집니다. 추가적인 공간 없이 제자리에서 작업을 수행하므로 공간 복잡도는 `O(1)`입니다. 이는 메모리 사용량 측면에서도 매우 효율적입니다.

## 🧐 언제 투 포인터 기법을 고려해야 할까요?

*   **선형 자료구조 (배열, 리스트, 연결 리스트)를 다룰 때**: 특히 정렬된 배열에서 빛을 발합니다.
*   **부분 배열/부분 문자열 또는 특정 조건을 만족하는 쌍을 찾아야 할 때**.
*   **이중 반복문을 줄여 시간 복잡도를 개선하고 싶을 때**.
*   **추가적인 공간 사용 없이(in-place) 문제를 해결해야 할 때**.

투 포인터는 문제를 어떻게 바라보고 해결해야 할지에 대한 '사고방식'입니다. 단순히 두 개의 인덱스를 사용하는 것을 넘어, 이들을 어떤 역할로 움직이게 할 것인지를 고민하는 것이 중요합니다.
