# 슬라이딩 윈도우(Sliding Window): 효율적인 부분 배열/문자열 탐색의 비밀

안녕하세요! 효율적인 코드 작성을 즐기는 개발 블로거입니다. 오늘은 코딩 테스트나 알고리즘 문제를 풀 때 빛을 발하는 아주 유용한 기법, 바로 '슬라이딩 윈도우(Sliding Window)'에 대해 이야기해보려 합니다. 이름만 들으면 어려울 것 같지만, 개념을 이해하고 나면 "아! 이렇게 간단하고 효율적이라니!" 하고 무릎을 탁 치게 될 거예요. 초보자분들도 쉽게 이해할 수 있도록 친절하게 설명해 드릴게요!

---

## 🤷‍♀️ 슬라이딩 윈도우, 왜 필요할까요?

여러분은 혹시 이런 문제를 마주친 적이 있으신가요?

*   "주어진 긴 문자열에서, 특정 길이를 가진 부분 문자열 중 가장 많이 반복되는 문자를 찾아라."
*   "배열에서 특정 `K` 길이의 부분 배열(subarray) 중 합이 가장 큰 것을 찾아라."
*   "연속된 숫자들로 이루어진 부분 배열 중, 특정 조건을 만족하는 가장 짧은 길이를 찾아라."

이런 문제들의 공통점은 바로 '연속된 부분(contiguous part)'을 다룬다는 것입니다. 만약 이 문제를 무작정 푼다면, 모든 가능한 부분 배열이나 부분 문자열을 일일이 만들어서 확인해야 할 거예요. 예를 들어, 길이가 `N`인 배열에서 길이 `K`의 모든 부분 배열을 찾는다고 가정해 봅시다. `N-K+1`개의 부분 배열이 있고, 각각의 합을 구하려면 `K`번의 연산이 필요하므로 총 `O(N*K)`의 시간 복잡도를 가집니다. `N`이 커질수록 어마어마하게 느려지겠죠?

바로 이때, 슬라이딩 윈도우 기법이 등장하여 이 문제를 아주 우아하고 효율적으로 해결해줍니다.

---

## 🖼️ 슬라이딩 윈도우란 무엇일까요?

슬라이딩 윈도우는 이름 그대로, '창문(Window)'이 데이터 위를 '미끄러지듯이(Sliding)' 이동하면서 문제를 해결하는 알고리즘 기법입니다.

*   **창문 (Window):** 배열이나 문자열 같은 순회 가능한(iterable) 데이터 구조에서, 고정되거나 유동적인 크기의 '부분(segment)'을 의미합니다. 마치 기차 창문 밖으로 풍경이 바뀌어 보이듯이, 이 창문이 이동하면서 데이터를 탐색합니다.
*   **슬라이딩 (Sliding):** 이 창문이 한 칸씩 오른쪽(또는 왼쪽)으로 이동하는 것을 의미합니다. 중요한 점은 창문이 이동할 때마다 모든 것을 새로 계산하는 것이 아니라, 창문에서 나가는 값은 제거하고 새로 들어오는 값만 추가하여 기존 정보를 효율적으로 '업데이트'한다는 것입니다.

이 기법을 사용하면 매번 처음부터 다시 계산할 필요 없이, `O(N)` 또는 `O(N log N)`과 같은 훨씬 더 효율적인 시간 복잡도로 문제를 해결할 수 있습니다.

**핵심 아이디어:**
1.  **초기 윈도우 설정:** 처음에 특정 크기(K)의 윈도우를 설정하고 필요한 계산을 수행합니다.
2.  **윈도우 슬라이딩:** 윈도우를 한 칸 오른쪽으로 옮길 때,
    *   가장 왼쪽에 있는 요소를 윈도우에서 '제거'합니다.
    *   새로 윈도우에 들어오는 가장 오른쪽에 있는 요소를 '추가'합니다.
    *   이전 윈도우의 계산 결과를 바탕으로 새로운 윈도우의 결과를 효율적으로 업데이트합니다.

---

## 🔍 슬라이딩 윈도우는 언제 사용할까요?

가장 중요한 특징은 **'연속된 부분(contiguous subarray/substring)'**을 다룰 때 사용된다는 점입니다. 주로 다음과 같은 유형의 문제에서 강력한 성능을 발휘합니다.

*   **고정 크기 윈도우 (Fixed-size Window):**
    *   길이 `K`의 부분 배열/문자열 중 최대/최소 합/평균 찾기
    *   길이 `K`의 부분 문자열 중 특정 조건을 만족하는 것 찾기
*   **가변 크기 윈도우 (Variable-size Window):** (오늘 다룰 예제는 고정 크기에 초점을 맞추지만, 이 경우도 응용 가능합니다.)
    *   특정 조건을 만족하는 가장 짧은/가장 긴 부분 배열/문자열 찾기
    *   중복 문자가 없는 가장 긴 부분 문자열 찾기

## 🧑‍💻 슬라이딩 윈도우 코드 예제 (고정 크기 윈도우)

가장 기본적인 예제를 통해 슬라이딩 윈도우 기법이 어떻게 동작하는지 알아보겠습니다.

**문제:** 주어진 배열(정수 리스트)에서, 특정 길이 `K`를 갖는 부분 배열(Subarray)들의 합 중 최댓값을 찾아보세요.

**예시:** `arr = [1, 4, 2, 10, 2, 3, 1, 0, 20]`, `K = 3`
가능한 길이 3의 부분 배열은 다음과 같습니다:
*   `[1, 4, 2]` -> 합: 7
*   `[4, 2, 10]` -> 합: 16
*   `[2, 10, 2]` -> 합: 14
*   `[10, 2, 3]` -> 합: 15
*   `[2, 3, 1]` -> 합: 6
*   `[3, 1, 0]` -> 합: 4
*   `[1, 0, 20]` -> 합: 21
최대 합은 21입니다.

### Python 코드

```python
def max_subarray_sum_sliding_window(arr, k):
    """
    슬라이딩 윈도우 기법을 사용하여 주어진 배열에서 길이 K인 부분 배열의 최대 합을 찾습니다.

    Args:
        arr (list): 정수로 이루어진 배열.
        k (int): 부분 배열의 길이.

    Returns:
        int: 길이 K인 부분 배열들의 합 중 최댓값.
             유효하지 않은 입력 시 0을 반환.
    """
    # 1. 예외 처리: 배열이 비어있거나 K가 유효하지 않은 경우
    if not arr or k <= 0 or k > len(arr):
        return 0

    window_sum = 0
    
    # 2. 첫 번째 윈도우의 합을 계산 (초기 윈도우 설정)
    # 인덱스 0부터 k-1까지의 합을 구합니다.
    for i in range(k):
        window_sum += arr[i]

    # 현재까지의 최대 합을 첫 번째 윈도우의 합으로 초기화
    max_sum = window_sum

    # 3. 윈도우를 한 칸씩 오른쪽으로 이동 (슬라이딩)
    # right 포인터는 k부터 배열의 끝까지 이동합니다.
    # arr[right]는 새로 윈도우에 들어오는 값입니다.
    # arr[right - k]는 윈도우에서 나가는(가장 왼쪽) 값입니다.
    for right in range(k, len(arr)):
        # 윈도우의 합을 효율적으로 업데이트:
        # 새로 들어오는 값을 더하고, 나가는 값을 뺍니다.
        window_sum += arr[right] - arr[right - k]
        
        # 현재 윈도우의 합과 이전까지의 최대 합을 비교하여 갱신
        max_sum = max(max_sum, window_sum)

    return max_sum

# --- 예제 실행 ---
my_array = [1, 4, 2, 10, 2, 3, 1, 0, 20]
k_value = 3
result = max_subarray_sum_sliding_window(my_array, k_value)
print(f"배열 {my_array}에서 길이 {k_value}인 부분 배열의 최대 합: {result}") # 예상 출력: 21

my_array2 = [1, 2, 3, 4, 5]
k_value2 = 2
result2 = max_subarray_sum_sliding_window(my_array2, k_value2)
print(f"배열 {my_array2}에서 길이 {k_value2}인 부분 배열의 최대 합: {result2}") # 예상 출력: 9
```

### 코드 설명

1.  **초기화 (`if not arr or k <= 0 or k > len(arr)`):**
    *   코드의 안정성을 위해 유효하지 않은 입력(배열이 비었거나 `K`가 0 이하, 또는 배열 길이보다 긴 경우)을 먼저 처리합니다.
2.  **첫 번째 윈도우 합 계산 (`for i in range(k): ...`):**
    *   `window_sum` 변수에 배열의 첫 `K`개 요소(`arr[0]`부터 `arr[k-1]`)의 합을 저장합니다. 이것이 초기 윈도우의 합이 됩니다.
    *   `max_sum`을 이 `window_sum`으로 초기화하여, 현재까지 찾은 최대 합을 추적합니다.
3.  **윈도우 슬라이딩 (`for right in range(k, len(arr)): ...`):**
    *   `right` 포인터는 `k`부터 시작하여 배열의 끝까지 이동합니다. 이는 현재 윈도우의 "새로 들어올" 가장 오른쪽 요소를 가리킵니다.
    *   **핵심 로직 (`window_sum += arr[right] - arr[right - k]`):**
        *   `arr[right]`를 `window_sum`에 더합니다. 이것은 윈도우가 한 칸 오른쪽으로 이동하면서 새로 포함되는 값입니다.
        *   `arr[right - k]`를 `window_sum`에서 뺍니다. `right - k`는 현재 윈도우에서 가장 왼쪽의 값, 즉 윈도우 밖으로 나가는 값의 인덱스입니다.
        *   이 연산을 통해 매번 `K`개의 요소를 다시 더하는 대신, 단 두 번의 연산(덧셈, 뺄셈)으로 윈도우 합을 업데이트합니다.
    *   **최대 합 갱신 (`max_sum = max(max_sum, window_sum)`):**
        *   윈도우가 한 칸 이동할 때마다 새로운 `window_sum`이 계산되는데, 이 값이 `max_sum`보다 크면 `max_sum`을 갱신합니다.
4.  **결과 반환 (`return max_sum`):**
    *   모든 윈도우를 탐색한 후, 최종적으로 `max_sum`에 저장된 값이 배열 내에서 길이 `K`인 부분 배열들의 최대 합이 됩니다.

이 슬라이딩 윈도우 기법은 배열을 한 번만 순회하므로, 시간 복잡도는 `O(N)`이 됩니다. `O(N*K)`와 비교했을 때 훨씬 효율적이죠!
