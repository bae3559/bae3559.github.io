# 복잡한 작업의 순서를 우아하게 정리: 위상 정렬 개념과 파이썬 구현

안녕하세요, 여러분! 개발자라면 한 번쯤 "이 작업은 저 작업이 끝나야 시작할 수 있는데...", "저 패키지는 이 패키지에 의존성이 있는데..." 같은 고민을 해보셨을 겁니다. 복잡한 의존 관계를 가진 여러 작업들의 순서를 결정해야 할 때, 이 문제를 우아하게 해결해주는 멋진 알고리즘이 있습니다. 바로 **위상 정렬(Topological Sort)**입니다.

오늘은 위상 정렬이 무엇인지, 왜 필요한지, 그리고 파이썬으로 어떻게 구현하는지 초보자분들도 쉽게 이해할 수 있도록 친절하게 설명해 드릴게요.

---

## 1. 위상 정렬(Topological Sort)이란 무엇일까요?

간단히 말해, 위상 정렬은 **방향성이 있는 그래프(Directed Graph)에 존재하는 노드들의 순서를 나열하는 방법**입니다. 단, 이때 중요한 조건이 있습니다. 바로 **"간선 U → V가 존재하면, U는 반드시 V보다 먼저 나와야 한다"**는 규칙을 지키면서 모든 노드를 순서대로 나열하는 것이죠.

하지만 모든 방향 그래프에서 위상 정렬을 할 수 있는 것은 아닙니다. 위상 정렬은 **사이클이 없는 방향 그래프(Directed Acyclic Graph, DAG)**에서만 유효합니다. 만약 그래프에 사이클이 존재한다면, 예를 들어 A → B → C → A 와 같은 관계라면, A를 B보다 먼저, B를 C보다 먼저, C를 다시 A보다 먼저 두는 순서는 존재할 수 없기 때문입니다.

**예시:**

여러분이 아침에 회사에 가기 위한 일련의 과정을 생각해봅시다.
- 일어나기 → 씻기
- 씻기 → 옷 입기
- 옷 입기 → 아침 식사
- 아침 식사 → 출근

이 과정을 그래프로 표현하면 다음과 같습니다.
`일어나기 → 씻기 → 옷 입기 → 아침 식사 → 출근`
이것이 바로 위상 정렬의 한 예시가 될 수 있습니다. 각 활동은 그 이전 활동이 끝나야 시작할 수 있죠.

---

## 2. 위상 정렬은 왜 필요할까요? (사용 사례)

위상 정렬은 생각보다 우리 주변의 많은 문제들을 해결하는 데 사용됩니다.

*   **빌드 시스템 (Makefiles, Gradle 등):** 프로젝트를 빌드할 때, 어떤 파일은 다른 파일이 컴파일되어야만 컴파일될 수 있습니다. 위상 정렬은 이런 의존 관계를 파악하여 올바른 빌드 순서를 결정합니다.
*   **패키지 관리자 (npm, pip, apt 등):** 새로운 라이브러리를 설치할 때, 해당 라이브러리가 의존하는 다른 라이브러리들이 먼저 설치되어야 합니다. 위상 정렬이 설치 순서를 결정합니다.
*   **컴파일러 스케줄링:** 여러 작업 간의 데이터 의존성을 고려하여 작업 실행 순서를 최적화합니다.
*   **학사 일정 또는 프로젝트 계획:** 선수 과목이 있는 강의의 수강 순서나, 선행 작업이 필요한 프로젝트의 태스크 순서를 정할 때 활용됩니다.

## 3. 위상 정렬 알고리즘: Kahn's Algorithm (BFS 기반)

위상 정렬을 구현하는 방법은 크게 두 가지가 있습니다. DFS(깊이 우선 탐색) 기반과 BFS(너비 우선 탐색) 기반이죠. 여기서는 초보자분들이 더 직관적으로 이해하기 쉬운 **Kahn's Algorithm (칸의 알고리즘)**이라는 BFS 기반 접근 방식을 설명하고 구현해 보겠습니다.

Kahn's Algorithm의 핵심 아이디어는 다음과 같습니다.

1.  **진입 차수(In-degree) 계산:** 모든 노드에 대해, 자신에게 들어오는 간선의 개수(진입 차수)를 계산합니다.
2.  **진입 차수가 0인 노드를 큐에 추가:** 위상 정렬의 첫 번째 노드는 항상 진입 차수가 0이어야 합니다. 즉, 어떤 선행 조건도 없는 노드들입니다. 이 노드들을 큐(Queue)에 넣습니다.
3.  **큐에서 노드를 꺼내고 인접 노드의 진입 차수 감소:**
    *   큐에서 노드 `U`를 하나 꺼내 위상 정렬 결과 리스트에 추가합니다.
    *   `U`에서 나가는 모든 간선 (`U` → `V`)에 대해, `V`의 진입 차수를 1 감소시킵니다.
    *   만약 `V`의 진입 차수가 0이 되면, `V`를 큐에 추가합니다.
4.  **반복:** 큐가 빌 때까지 3번 과정을 반복합니다.
5.  **사이클 확인:** 만약 위상 정렬 결과에 포함된 노드의 개수가 전체 노드의 개수보다 적다면, 그래프에 사이클이 존재한다는 의미입니다.

---

## 4. 파이썬으로 위상 정렬 구현하기 (Kahn's Algorithm)

이제 위에서 설명한 Kahn's Algorithm을 파이썬 코드로 구현해 보겠습니다.

```python
from collections import deque

def topological_sort(graph):
    """
    Kahn's Algorithm을 사용하여 위상 정렬을 수행합니다.
    :param graph: 인접 리스트 형태의 그래프 {노드: [인접 노드1, 인접 노드2, ...]}
    :return: 위상 정렬된 노드 리스트 또는 사이클이 있다면 빈 리스트
    """
    
    # 1. 모든 노드의 진입 차수(In-degree)를 계산합니다.
    in_degree = {node: 0 for node in graph} # 모든 노드를 일단 0으로 초기화
    
    # 그래프를 순회하며 실제 진입 차수를 계산합니다.
    for node in graph:
        for neighbor in graph[node]:
            # 만약 이웃 노드가 in_degree 맵에 없으면 추가 (새로운 노드 발견)
            if neighbor not in in_degree:
                in_degree[neighbor] = 0
            in_degree[neighbor] += 1
            
    # 모든 노드를 다시 한 번 확인하여 in_degree에 없는 노드를 추가 (간선이 없는 독립 노드)
    # (graph 딕셔너리의 키로만 그래프를 표현하는 경우, 진출 차수만 있는 노드는 누락될 수 있음)
    all_nodes = set(graph.keys()).union(set(n for neighbors in graph.values() for n in neighbors))
    for node in all_nodes:
        if node not in in_degree:
            in_degree[node] = 0
            
    
    # 2. 진입 차수가 0인 노드들을 큐에 추가합니다.
    queue = deque()
    for node in in_degree:
        if in_degree[node] == 0:
            queue.append(node)
            
    # 3. 위상 정렬 결과를 저장할 리스트를 초기화합니다.
    result = []
    
    # 4. 큐가 빌 때까지 반복합니다.
    while queue:
        current_node = queue.popleft() # 큐에서 노드를 하나 꺼냅니다.
        result.append(current_node)    # 결과 리스트에 추가합니다.
        
        # 현재 노드에서 나가는 모든 간선(이웃 노드)에 대해 처리합니다.
        # graph[current_node]가 존재하지 않을 수도 있으므로 get()으로 안전하게 접근
        for neighbor in graph.get(current_node, []): 
            in_degree[neighbor] -= 1 # 이웃 노드의 진입 차수를 1 감소시킵니다.
            
            # 진입 차수가 0이 된 이웃 노드를 큐에 추가합니다.
            if in_degree[neighbor] == 0:
                queue.append(neighbor)
                
    # 5. 사이클 확인: 결과 리스트의 길이가 전체 노드의 개수와 다르면 사이클이 존재합니다.
    if len(result) == len(in_degree): # len(in_degree)는 모든 노드의 개수를 나타냄
        return result
    else:
        print("그래프에 사이클이 존재하여 위상 정렬을 수행할 수 없습니다.")
        return []

# --- 예시 사용 ---
if __name__ == "__main__":
    # 예시 1: 기본적인 작업 의존성 (사이클 없음)
    # 0: 일찍 일어나기
    # 1: 씻기
    # 2: 옷 입기
    # 3: 아침 식사
    # 4: 출근
    # 5: 뉴스 보기 (씻기 후에 가능)
    # 6: 커피 마시기 (아침 식사 후에 가능)
    
    graph1 = {
        0: [1],
        1: [2, 5],
        2: [3],
        3: [4, 6],
        5: [6], # 뉴스 보고 커피 마셔도 됨 (아침 식사랑은 무관하게)
        6: [4]  # 커피 마시고 출근
    }
    
    print("--- 예시 1: 기본적인 작업 의존성 ---")
    sorted_tasks1 = topological_sort(graph1)
    if sorted_tasks1:
        print("위상 정렬 결과:", sorted_tasks1) # 예: [0, 1, 2, 5, 3, 6, 4] 또는 [0, 1, 5, 2, 3, 6, 4] 등
    print("-" * 30)

    # 예시 2: 사이클이 있는 경우
    # A -> B
    # B -> C
    # C -> A (사이클 발생)
    graph2 = {
        'A': ['B'],
        'B': ['C'],
        'C': ['A']
    }
    
    print("--- 예시 2: 사이클이 있는 그래프 ---")
    sorted_tasks2 = topological_sort(graph2)
    if sorted_tasks2:
        print("위상 정렬 결과:", sorted_tasks2)
    print("-" * 30)

    # 예시 3: 고립된 노드가 있는 경우
    # 0 -> 1
    # 2 -> 3
    # 4 (고립된 노드)
    graph3 = {
        0: [1],
        2: [3],
        4: [] # 4는 아무데도 연결되지 않음
    }
    # in_degree에 모든 노드를 포함시키기 위해 all_nodes를 사용해야 함
    
    print("--- 예시 3: 고립된 노드가 있는 그래프 ---")
    sorted_tasks3 = topological_sort(graph3)
    if sorted_tasks3:
        print("위상 정렬 결과:", sorted_tasks3) # 예: [0, 2, 4, 1, 3] 또는 [4, 0, 2, 1, 3] 등
    print("-" * 30)
```

**코드 설명:**

1.  **`collections.deque` 임포트:** 큐(Queue) 자료구조를 효율적으로 사용하기 위해 `deque`를 사용합니다.
2.  **`in_degree` 딕셔너리 초기화:** 각 노드의 진입 차수를 저장하는 딕셔너리입니다. `graph`에 존재하는 모든 노드와 그 이웃 노드들을 포함시켜야 합니다.
3.  **진입 차수 계산:** 그래프를 한 번 순회하면서 각 노드의 진입 차수를 정확하게 계산합니다. `all_nodes`를 사용하여 그래프에 명시적으로 연결되지 않은 노드들도 `in_degree`에 포함되도록 합니다.
4.  **큐 초기화:** 진입 차수가 0인 노드들(선행 작업이 없는 노드들)을 `deque`에 추가합니다.
5.  **메인 루프:**
    *   큐에서 노드를 하나 꺼내 `result` 리스트에 추가합니다.
    *   꺼낸 노드 `current_node`의 모든 이웃 노드들에 대해 진입 차수를 1 감소시킵니다.
    *   만약 이웃 노드의 진입 차수가 0이 되면, 이 노드도 이제 선행 작업이 완료된 것이므로 큐에 추가합니다.
6.  **사이클 검출:** 최종 `result` 리스트의 길이가 `in_degree` 딕셔너리에 있는 총 노드의 개수와 다르다면, 이는 그래프에 사이클이 있어서 모든 노드를 정렬할 수 없었다는 의미입니다.
