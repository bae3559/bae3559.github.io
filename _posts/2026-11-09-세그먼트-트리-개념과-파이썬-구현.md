# 개발자를 위한 필수 자료구조: 세그먼트 트리(Segment Tree) 개념과 파이썬 구현

안녕하세요, 개발 블로그 작가 개발몽입니다.
데이터를 다루다 보면 특정 '구간'에 대한 정보를 빠르게 찾아내거나, 특정 값을 '업데이트'해야 하는 경우가 자주 생깁니다. 예를 들어, "이 배열에서 3번째부터 7번째 숫자까지의 합은 얼마일까?" 또는 "5번째 숫자를 10으로 바꾸면, 3번째부터 7번째 숫자까지의 합은 어떻게 변할까?" 같은 질문들이죠.

이런 작업을 단순하게 반복문으로 처리한다면, 데이터의 양이 많아질수록 성능은 급격히 나빠질 겁니다. O(N)의 시간 복잡도를 가지기 때문이죠. 이때 우리에게 필요한 강력한 도구가 바로 **세그먼트 트리(Segment Tree)** 입니다.

오늘은 세그먼트 트리가 무엇인지, 왜 필요한지, 그리고 파이썬으로 어떻게 구현하는지 초보자분들도 쉽게 이해할 수 있도록 친절하게 설명해 드릴게요!

---

## 🚀 세그먼트 트리(Segment Tree)란 무엇일까요?

세그먼트 트리(Segment Tree)는 '구간'을 효율적으로 다루기 위한 이진 트리 기반의 자료구조입니다. 마치 거대한 책을 여러 챕터, 단락으로 나누어 요약본을 만들어 놓는 것과 비슷해요.

원본 배열의 각 '구간'에 대한 정보를 트리의 노드에 저장해 두는 방식입니다.
*   **리프 노드(Leaf Node)**: 원본 배열의 개별 요소를 나타냅니다. (가장 작은 구간)
*   **내부 노드(Internal Node)**: 자식 노드들이 나타내는 구간들의 정보를 '요약'하여 저장합니다. 이 요약 정보는 구간 합, 구간 최솟값, 구간 최댓값 등 다양한 연산이 될 수 있습니다.

예를 들어, [1, 2, 3, 4]라는 배열이 있다면, 루트 노드는 [1, 2, 3, 4]의 합(10)을 가지고 있고, 그 왼쪽 자식은 [1, 2]의 합(3)을, 오른쪽 자식은 [3, 4]의 합(7)을 가지는 식이죠.

## 💡 왜 세그먼트 트리가 필요할까요?

세그먼트 트리의 가장 큰 장점은 바로 `O(log N)`의 시간 복잡도로 **구간 쿼리(Range Query)**와 **단일 원소 업데이트(Point Update)**를 수행할 수 있다는 점입니다.

*   **구간 쿼리:** 특정 구간의 합, 최솟값, 최댓값 등을 찾을 때
    *   일반적인 배열: `O(N)` (모든 원소를 순회)
    *   세그먼트 트리: `O(log N)`
*   **단일 원소 업데이트:** 배열의 특정 위치 값을 변경할 때
    *   일반적인 배열: `O(1)` (직접 접근)
    *   세그먼트 트리: `O(log N)` (변경 후 상위 노드들의 요약 정보도 갱신해야 함)

데이터가 수십만, 수백만 개에 달할 때 `O(N)`과 `O(log N)`의 차이는 엄청난 성능 차이를 만듭니다. `N=1,000,000`일 때, `log N`은 약 20밖에 되지 않으니까요!

## 📚 세그먼트 트리 동작 원리 (구간 합 예시)

세그먼트 트리는 크게 세 가지 주요 연산을 가집니다.

1.  **트리 구축 (Build)**
2.  **구간 쿼리 (Query)**
3.  **값 업데이트 (Update)**

### 1. 트리 구축 (Build)

원본 배열을 바탕으로 세그먼트 트리를 만드는 과정입니다. 재귀적으로 배열을 절반씩 나누어가며 트리를 구성합니다.

*   **바닥부터 채우기:** 가장 작은 구간(원본 배열의 각 요소)을 리프 노드로 만듭니다.
*   **위로 올라가기:** 자식 노드들의 값을 이용하여 부모 노드의 값을 계산합니다. (예: 왼쪽 자식 합 + 오른쪽 자식 합)
*   **트리 크기:** 보통 원본 배열 크기(N)의 4배 정도 되는 크기의 배열로 트리를 표현합니다. (이진 트리는 일반적으로 배열로 표현할 때 1번 인덱스부터 시작하며, 2\*노드, 2\*노드+1 방식으로 자식 노드에 접근합니다.)

### 2. 구간 쿼리 (Query)

원하는 구간의 정보를 찾습니다. 쿼리하려는 구간(`left`, `right`)과 현재 노드가 담당하는 구간(`start`, `end`)을 비교하여 재귀적으로 탐색합니다.

*   **완전히 겹치지 않는 경우:** 현재 노드의 구간이 쿼리 구간과 전혀 겹치지 않으면, 이 노드는 결과에 영향을 주지 않으므로 `0`(합의 경우)을 반환하고 탐색을 종료합니다.
*   **완전히 겹치는 경우:** 현재 노드의 구간이 쿼리 구간 안에 완전히 포함되면, 이 노드가 가진 요약 값(예: `tree[node]`)을 바로 반환합니다. 더 이상 내려갈 필요가 없습니다.
*   **부분적으로 겹치는 경우:** 현재 노드의 구간이 쿼리 구간과 부분적으로 겹치면, 왼쪽 자식과 오른쪽 자식에게 각각 쿼리를 보낸 후, 두 결과를 합하여 반환합니다.

### 3. 값 업데이트 (Update)

원본 배열의 특정 위치(`idx`)의 값이 변경되면, 해당 값과 관련된 모든 노드들의 요약 정보를 갱신해야 합니다.

*   **리프 노드 찾기:** `idx`에 해당하는 리프 노드를 찾아 값을 업데이트합니다.
*   **상위 노드 갱신:** 리프 노드부터 루트 노드까지 거슬러 올라가면서, 변경된 값에 영향을 받는 부모 노드들의 요약 값을 재계산합니다.

## 🐍 파이썬으로 구현하기 (구간 합 세그먼트 트리)

이제 파이썬으로 세그먼트 트리를 직접 구현해볼까요? `build`, `update`, `query` 함수를 만들어보겠습니다.

```python
import sys

# 재귀 호출 깊이 제한 늘리기 (Python 기본 제한 초과 방지)
sys.setrecursionlimit(10**6)

# 전역 변수로 선언하여 여러 함수에서 접근하기 쉽게
arr = [] # 원본 배열
tree = [] # 세그먼트 트리를 저장할 배열
N = 0    # 원본 배열의 크기

# 1. 세그먼트 트리 구축 함수
# node: 현재 노드의 인덱스
# start, end: 현재 노드가 담당하는 배열의 구간 [start, end]
def build(node, start, end):
    # 리프 노드 (원본 배열의 한 요소를 담당)
    if start == end:
        tree[node] = arr[start]
        return

    # 리프 노드가 아니면, 자식 노드들로 재귀 호출
    mid = (start + end) // 2
    build(2 * node, start, mid)         # 왼쪽 자식 노드 (2*node)
    build(2 * node + 1, mid + 1, end)   # 오른쪽 자식 노드 (2*node + 1)

    # 자식 노드들의 값을 이용하여 현재 노드의 값 계산 (여기서는 합)
    tree[node] = tree[2 * node] + tree[2 * node + 1]

# 2. 값 업데이트 함수
# node: 현재 노드의 인덱스
# start, end: 현재 노드가 담당하는 배열의 구간 [start, end]
# idx: 업데이트할 원본 배열의 인덱스
# val: 새롭게 변경될 값
def update(node, start, end, idx, val):
    # 업데이트할 인덱스가 현재 노드의 구간 밖에 있는 경우
    if idx < start or idx > end:
        return

    # 리프 노드인 경우 (업데이트할 원소를 찾은 경우)
    if start == end:
        tree[node] = val
        return

    # 리프 노드가 아니면, 자식 노드들로 재귀 호출
    mid = (start + end) // 2
    if start <= idx <= mid: # 업데이트할 인덱스가 왼쪽 자식 구간에 있는 경우
        update(2 * node, start, mid, idx, val)
    else: # 업데이트할 인덱스가 오른쪽 자식 구간에 있는 경우
        update(2 * node + 1, mid + 1, end, idx, val)

    # 자식 노드의 값이 변경되었으므로, 현재 노드의 값도 다시 계산
    tree[node] = tree[2 * node] + tree[2 * node + 1]

# 3. 구간 쿼리 함수
# node: 현재 노드의 인덱스
# start, end: 현재 노드가 담당하는 배열의 구간 [start, end]
# left, right: 쿼리하려는 구간 [left, right]
def query(node, start, end, left, right):
    # 쿼리 구간과 현재 노드의 구간이 전혀 겹치지 않는 경우
    if left > end or right < start:
        return 0 # 합 연산이므로 0 반환 (다른 연산이면 초기값 달라짐)

    # 쿼리 구간이 현재 노드의 구간을 완전히 포함하는 경우
    if left <= start and end <= right:
        return tree[node] # 현재 노드의 요약 값 반환

    # 쿼리 구간과 현재 노드의 구간이 부분적으로 겹치는 경우
    mid = (start + end) // 2
    p1 = query(2 * node, start, mid, left, right)         # 왼쪽 자식에서 쿼리
    p2 = query(2 * node + 1, mid + 1, end, left, right)   # 오른쪽 자식에서 쿼리
    return p1 + p2 # 두 결과를 합하여 반환

# --- 사용 예시 ---
if __name__ == "__main__":
    original_data = [1, 2, 3, 4, 5, 6, 7, 8]
    N = len(original_data)
    arr = original_data[:] # 원본 배열 복사

    # 세그먼트 트리는 보통 원본 배열 크기의 4배 정도로 초기화
    # 2^k >= N 인 k를 찾아서 2^(k+1) 크기로 만드는 방법도 있지만, 4*N이 더 간편
    tree = [0] * (4 * N)

    print(f"원본 배열: {arr}")

    # 1. 세그먼트 트리 구축
    build(1, 0, N - 1)
    print(f"세그먼트 트리 (부분): {tree[:2*N]}") # 트리의 일부분만 출력 (실제 4N까지 다 쓰지 않을 수 있음)
    print(f"루트 노드의 값 (전체 합): {tree[1]}") # tree[1]이 루트 노드

    # 2. 구간 쿼리 예시
    # 인덱스 0부터 4까지의 합 (1 + 2 + 3 + 4 + 5 = 15)
    query_start, query_end = 0, 4
    result_sum = query(1, 0, N - 1, query_start, query_end)
    print(f"\n인덱스 {query_start}부터 {query_end}까지의 합: {result_sum}") # 예상: 15

    # 인덱스 2부터 6까지의 합 (3 + 4 + 5 + 6 + 7 = 25)
    query_start, query_end = 2, 6
    result_sum = query(1, 0, N - 1, query_start, query_end)
    print(f"인덱스 {query_start}부터 {query_end}까지의 합: {result_sum}") # 예상: 25

    # 3. 값 업데이트 예시
    update_idx, new_value = 3, 10 # 3번 인덱스의 값을 4에서 10으로 변경
    print(f"\n인덱스 {update_idx}의 값을 {arr[update_idx]}에서 {new_value}로 업데이트합니다.")
    arr[update_idx] = new_value # 원본 배열도 업데이트
    update(1, 0, N - 1, update_idx, new_value)
    print(f"업데이트 후 원본 배열: {arr}")
    print(f"업데이트 후 루트 노드의 값 (전체 합): {tree[1]}") # 전체 합 변경 확인

    # 업데이트 후 다시 쿼리
    # 인덱스 0부터 4까지의 합 (1 + 2 + 3 + 10 + 5 = 21)
    query_start, query_end = 0, 4
    result_sum = query(1, 0, N - 1, query_start, query_end)
    print(f"업데이트 후 인덱스 {query_start}부터 {query_end}까지의 합: {result_sum}") # 예상: 21
```

## 🎯 고려사항 및 확장

*   **공간 복잡도:** 세그먼트 트리는 `O(N)`의 공간 복잡도를 가집니다. 일반적으로 `4 * N` 크기의 배열이 필요합니다.
*   **다른 연산:** 위 예시에서는 구간 합을 다루었지만, 구간 최솟값, 구간 최댓값, 구간 곱 등 다양한 연산에 적용할 수 있습니다. `build`, `update`, `query` 함수의 마지막 부분에서 연산 방식만 바꿔주면 됩니다.
    *   최솟값: `tree[node] = min(tree[2 * node], tree[2 * node + 1])`
    *   최댓값: `tree[node] = max(tree[2 * node], tree[2 * node + 1])`
    *   쿼리 시 겹치지 않는 경우 반환 값도 연산에 맞게 변경 (최솟값은 `float('inf')`, 최댓값은 `float('-inf')`)
*   **지연 전파(Lazy Propagation):** 특정 구간 전체를 업데이트해야 하는 경우 (예: "3번부터 7번까지의 모든 숫자에 5를 더하시오"), 일반적인 세그먼트 트리는 `O(N)`에 가까운 시간이 걸릴 수 있습니다. 이때 `O(log N)`으로 처리하기 위한 기법이 바로 '지연 전파'이며, 이는 세그먼트 트리의 고급 개념입니다.
