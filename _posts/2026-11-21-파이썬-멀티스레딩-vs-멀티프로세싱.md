# Python 동시성 프로그래밍: 멀티스레딩 vs 멀티프로세싱, 언제 뭘 써야 할까요?

안녕하세요, 개발 블로그 독자 여러분! 🚀

여러분은 혹시 파이썬으로 프로그램을 개발하면서 "이 작업은 왜 이렇게 느리지?", "여러 작업을 동시에 처리할 수는 없을까?" 같은 고민을 해본 적이 있으신가요? 특히 웹 요청, 대용량 데이터 처리, 복잡한 계산 등 시간이 오래 걸리는 작업을 만나면 더욱 그렇죠. 이럴 때 우리는 프로그램의 '동시성(Concurrency)' 또는 '병렬성(Parallelism)'을 고려하게 됩니다.

파이썬에서 여러 작업을 동시에 처리하는 대표적인 방법으로는 **멀티스레딩(Multithreading)**과 **멀티프로세싱(Multiprocessing)**이 있습니다. 둘 다 '동시에' 무언가를 한다는 점에서 비슷해 보이지만, 내부 동작 방식과 사용 사례는 확연히 다릅니다. 이 글에서는 두 개념을 초보자도 이해하기 쉽게 설명하고, 각각 언제 사용하면 좋을지 코드 예제와 함께 자세히 알아보겠습니다.

---

## 1. 멀티스레딩 (Multithreading): GIL의 그림자 속에서

### 1.1. 개념 설명

멀티스레딩은 하나의 프로그램(프로세스) 안에서 여러 개의 '스레드(Thread)'를 생성하여 작업을 동시에 수행하는 방식입니다. 스레드는 프로세스 내에서 실행되는 작업의 흐름 단위이며, 같은 프로세스 내의 스레드들은 메모리 공간을 공유합니다. 비유하자면, 한 명의 요리사(프로세스)가 동시에 여러 요리(스레드)를 저글링하며 만드는 것과 비슷합니다. 재료(메모리)를 함께 사용하기 때문에 효율적일 수 있습니다.

**하지만!** 파이썬의 멀티스레딩에는 중요한 '장벽'이 하나 있습니다. 바로 **GIL (Global Interpreter Lock)** 입니다.

**GIL(Global Interpreter Lock)이란?**
GIL은 파이썬 인터프리터가 한 번에 하나의 스레드만 파이썬 바이트코드를 실행할 수 있도록 강제하는 메커니즘입니다. 즉, 아무리 코어(CPU)가 여러 개 있어도, 파이썬 스레드는 한 번에 단 하나만 CPU를 점유하고 실행될 수 있다는 뜻입니다. 마치 4차선 도로에 차가 여러 대 있어도, 한 번에 한 대만 진입할 수 있도록 하는 톨게이트와 같습니다.

이 때문에 파이썬의 멀티스레딩은 **진정한 의미의 병렬 처리(CPU 코어를 동시에 활용하는 것)**를 제공하지 못합니다. CPU 연산이 주를 이루는 작업(CPU-bound)에서는 오히려 스레드 간 컨텍스트 스위칭(Context Switching) 오버헤드 때문에 단일 스레드보다 느려질 수도 있습니다.

그렇다면 멀티스레딩은 쓸모가 없을까요? 아닙니다! GIL은 파이썬 바이트코드를 실행할 때만 잠금을 걸기 때문에, 스레드가 **I/O 작업(예: 네트워크 요청, 파일 읽기/쓰기, 데이터베이스 접근 등)**을 할 때는 GIL을 잠시 해제합니다. 이 덕분에 다른 스레드가 파이썬 코드를 실행할 수 있게 되어, I/O-bound 작업에서는 매우 효과적인 동시성을 제공합니다.

### 1.2. 멀티스레딩 사용 시기

*   **I/O 바운드(I/O-bound) 작업:** 네트워크 요청(웹 크롤링, API 호출), 파일 입출력, 데이터베이스 쿼리 등 대부분의 시간을 데이터를 기다리는 데 보내는 작업.
*   GIL 덕분에 진정한 병렬성은 얻을 수 없지만, 기다리는 동안 다른 스레드가 CPU를 사용할 수 있으므로 전체 작업 시간을 단축할 수 있습니다.

### 1.3. 멀티스레딩 코드 예제

`time.sleep()` 함수는 I/O 작업을 흉내 내는 좋은 방법입니다. 스레드는 잠시 잠들면서 GIL을 해제하고, 다른 스레드가 실행될 기회를 얻습니다.

```python
import threading
import time

def task_thread(name):
    """
    I/O 바운드 작업을 시뮬레이션하는 함수
    """
    print(f"[{name}] 작업 시작...")
    time.sleep(2)  # 2초 동안 기다림 (I/O 작업 시뮬레이션)
    print(f"[{name}] 작업 완료!")

if __name__ == "__main__":
    start_time = time.time()

    threads = []
    # 3개의 스레드 생성
    for i in range(3):
        thread_name = f"스레드-{i+1}"
        thread = threading.Thread(target=task_thread, args=(thread_name,))
        threads.append(thread)
        thread.start() # 스레드 시작

    # 모든 스레드가 종료될 때까지 기다림
    for thread in threads:
        thread.join()

    end_time = time.time()
    print(f"\n모든 스레드 작업 완료. 총 소요 시간: {end_time - start_time:.2f}초")

# 예상 출력: 약 2초. 3개의 스레드가 동시에 대기하여 총 시간을 단축합니다.
# 만약 순차적으로 실행했다면 2초 * 3 = 6초가 걸렸을 것입니다.
```

위 코드를 실행하면 약 2초 만에 모든 작업이 완료되는 것을 볼 수 있습니다. 각 스레드가 2초 동안 `time.sleep()`을 하는 동안, GIL이 해제되어 다른 스레드가 실행될 수 있었기 때문입니다. 만약 이 작업들을 순차적으로 실행했다면 6초가 걸렸을 것입니다.

## 2. 멀티프로세싱 (Multiprocessing): GIL을 뛰어넘어

### 2.1. 개념 설명

멀티프로세싱은 이름 그대로 여러 개의 독립적인 '프로세스(Process)'를 생성하여 작업을 수행하는 방식입니다. 각 프로세스는 자신만의 독립적인 메모리 공간을 가지고 있으며, 자신만의 파이썬 인터프리터를 포함합니다.

가장 중요한 점은, 각 프로세스가 독립적인 파이썬 인터프리터를 가지기 때문에 **GIL의 제약을 받지 않습니다.** 이는 곧 CPU 코어 수만큼 **진정한 병렬 처리(실제로 여러 CPU 코어를 동시에 활용)**가 가능하다는 의미입니다. 비유하자면, 여러 명의 요리사(프로세스)가 각자 독립적인 주방(메모리 공간)에서 각자의 요리를 만드는 것과 비슷합니다. 재료를 공유하려면 복잡한 과정을 거쳐야 하지만, 각자 작업하기 때문에 효율적으로 전체 작업을 빠르게 처리할 수 있습니다.

### 2.2. 멀티프로세싱 사용 시기

*   **CPU 바운드(CPU-bound) 작업:** 대규모 계산, 이미지 및 비디오 처리, 복잡한 알고리즘 실행, 데이터 분석 등 대부분의 시간을 CPU 연산에 소비하는 작업.
*   GIL의 제약을 받지 않아 여러 CPU 코어를 동시에 활용하여 작업 속도를 크게 향상시킬 수 있습니다.

### 2.3. 멀티프로세싱 코드 예제

이번에는 CPU 연산을 많이 하는 작업을 시뮬레이션해 보겠습니다.

```python
import multiprocessing
import time
import os

def task_process(name):
    """
    CPU 바운드 작업을 시뮬레이션하는 함수
    """
    print(f"[{name}] (PID: {os.getpid()}) 작업 시작...")
    result = 0
    for _ in range(100_000_000): # 1억 번 반복하는 무거운 계산
        result += 1
    print(f"[{name}] (PID: {os.getpid()}) 작업 완료! 결과: {result}")

if __name__ == "__main__":
    start_time = time.time()

    processes = []
    # 3개의 프로세스 생성
    for i in range(3):
        process_name = f"프로세스-{i+1}"
        process = multiprocessing.Process(target=task_process, args=(process_name,))
        processes.append(process)
        process.start() # 프로세스 시작

    # 모든 프로세스가 종료될 때까지 기다림
    for process in processes:
        process.join()

    end_time = time.time()
    print(f"\n모든 프로세스 작업 완료. 총 소요 시간: {end_time - start_time:.2f}초")

# 예상 출력: 3개의 코어가 있다면, 단일 프로세스 실행 시간의 약 1/3로 단축됩니다.
# (예: 단일 프로세스 10초 -> 멀티프로세싱 3.x초)
```

이 코드를 실행하면, 각 프로세스가 독립적으로 무거운 계산을 수행하며 여러 CPU 코어를 동시에 활용하는 것을 확인할 수 있습니다. 시스템의 코어 수에 따라 단일 프로세스로 실행했을 때보다 훨씬 빠르게 전체 작업이 완료될 것입니다.

## 3. 그래서, 언제 뭘 써야 할까요? 요약 및 결론!

멀티스레딩과 멀티프로세싱은 각자의 장단점과 적합한 사용 사례가 명확합니다.

| 특징          | 멀티스레딩 (Multithreading)                                    | 멀티프로세싱 (Multiprocessing)                               |
| :------------ | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **개념**      | 하나의 프로세스 내 여러 스레드, 메모리 공유                  | 독립적인 여러 프로세스, 각자 메모리 가짐                   |
| **GIL 영향**  | GIL의 제약을 받음 (진정한 CPU 병렬 처리 어려움)              | GIL의 제약을 받지 않음 (진정한 CPU 병렬 처리 가능)         |
| **메모리**    | 스레드 간 메모리 공유 용이 (단, 동기화 문제 발생 가능)        | 프로세스 간 메모리 공유 어려움 (IPC 필요)                |
| **오버헤드**  | 생성 및 관리 비용이 적음 (가벼움)                            | 생성 및 관리 비용이 많음 (무거움)                          |
| **적합한 작업** | **I/O 바운드(I/O-bound):** 네트워크, 파일 입출력, DB 쿼리 등 | **CPU 바운드(CPU-bound):** 대규모 연산, 이미지 처리, 데이터 분석 등 |
| **복잡도**    | 공유 자원 동기화(Lock, Semaphore) 필요                         | 프로세스 간 통신(Queue, Pipe) 필요, 상대적으로 복잡      |

### 간단한 선택 가이드

1.  **작업이 주로 네트워크 통신, 파일 읽기/쓰기, 데이터베이스 접근 등 "무언가를 기다리는" 작업이라면?**
    ➡️ **멀티스레딩**을 고려하세요. GIL이 I/O 대기 중에는 해제되어 효율적인 동시성을 얻을 수 있습니다.

2.  **작업이 주로 복잡한 계산, 대규모 데이터 처리, 이미지 처리 등 "CPU를 많이 사용하는" 작업이라면?**
    ➡️ **멀티프로세싱**을 고려하세요. 각 프로세스가 독립적으로 CPU 코어를 활용하여 진정한 병렬 처리를 통해 속도를 크게 향상시킬 수 있습니다.

---

동시성 프로그래밍은 프로그램의 성능을 비약적으로 끌어올릴 수 있는 강력한 도구입니다. 하지만 잘못 사용하면 오히려 복잡성만 늘고 성능은 저하될 수도 있습니다. 여러분의 프로젝트가 어떤 종류의 작업이 주를 이루는지 명확히 파악하고, 그에 맞는 최적의 방법을 선택하는 것이 중요합니다.

가장 좋은 방법은 직접 코드를 작성하고 실행해보면서 각 방식의 동작과 성능 차이를 체감하는 것입니다. 이 글이 여러분의 파이썬 동시성 프로그래밍 여정에 작은 길잡이가 되었기를 바랍니다!
