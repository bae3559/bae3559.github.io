## # 최소 신장 트리 (MST): 크루스칼 & 프림으로 길을 찾다

### 💡 MST, 왜 필요할까요? (문제 정의)

상상해보세요. 여러분은 여러 도시를 연결하는 고속도로망을 설계해야 합니다. 각 도로를 건설하는 데는 비용이 들어요. 모든 도시를 서로 연결하면서도 *총 건설 비용을 최소화*하고 싶습니다. 또는, 캠퍼스 내 모든 건물에 광케이블을 연결해야 하는데, 케이블 길이를 최소화하여 비용을 아끼고 싶을 수도 있죠.

이런 문제들을 해결해주는 것이 바로 **최소 신장 트리(Minimum Spanning Tree, MST)** 입니다.

### 🌳 최소 신장 트리(MST)는 무엇인가요?

MST를 이해하기 위해 몇 가지 기본 개념부터 짚고 넘어갈게요.

1.  **그래프(Graph):** 정점(Vertex, 노드)과 이들을 잇는 간선(Edge)으로 이루어진 자료구조입니다.
    *   **정점(Vertex/Node):** 도시, 건물 등 연결하려는 각각의 '점'을 의미합니다.
    *   **간선(Edge):** 정점들을 잇는 '선'으로, 도로, 케이블 등을 의미합니다.
    *   **가중치(Weight):** 간선마다 부여된 '비용' 또는 '거리' 값입니다.

2.  **신장 트리(Spanning Tree):** 주어진 그래프의 모든 정점을 포함하면서, 사이클(cycle, 한 바퀴 돌아 제자리로 돌아오는 길) 없이 모든 정점을 연결하는 부분 그래프입니다. 쉽게 말해, 모든 점을 이었지만 빙빙 돌지 않는 '나무' 형태라고 생각하시면 됩니다.

3.  **최소 신장 트리(Minimum Spanning Tree, MST):** 신장 트리 중에서 간선들의 가중치 합이 가장 작은(최소인) 트리를 말합니다. 즉, 모든 정점을 연결하면서도 총 비용이 가장 저렴한 길인 셈이죠!

MST를 찾는 대표적인 알고리즘에는 **크루스칼(Kruskal)** 알고리즘과 **프림(Prim)** 알고리즘이 있습니다. 둘 다 **탐욕적(Greedy) 알고리즘**이라는 공통점을 가지고 있습니다. 현재 상황에서 가장 최적의 선택을 하는 방식이죠.

---

### 🗡️ 크루스칼(Kruskal) 알고리즘: 가장 저렴한 간선부터 연결하기

크루스칼 알고리즘은 모든 간선(edge)들을 가중치 기준으로 오름차순 정렬한 후, 가장 가중치가 낮은 간선부터 하나씩 추가해나가며 MST를 만듭니다. 이때, 사이클이 발생하면 해당 간선은 추가하지 않습니다.

**작동 방식:**

1.  모든 간선을 가중치를 기준으로 오름차순으로 정렬합니다.
2.  `Union-Find` 자료구조를 사용하여 각 노드가 어떤 집합에 속하는지 추적합니다. (처음에는 각 노드가 자신만의 집합에 속합니다.)
3.  정렬된 간선들을 하나씩 확인합니다.
    *   해당 간선으로 연결되는 두 노드가 **서로 다른 집합**에 속해 있다면, 이 간선을 MST에 추가하고 두 집합을 합칩니다(`Union`).
    *   두 노드가 **이미 같은 집합**에 속해 있다면, 이 간선을 추가하면 사이클이 발생하므로 건너뜁니다.
4.  MST에 포함되는 간선의 개수가 `정점의 개수 - 1`개가 될 때까지 3번 과정을 반복합니다.

`Union-Find`는 집합(그룹)을 관리하는 자료구조로, 두 노드가 같은 집합에 속하는지 확인하고, 두 집합을 합치는 연산을 효율적으로 수행합니다.

**코드 예제 (Python):**

```python
def find(parent, i):
    # i의 루트 노드를 찾습니다.
    if parent[i] == i:
        return i
    parent[i] = find(parent, parent[i]) # 경로 압축 (Path Compression)
    return parent[i]

def union(parent, rank, i, j):
    # i와 j가 속한 집합을 합칩니다.
    root_i = find(parent, i)
    root_j = find(parent, j)

    if root_i != root_j:
        # 랭크(트리 높이)를 기준으로 합쳐서 트리를 평평하게 유지
        if rank[root_i] < rank[root_j]:
            parent[root_i] = root_j
        elif rank[root_i] > rank[root_j]:
            parent[root_j] = root_i
        else:
            parent[root_j] = root_i
            rank[root_i] += 1
        return True # 합병 성공
    return False # 이미 같은 집합

def kruskal(vertices, edges):
    mst = [] # 최소 신장 트리에 포함될 간선들
    total_cost = 0

    # 1. 모든 간선을 가중치 기준으로 오름차순 정렬
    # 간선 형태: (가중치, 시작 노드, 끝 노드)
    edges.sort()

    # 2. Union-Find 자료구조 초기화
    parent = list(range(vertices)) # 각 노드가 자신을 부모로 가짐
    rank = [0] * vertices # 트리의 높이 (랭크) 초기화

    # 3. 정렬된 간선들을 하나씩 확인
    for weight, u, v in edges:
        # 간선을 추가해도 사이클이 발생하지 않는다면 (두 노드가 다른 집합)
        if union(parent, rank, u, v):
            mst.append((u, v, weight))
            total_cost += weight
            # MST 간선의 수가 (정점의 수 - 1)이 되면 종료
            if len(mst) == vertices - 1:
                break
    
    return mst, total_cost

# 예제 그래프
# 정점: 0, 1, 2, 3, 4 (총 5개)
# 간선: (가중치, 시작 노드, 끝 노드)
edges = [
    (1, 0, 1),
    (3, 0, 2),
    (2, 0, 3),
    (4, 1, 3),
    (5, 2, 3),
    (6, 1, 4),
    (7, 3, 4)
]
num_vertices = 5

mst_edges, mst_cost = kruskal(num_vertices, edges)
print(f"크루스칼 알고리즘으로 찾은 MST 간선: {mst_edges}")
print(f"크루스칼 알고리즘으로 찾은 MST 총 비용: {mst_cost}")

```
**크루스칼 알고리즘 출력 결과:**
```
크루스칼 알고리즘으로 찾은 MST 간선: [(0, 1, 1), (0, 3, 2), (0, 2, 3), (1, 4, 6)]
크루스칼 알고리즘으로 찾은 MST 총 비용: 12
```

**시간 복잡도:** 간선 정렬에 `O(E log E)` (여기서 E는 간선의 수), Union-Find 연산에 `O(E α(V))` (여기서 V는 정점의 수, α는 아커만 함수의 역함수로 거의 상수 취급)가 소요됩니다. 따라서 주로 `O(E log E)` 또는 `O(E log V)`로 표현됩니다.

### 👑 프림(Prim) 알고리즘: 한 점부터 확장해나가기

프림 알고리즘은 하나의 정점에서 시작하여 점진적으로 MST를 확장해나가는 방식입니다. 마치 덩어리를 키워나가듯이 MST를 구성합니다. 이웃한 간선들 중 가장 가중치가 작은 간선을 선택하여 트리에 추가하는 방식이죠.

**작동 방식:**

1.  그래프 내의 임의의 시작 정점을 하나 선택하여 MST에 추가합니다.
2.  MST에 추가된 정점들과 인접한 간선들 중에서, MST에 아직 포함되지 않은 정점으로 이어지는 간선들 중 **가장 가중치가 작은 간선**을 선택합니다.
3.  선택된 간선을 MST에 추가하고, 해당 간선이 연결하는 정점도 MST에 추가합니다.
4.  MST에 `정점의 개수`만큼의 정점이 모두 포함될 때까지 2~3번 과정을 반복합니다. (간선의 수는 `정점의 개수 - 1`개가 됩니다.)

이때, 가장 작은 가중치의 간선을 효율적으로 찾기 위해 **우선순위 큐(Priority Queue)**를 사용합니다.

**코드 예제 (Python):**

```python
import heapq

def prim(num_vertices, graph_adj_list):
    mst = [] # MST 간선 리스트
    total_cost = 0
    
    visited = [False] * num_vertices # 노드 방문 여부
    
    # 우선순위 큐: (가중치, 시작 노드, 끝 노드)
    # 시작 노드는 임의로 0번 노드 선택
    # 큐에는 (가중치, 연결될 노드) 또는 (가중치, 현재 노드, 다음 노드) 형태로 넣을 수 있음
    # 여기서는 (가중치, 도착 노드) 형태로 관리하여, 도착 노드가 추가되면 그 노드에 연결된 모든 간선을 추가
    
    min_heap = [(0, 0)] # (가중치, 시작 노드) - 0번 노드에서 시작, 가중치는 0
    
    while min_heap:
        weight, u = heapq.heappop(min_heap) # 가장 가중치가 작은 간선 (또는 노드) 꺼내기

        if visited[u]: # 이미 방문한 노드라면 건너뛰기 (사이클 방지)
            continue
        
        visited[u] = True # 현재 노드를 방문 처리
        total_cost += weight
        
        # (MST에 추가되는 간선을 추적하려면 별도의 로직 필요, 여기서는 총 비용 계산)
        # 만약 (weight, parent_node, current_node) 형태로 힙에 넣었다면, 여기서 mst.append((parent_node, current_node, weight)) 가능

        # 모든 노드를 방문했다면 종료
        if all(visited):
            break

        # 현재 노드 u에 인접한 모든 간선들을 우선순위 큐에 추가
        for v, w_uv in graph_adj_list[u]:
            if not visited[v]:
                heapq.heappush(min_heap, (w_uv, v))
                # 참고: 프림 알고리즘 구현 방식에 따라 간선 정보를 더 저장하기도 함
                # 예: (w_uv, u, v) 형태로 저장하여 나중에 mst에 간선을 정확히 추가

    # 모든 간선을 추적하는 방식의 프림 구현
    # (weight, from_node, to_node) 형태로 힙에 저장
    mst_edges_with_nodes = []
    min_heap_full_info = [(0, -1, 0)] # (weight, from_node, to_node) - from_node가 -1이면 시작 노드
    visited_full = [False] * num_vertices
    total_cost_full = 0

    while min_heap_full_info:
        weight, prev_node, curr_node = heapq.heappop(min_heap_full_info)

        if visited_full[curr_node]:
            continue
        
        visited_full[curr_node] = True
        total_cost_full += weight
        if prev_node != -1: # 시작 노드를 제외한 간선만 MST에 추가
            mst_edges_with_nodes.append((prev_node, curr_node, weight))

        # 현재 노드에 인접한 모든 간선을 힙에 추가
        for neighbor, edge_weight in graph_adj_list[curr_node]:
            if not visited_full[neighbor]:
                heapq.heappush(min_heap_full_info, (edge_weight, curr_node, neighbor))
                
    return mst_edges_with_nodes, total_cost_full


# 예제 그래프 (인접 리스트 형태)
# 정점: 0, 1, 2, 3, 4 (총 5개)
# graph_adj_list[i] = [(인접 노드, 가중치), ...]
graph_adj = [
    [(1, 1), (2, 3), (3, 2)], # 0번 노드
    [(0, 1), (3, 4), (4, 6)], # 1번 노드
    [(0, 3), (3, 5)],        # 2번 노드
    [(0, 2), (1, 4), (2, 5), (4, 7)], # 3번 노드
    [(1, 6), (3, 7)]         # 4번 노드
]
num_vertices_prim = 5

mst_edges_prim, mst_cost_prim = prim(num_vertices_prim, graph_adj)
print(f"\n프림 알고리즘으로 찾은 MST 간선: {mst_edges_prim}")
print(f"프림 알고리즘으로 찾은 MST 총 비용: {mst_cost_prim}")
```
**프림 알고리즘 출력 결과:**
```
프림 알고리즘으로 찾은 MST 간선: [(0, 1, 1), (0, 3, 2), (0, 2, 3), (1, 4, 6)]
프림 알고리즘으로 찾은 MST 총 비용: 12
```

**시간 복잡도:** 우선순위 큐를 사용하면 `O(E log V)` 또는 `O(E + V log V)` (피보나치 힙 사용 시)가 됩니다. 여기서 E는 간선의 수, V는 정점의 수입니다.

### ⚔️ 크루스칼 vs. 프림: 언제 무엇을 쓸까?

두 알고리즘 모두 MST를 찾아주지만, 그래프의 특성에 따라 성능 차이가 있을 수 있습니다.

*   **크루스칼 (Kruskal):**
    *   **간선 중심**으로 동작합니다.
    *   **희소 그래프(Sparse Graph)**, 즉 간선이 정점에 비해 적은 그래프에서 효율적입니다. (`E`가 `V^2`보다 훨씬 작을 때)
    *   구현이 비교적 직관적이고 쉽습니다.

*   **프림 (Prim):**
    *   **정점 중심**으로 동작합니다.
    *   **밀집 그래프(Dense Graph)**, 즉 간선이 정점에 비해 많은 그래프에서 효율적입니다. (`E`가 `V^2`에 가까울 때)
    *   우선순위 큐를 활용하여 구현합니다.

일반적으로는 두 알고리즘 모두 큰 성능 차이를 보이지 않지만, 그래프의 형태를 고려하여 선택하면 좋습니다.
