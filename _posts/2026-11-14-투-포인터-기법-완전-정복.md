# 투 포인터(Two Pointers) 기법 완전 정복: 효율적인 알고리즘 설계의 핵심!

안녕하세요, 개발 블로그 독자 여러분! 알고리즘 문제 풀이에 어려움을 겪고 계신가요? 특히 배열, 리스트와 같은 선형 자료구조 문제를 풀 때 시간 제한(Time Limit Exceeded, TLE) 때문에 좌절한 경험이 있으시다면, 오늘 소개해 드릴 "투 포인터(Two Pointers)" 기법에 주목해 주세요.

투 포인터는 이름 그대로 **두 개의 포인터(또는 인덱스)**를 사용하여 배열이나 리스트와 같은 자료구조를 탐색하며 문제를 해결하는 기법입니다. 이 간단해 보이는 아이디어가 놀랍도록 효율적인 해결책을 제시하며, 복잡한 문제의 시간 복잡도를 획기적으로 줄여주는 마법 같은 도구로 활용됩니다.

오늘은 초보자분들도 쉽게 이해할 수 있도록 투 포인터의 기본 개념부터 핵심 활용 패턴, 그리고 실제 코드 예제까지 자세히 다뤄보겠습니다. 이 글을 끝까지 읽으시면 여러분의 알고리즘 문제 해결 능력이 한 단계 업그레이드될 것이라고 확신합니다!

## 1. 투 포인터(Two Pointers) 기법이란 무엇인가요?

투 포인터 기법은 주로 **정렬된 배열이나 리스트**에서 특정 조건을 만족하는 두 요소를 찾거나, 부분 배열(Subarray)의 합을 구하거나, 중복된 요소를 제거하는 등 다양한 상황에서 사용됩니다. 핵심은 두 포인터의 위치를 조절하면서 전체 탐색 범위를 줄여나가거나, 필요한 정보를 효율적으로 업데이트하는 것입니다.

이 기법의 가장 큰 장점은 **시간 복잡도를 크게 개선**한다는 점입니다. 일반적으로 중첩 반복문(Brute Force)을 사용하면 O(N^2)의 시간 복잡도가 발생할 수 있는 문제를 투 포인터를 사용하면 O(N)으로 줄일 수 있는 경우가 많습니다. 이는 데이터의 크기 N이 커질수록 어마어마한 성능 차이를 만들어냅니다.

### 투 포인터의 두 가지 주요 패턴

투 포인터는 크게 두 가지 패턴으로 나눌 수 있습니다.

1.  **서로를 향해 움직이는 포인터 (Opposite Direction Pointers):**
    *   하나의 포인터는 배열의 시작(left), 다른 하나는 배열의 끝(right)에서 출발하여 서로를 향해 중앙으로 이동합니다.
    *   주로 정렬된 배열에서 특정 합을 가지는 두 수를 찾거나, 회문(Palindrome) 검사, 배열 뒤집기 등에 활용됩니다.

2.  **같은 방향으로 움직이는 포인터 (Same Direction Pointers):**
    *   두 포인터 모두 배열의 시작(또는 특정 지점)에서 출발하여 같은 방향(대부분 오른쪽)으로 이동합니다.
    *   `fast` 포인터가 `slow` 포인터보다 앞서나가면서 특정 조건을 만족하는 구간(Sliding Window)을 탐색하거나, 중복 제거, 연결 리스트에서 사이클 찾기 등에 활용됩니다.

이제 각 패턴별로 구체적인 예제를 통해 투 포인터 기법을 정복해 봅시다!

## 2. 예제 1: 서로를 향해 움직이는 포인터 - 두 수의 합 (Two Sum)

**문제:** 정렬된 정수 배열 `nums`와 목표값 `target`이 주어졌을 때, 합이 `target`이 되는 두 수를 찾아 그 인덱스를 반환하시오. (단, 같은 요소를 두 번 사용할 수 없으며, 답은 유일하다고 가정합니다.)

**예시:**
`nums = [2, 7, 11, 15]`, `target = 9`
`출력: [0, 1]` (2 + 7 = 9 이므로 인덱스 0과 1 반환)

### 2.1. 투 포인터 없이 풀면? (비효율적인 접근)

가장 먼저 떠오르는 방법은 아마도 중첩 반복문을 사용하는 Brute Force(무차별 대입) 방식일 것입니다.

```python
def two_sum_brute_force(nums, target):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n): # i 다음부터 탐색
            if nums[i] + nums[j] == target:
                return [i, j]
    return [] # 답을 찾지 못한 경우
```

이 방법의 시간 복잡도는 O(N^2)입니다. 배열의 길이가 길어지면 길어질수록 계산 시간이 급격히 늘어나 비효율적입니다.

### 2.2. 투 포인터로 효율적으로 풀기 (O(N) 해결!)

정렬된 배열이라는 조건은 투 포인터를 사용할 수 있는 강력한 힌트입니다. 배열이 정렬되어 있기 때문에, 현재 두 포인터가 가리키는 값들의 합이 `target`보다 크거나 작은지에 따라 다음 탐색 방향을 결정할 수 있습니다.

**아이디어:**
1.  `left` 포인터를 배열의 시작(인덱스 0)에, `right` 포인터를 배열의 끝(인덱스 `len(nums) - 1`)에 둡니다.
2.  `left`와 `right`가 서로 교차하기 전까지 반복합니다.
3.  현재 `nums[left]`와 `nums[right]`의 합을 계산합니다.
    *   **합이 `target`과 같으면:** 정답을 찾았으므로 `[left, right]`를 반환합니다.
    *   **합이 `target`보다 작으면:** 현재 합을 늘려야 합니다. 배열은 오름차순으로 정렬되어 있으므로, `left` 포인터를 오른쪽으로 한 칸 이동(`left += 1`)하여 더 큰 값을 더해야 합니다.
    *   **합이 `target`보다 크면:** 현재 합을 줄여야 합니다. `right` 포인터를 왼쪽으로 한 칸 이동(`right -= 1`)하여 더 작은 값을 더해야 합니다.

**코드 예제:**

```python
def two_sum_sorted_two_pointers(nums, target):
    left, right = 0, len(nums) - 1 # 양 끝에 포인터 초기화

    while left < right: # left가 right보다 작을 때까지 반복 (교차하면 종료)
        current_sum = nums[left] + nums[right] # 현재 두 포인터가 가리키는 값의 합

        if current_sum == target:
            return [left, right] # 합이 target과 같으면 인덱스 반환
        elif current_sum < target:
            left += 1 # 합이 target보다 작으면, left를 오른쪽으로 옮겨 합을 늘림
        else: # current_sum > target
            right -= 1 # 합이 target보다 크면, right를 왼쪽으로 옮겨 합을 줄임

    return [] # 답을 찾지 못한 경우 (문제 조건상 이 부분에 도달하지 않아야 함)

# 예시 테스트
nums1 = [2, 7, 11, 15]
target1 = 9
print(f"nums: {nums1}, target: {target1} -> {two_sum_sorted_two_pointers(nums1, target1)}") # 출력: [0, 1]

nums2 = [1, 2, 3, 4, 5, 6]
target2 = 10
print(f"nums: {nums2}, target: {target2} -> {two_sum_sorted_two_pointers(nums2, target2)}") # 출력: [3, 5] (4 + 6 = 10)

nums3 = [-3, 0, 1, 2, 5, 8]
target3 = 7
print(f"nums: {nums3}, target: {target3} -> {two_sum_sorted_two_pointers(nums3, target3)}") # 출력: [2, 4] (1 + 5 = 6, 2+5=7)
```

**코드 설명:**
*   `left`와 `right`는 각각 배열의 가장 왼쪽과 가장 오른쪽을 가리킵니다.
*   `while left < right:` 조건은 두 포인터가 서로 만나거나 교차하기 전까지 탐색을 계속하겠다는 의미입니다.
*   `current_sum`을 계산한 후 `target`과의 비교를 통해 `left`나 `right` 포인터 중 하나만 이동시켜 시간 복잡도를 O(N)으로 만들 수 있습니다.

## 3. 예제 2: 같은 방향으로 움직이는 포인터 - 정렬된 배열에서 중복 제거

**문제:** 정렬된 정수 배열 `nums`가 주어졌을 때, 각 요소가 한 번만 나타나도록 중복을 제거하고 새로운 배열의 길이를 반환하시오. 단, 추가적인 배열 공간을 사용하지 않고 `nums` 배열 안에서 해결(in-place)해야 합니다.

**예시:**
`nums = [1, 1, 2]`
`출력: 2` (배열은 `[1, 2, _]`로 변경되어야 함)

`nums = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]`
`출력: 5` (배열은 `[0, 1, 2, 3, 4, _, _, _, _, _]`로 변경되어야 함)

### 3.1. 투 포인터로 효율적으로 풀기 (O(N) 해결!)

이 문제는 `fast` 포인터와 `slow` 포인터를 같은 방향으로 이동시키며 해결할 수 있습니다. `slow` 포인터는 고유한 요소들이 채워질 위치를 가리키고, `fast` 포인터는 배열 전체를 순회하며 고유한 요소를 찾습니다.

**아이디어:**
1.  `slow` 포인터를 0(첫 번째 요소의 인덱스)으로 초기화합니다. 이 `slow`는 고유한 요소들이 저장될 마지막 인덱스를 의미합니다.
2.  `fast` 포인터를 1(두 번째 요소의 인덱스)부터 배열의 끝까지 이동시킵니다.
3.  `nums[fast]`와 `nums[slow]`를 비교합니다.
    *   **`nums[fast]`와 `nums[slow]`가 다르면:** `fast`가 새로운 고유한 요소를 찾았다는 의미입니다.
        *   `slow`를 한 칸 앞으로 이동(`slow += 1`).
        *   `nums[slow]`에 `nums[fast]` 값을 할당하여 고유한 요소를 저장합니다.
    *   **`nums[fast]`와 `nums[slow]`가 같으면:** 중복된 요소이므로 아무것도 하지 않고 `fast`만 다음 칸으로 이동하여 계속 탐색합니다.
4.  모든 요소를 탐색한 후, `slow + 1`이 중복이 제거된 배열의 새 길이가 됩니다.

**코드 예제:**

```python
def remove_duplicates_two_pointers(nums):
    if not nums: # 배열이 비어있으면 길이 0 반환
        return 0

    slow = 0 # 고유한 요소들이 위치할 인덱스 (결과 배열의 마지막 인덱스)
    # fast는 배열의 두 번째 요소부터 끝까지 순회합니다.
    for fast in range(1, len(nums)):
        # 만약 fast가 가리키는 값과 slow가 가리키는 값이 다르다면,
        # fast가 새로운 고유한 값을 찾았다는 의미입니다.
        if nums[fast] != nums[slow]:
            slow += 1 # slow를 한 칸 이동시켜 새로운 고유한 값이 들어갈 자리를 만듭니다.
            nums[slow] = nums[fast] # fast의 값을 slow 위치에 저장합니다.

    return slow + 1 # 중복이 제거된 배열의 길이 (인덱스 0부터 slow까지이므로 +1)

# 예시 테스트
nums1 = [1, 1, 2]
length1 = remove_duplicates_two_pointers(nums1)
print(f"Original: [1, 1, 2], New length: {length1}, Array: {nums1[:length1]}") # 출력: New length: 2, Array: [1, 2]

nums2 = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]
length2 = remove_duplicates_two_pointers(nums2)
print(f"Original: [0,0,1,1,1,2,2,3,3,4], New length: {length2}, Array: {nums2[:length2]}") # 출력: New length: 5, Array: [0, 1, 2, 3, 4]

nums3 = [1, 2, 3, 4, 5]
length3 = remove_duplicates_two_pointers(nums3)
print(f"Original: [1,2,3,4,5], New length: {length3}, Array: {nums3[:length3]}") # 출력: New length: 5, Array: [1, 2, 3, 4, 5]
```

**코드 설명:**
*   `slow`는 최종적으로 중복이 제거된 배열의 유효한 마지막 인덱스를 가리키게 됩니다.
*   `fast`는 배열의 모든 요소를 빠르게 순회하며 `slow`가 가리키는 값과 다른(즉, 새로운 고유값인) 요소를 찾습니다.
*   `nums[fast] != nums[slow]` 조건이 만족하면, `slow`를 한 칸 전진시키고 그 위치에 `nums[fast]`의 값을 덮어씌웁니다. 이렇게 하면 `slow`가 가리키는 위치까지는 모두 고유한 값으로 채워지게 됩니다.
*   `fast`는 항상 한 칸씩 전진합니다.
*   마지막으로 `slow + 1`을 반환하여 중복이 제거된 배열의 길이를 알려줍니다. 배열 자체도 `in-place`로 변경된 상태입니다.

## 4. 투 포인터 기법은 언제, 왜 사용하는가?

*   **정렬된 배열/리스트에서 특정 조건(합, 값 등)을 만족하는 두 요소를 찾아야 할 때:** `two_sum` 예제처럼 탐색 범위를 효과적으로 줄일 수 있습니다.
*   **부분 배열/부분 문자열(Subarray/Substring) 문제를 효율적으로 해결할 때 (슬라이딩 윈도우와 결합):** 두 포인터가 윈도우의 시작과 끝을 나타내며, 윈도우를 한 칸씩 이동시키는 데 사용됩니다.
*   **배열/리스트의 중복 요소를 제거하거나, 특정 조건에 따라 요소를 재정렬할 때 (in-place):** `remove_duplicates` 예제처럼 추가 공간 없이 데이터를 조작할 수 있습니다.
*   **연결 리스트에서 사이클을 찾거나, 중간 노드를 찾을 때:** `slow`와 `fast` 포인터가 다른 속도로 움직이는 방식을 활용합니다.

투 포인터 기법은 위와 같은 문제들에서 중첩 반복문으로 인한 O(N^2)의 시간 복잡도를 O(N)으로 개선하여 알고리즘의 효율성을 극대화합니다. 또한, 대부분 O(1)의 추가 공간 복잡도만을 사용하여 메모리 사용량도 매우 적습니다.

## 5. 투 포인터 마스터를 위한 팁!

1.  **문제의 힌트를 찾아라:** 정렬된 배열, 리스트, `in-place` 연산, 특정 조건을 만족하는 두 요소 찾기 등의 키워드가 있다면 투 포인터를 고려해보세요.
2.  **포인터의 역할과 움직임을 명확히 정의:** 각 포인터가 무엇을 의미하고, 어떤 조건에서 어떻게 움직여야 하는지 이해하는 것이 중요합니다.
3.  **손으로 직접 그려보거나 디버깅:** 처음에는 포인터의 움직임이 헷갈릴 수 있습니다. 작은 예시 데이터를 가지고 포인터의 위치와 값의 변화를 직접 그려보면서 이해도를 높일 수 있습니다.
4.  **다양한 문제 풀이:** 이 글에서 다룬 예제 외에도 백준, 프로그래머스, 리트코드 등 다양한 플랫폼에서 투 포인터 관련 문제를 풀어보면서 숙련도를 높여보세요.
