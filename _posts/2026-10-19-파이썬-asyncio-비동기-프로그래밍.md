# 파이썬 asyncio, 비동기 프로그래밍으로 멈춤 없는 코드 만들기

안녕하세요, 개발 블로그 독자 여러분!

혹시 코드를 실행했는데, 특정 작업이 끝날 때까지 아무것도 할 수 없어 답답했던 경험이 있으신가요? 특히 네트워크 통신이나 파일 입출력처럼 "기다리는 시간"이 많은 작업에서 이런 현상을 자주 마주치게 됩니다. 이럴 때 파이썬 `asyncio`는 여러분의 코드를 더욱 효율적이고 반응성 좋게 만들어 줄 강력한 도구가 됩니다.

오늘은 파이썬의 비동기 프로그래밍 핵심인 `asyncio`에 대해 초보자 눈높이에 맞춰 쉽고 친절하게 설명해 드릴게요. `asyncio`가 무엇이고, 왜 필요한지, 그리고 어떻게 사용하는지 함께 알아봅시다!

---

### 1. 비동기(Asynchronous) 프로그래밍이란? 왜 필요할까요?

먼저, 비동기가 무엇인지 이해하는 것이 중요합니다. 우리가 흔히 작성하는 코드는 "동기(Synchronous) 방식"으로 동작합니다. 즉, 한 줄 한 줄 위에서 아래로 실행되며, 특정 작업이 완료되어야 다음 작업으로 넘어갑니다. 만약 작업 중간에 네트워크 요청처럼 오래 걸리는 일이 있다면, 그 작업이 끝날 때까지 프로그램 전체가 멈춰버리게 되죠. 마치 길게 줄을 서서 기다리는 것과 같습니다.

반면, "비동기 방식"은 작업이 완료될 때까지 마냥 기다리지 않고, "잠시 기다려야 하는 작업"을 시작해두고는 다른 일을 먼저 처리합니다. 그리고 기다리던 작업이 완료되면 다시 돌아와서 그 결과를 처리하는 방식입니다.

**쉬운 비유로 설명해 볼까요?**

*   **동기 방식 카페:** 바리스타 한 명이 주문을 받고 커피를 내립니다. 한 손님의 커피가 완전히 나올 때까지 다음 손님의 주문을 받지 않습니다. (느리다!)
*   **비동기 방식 카페:** 바리스타 한 명이 주문을 받습니다. 커피 머신에 에스프레소를 내리라고 시킨 후, 에스프레소가 추출되는 동안 다음 손님의 주문을 받거나, 다른 손님의 잔을 준비하거나, 설거지를 합니다. 에스프레소가 다 추출되면 다시 돌아와 우유를 붓고 커피를 완성합니다. (효율적이다!)

`asyncio`는 이 비동기 방식의 카페 바리스타처럼, 파이썬 코드 안에서 "기다리는 시간"을 효율적으로 활용하여 여러 작업을 동시에 처리하는 것처럼 보이게 해줍니다. 이는 **동시성(Concurrency)**을 달성하는 것으로, 실제 여러 작업이 물리적으로 동시에 실행되는 **병렬성(Parallelism)**과는 다릅니다. 파이썬은 기본적으로 GIL(Global Interpreter Lock) 때문에 하나의 스레드에서만 코드를 실행하지만, `asyncio`는 이 하나의 스레드 안에서 "기다리는 시간"을 영리하게 활용하는 것이죠.

---

### 2. `asyncio`의 핵심 키워드: `async`와 `await`

`asyncio`를 사용하려면 두 가지 핵심 키워드를 알아야 합니다.

*   `async def`: 이 키워드로 정의된 함수를 **코루틴(Coroutine)**이라고 부릅니다. 일반 함수와는 다르게, 코루틴은 실행 도중에 잠시 멈췄다가 나중에 다시 실행될 수 있는 특별한 함수입니다. `asyncio`의 모든 비동기 작업은 이 코루틴을 통해 이루어집니다.
*   `await`: 이 키워드는 `async` 함수 안에서만 사용할 수 있습니다. `await` 뒤에 오는 코루틴이 완료될 때까지 현재 코루틴의 실행을 잠시 **"멈추고" 다른 코루틴이 실행되도록 "양보"**하겠다는 의미입니다. 즉, "나는 지금 이 작업이 끝날 때까지 기다려야 하지만, 그동안 다른 작업이 있다면 먼저 하세요!" 라고 말하는 것과 같습니다.

그리고 `asyncio` 코드를 실행하기 위한 진입점으로는 주로 `asyncio.run()` 함수를 사용합니다.

---

### 3. `asyncio` 코드 예제로 살펴보기

말보다 코드가 더 친숙하겠죠? 간단한 예제를 통해 `asyncio`의 마법을 직접 경험해 봅시다.

#### 3.1. 동기(Synchronous) 코드의 문제점

먼저, 우리가 일반적으로 작성하는 동기 코드입니다. 두 개의 작업을 순차적으로 실행해 봅시다.

```python
import time

def sync_task(name):
    print(f"[{name}] 작업 시작...")
    time.sleep(2) # 2초 동안 기다리는 작업
    print(f"[{name}] 작업 완료!")

if __name__ == "__main__":
    start_time = time.time()
    sync_task("첫 번째 작업")
    sync_task("두 번째 작업")
    end_time = time.time()
    print(f"총 실행 시간: {end_time - start_time:.2f}초")
```

**실행 결과:**

```
[첫 번째 작업] 작업 시작...
[첫 번째 작업] 작업 완료!
[두 번째 작업] 작업 시작...
[두 번째 작업] 작업 완료!
총 실행 시간: 4.00초
```

예상대로, 첫 번째 작업이 2초, 두 번째 작업이 2초 걸려 총 4초가 소요됩니다. 첫 번째 작업이 완료될 때까지 두 번째 작업은 시작조차 할 수 없습니다.

#### 3.2. `asyncio`로 비동기 코루틴 만들기 (단일 실행)

이제 `asyncio`를 사용하여 위 작업을 코루틴으로 만들어 봅시다. 아직 동시 실행은 아닙니다.

```python
import asyncio
import time

async def async_task(name): # async def로 코루틴 정의
    print(f"[{name}] 작업 시작...")
    await asyncio.sleep(2) # asyncio.sleep은 await 해야 하는 코루틴입니다.
    print(f"[{name}] 작업 완료!")

if __name__ == "__main__":
    start_time = time.time()
    asyncio.run(async_task("단일 비동기 작업")) # asyncio.run()으로 코루틴 실행
    end_time = time.time()
    print(f"총 실행 시간: {end_time - start_time:.2f}초")
```

**실행 결과:**

```
[단일 비동기 작업] 작업 시작...
[단일 비동기 작업] 작업 완료!
총 실행 시간: 2.00초
```

`asyncio.run()`은 하나의 최상위 코루틴만 실행합니다. 아직 여러 작업을 동시에 실행하지 않았기 때문에 2초가 걸리는 것은 당연합니다. 여기서 주목할 점은 `time.sleep()` 대신 `await asyncio.sleep(2)`를 사용했다는 것입니다. `asyncio.sleep()`은 코루틴이므로 `await`로 "다른 코루틴이 실행될 수 있도록 양보"하면서 잠시 대기하게 됩니다.

#### 3.3. `asyncio.gather()`로 여러 코루틴 동시 실행하기

이제 `asyncio`의 진정한 힘을 보여줄 차례입니다. 여러 코루틴을 동시에 실행하려면 `asyncio.gather()`를 사용합니다. `asyncio.gather()`는 여러 코루틴을 받아서 이들을 동시에 실행하도록 스케줄링하고, 모든 코루틴이 완료될 때까지 기다립니다.

```python
import asyncio
import time

async def async_task(name):
    print(f"[{name}] 작업 시작...")
    await asyncio.sleep(2) # 2초 동안 기다리는 작업
    print(f"[{name}] 작업 완료!")

if __name__ == "__main__":
    start_time = time.time()
    
    # asyncio.gather()를 사용하여 여러 코루틴을 동시에 실행하도록 예약
    # gather도 코루틴이므로 await 해야 합니다.
    asyncio.run(asyncio.gather(
        async_task("첫 번째 비동기 작업"),
        async_task("두 번째 비동기 작업"),
        async_task("세 번째 비동기 작업")
    ))
    
    end_time = time.time()
    print(f"총 실행 시간: {end_time - start_time:.2f}초")
```

**실행 결과:**

```
[첫 번째 비동기 작업] 작업 시작...
[두 번째 비동기 작업] 작업 시작...
[세 번째 비동기 작업] 작업 시작...
[첫 번째 비동기 작업] 작업 완료!
[두 번째 비동기 작업] 작업 완료!
[세 번째 비동기 작업] 작업 완료!
총 실행 시간: 2.00초
```

놀랍지 않나요? 세 개의 작업이 각각 2초씩 기다리는 작업임에도 불구하고, 총 실행 시간은 약 2초에 불과합니다! 이는 세 작업이 동시에 시작되어 2초 동안 `await asyncio.sleep(2)`로 양보하는 동안, `asyncio` 이벤트 루프가 이들 사이를 오가며 효율적으로 시간을 관리했기 때문입니다. 마치 비동기 카페의 바리스타가 세 손님의 커피를 동시에 만드는 것과 같은 원리입니다.

### 4. `asyncio`는 언제 사용하면 좋을까요?

`asyncio`는 주로 **I/O 바운드(I/O-bound)** 작업에 매우 효과적입니다. I/O 바운드 작업이란 CPU 연산보다는 데이터를 읽고 쓰는 데 시간이 더 많이 소요되는 작업을 의미합니다.

*   **웹 서버 요청/API 호출:** `requests` 라이브러리 대신 `aiohttp`와 같은 비동기 HTTP 클라이언트를 사용하면 여러 웹 요청을 동시에 보내고 받을 수 있습니다.
*   **데이터베이스 쿼리:** 데이터베이스에서 데이터를 가져오거나 저장하는 동안 대기 시간을 줄일 수 있습니다. (`asyncpg`, `aiomysql` 등)
*   **파일 입출력:** 큰 파일을 읽거나 쓰는 동안 다른 작업을 처리할 수 있습니다.
*   **웹 소켓 통신:** 실시간 양방향 통신이 필요한 애플리케이션에 적합합니다.
*   **크롤링/스크레이핑:** 여러 웹 페이지를 동시에 요청하여 데이터를 수집할 때 효율적입니다.

반면, **CPU 바운드(CPU-bound)** 작업, 즉 복잡한 계산처럼 CPU를 많이 사용하는 작업에는 `asyncio`가 적합하지 않습니다. `asyncio`는 하나의 스레드에서 작동하므로, CPU를 많이 쓰는 작업은 다른 코루틴에게 제어권을 양보할 틈이 없어 비동기의 이점을 살릴 수 없습니다. 이런 경우에는 `multiprocessing` 모듈을 사용하여 여러 코어를 활용하는 병렬 처리가 더 적합합니다.

---

### 5. 초보자를 위한 `asyncio` 팁

*   **`async`는 `await`를 품고, `await`는 `async` 안에서!**: `async def`로 정의된 코루틴 함수 안에서만 `await` 키워드를 사용할 수 있습니다. 그리고 `async def`로 정의된 코루틴은 반드시 `await`로 호출하거나 `asyncio.run()`, `asyncio.create_task()` 등으로 실행해야 합니다. 일반 함수처럼 `my_async_func()`라고 그냥 호출하면 코루틴 객체만 반환하고 실행되지 않습니다.
*   **`asyncio.sleep()`으로 연습**: 실제 네트워크 요청 대신 `asyncio.sleep()`을 사용하여 비동기 동작을 연습하는 것이 좋습니다.
*   **비동기는 병렬이 아니다**: `asyncio`는 단일 스레드에서 "기다리는 시간"을 효율적으로 활용하는 동시성입니다. 여러 CPU 코어를 활용하는 병렬성과는 개념이 다릅니다.
